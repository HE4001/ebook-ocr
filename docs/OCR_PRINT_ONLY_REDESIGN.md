# 印刷原文识别：实际故障分析与流程重设计

日期：2026-10-07。状态：本轮实现续修中；下列验收条件未执行。

实现与真实限制见 `OCR_PRINT_ONLY_IMPLEMENTATION.md`。本设计包含后续目标，不代表本轮所有条款已实现或经运行证实。

本方案依据当前源码、只读查询的运行记录、已保存模型响应及两张源页图像。未重新请求模型、启动识别、修改项目数据库或运行测试。历史 V2 文档中的交付结论不代表本方案已实现。

用户本次明确要求：**只要原书印刷内容，输出中不保留手写批注。** 这一范围覆盖正文、公式、标题、图表、图注、印刷脚注和页码；不包含后加手写文字、圈画、下划线及扫描杂点。遇到遮挡不能猜测原文。原始上传文件仍作为内部证据保存，不混入成品。

## 1. 结论

当前问题是目标定义、质量判断、恢复合并和几何定位共同造成的。继续增加提示词、重试次数或请求额度，不能解决这些问题。

现有系统已经把 PageContent 与 PageLayout 分离，这部分应保留。但它仍把“全部可见墨迹”近似当成“需要转录的原书内容”，把模型估计框当成后续定位的重要依据，把独立重读结果追加进已有正文。对包含手写笔记的扫描书，这些机制相互放大错误。

新流程应当是：

**源页诊断 → 印刷/批注/混合区域分层 → 印刷区域转录 → 区域核验 → 有界替换修复 → 冻结印刷正文 → 排版与输出。**

正常使用仍是“选文件 → 选页 → 开始识别 → 结果”，无需逐页人工审批或填写坐标。

## 3. 根因及代码证据

### 3.1 识别范围与实际需求相反

`backend/prompts.py` 的 CONTENT_RECOGNITION_PROMPT、CONTENT_REVIEW_PROMPT 要求覆盖所有可见内容和墨迹，没有区分印刷正文与后加批注。ContentBlock 只有 type/role，没有来源层。

两张源图可直接看到大面积手写证明、页边批注和圈画。第一页复核的三个问题都围绕手写区域；第二页还把页顶横线和一个小墨点列为缺失或不可辨内容。系统正在花钱处理用户不需要的内容。

**设计决定：** 冻结 `recognition_scope=printed_original_only`。批注存在不是正文错误；批注遮挡印刷字才是正文的局部可读性问题。

### 3.2 缺少行坐标，被升级成“可能漏字”并污染内容状态

`SourceAnalysis.uncovered_content()` 对文字/公式只取 line.bbox，对这些类型不以 block.bbox 作为已覆盖行的证据。允许 line.bbox=null 本身是合理的，但模型实际大量返回这种结构。

`source_coverage_content()` 将未覆盖墨迹转为 ContentIssue；当模型块框与墨迹框不能完全包含时，会归为 missing_content。原文已存在但几何估计偏移，也会触发这一分支。

`reviewed_content()` 首轮没有 checked_targets；若整页不是 passed_all，许多本地 missing_content 提示仍未解决，并通过框相交把相关块降为 uncertain。只要有一处手写无法识别，整页的几何提示就容易长时间保留。

**设计决定：** 拆开 `CoverageObservation` 与 `ContentIssue`。未知位置不等于未知文字；墨迹提示必须经过区域归属和范围判断，才能升级为印刷内容缺失。不能简单用大 block 框宣称文字全部覆盖。

### 3.3 恢复任务被提示插入顺序支配

`recovery_targets()` 顺序遍历 issues；`_recover_page_v2()` 直接选 unique[:count]，一轮至多三个目标。当前没有按“已确认印刷错误、预期收益、是否可修复”排序。

第一页选中前三条本地墨迹提示，第二页选中页顶细线、右侧小墨点及上部混合区域。真正的内容差异可能排在后面。

另外，复核的 repairable 字段在 `reviewed_content()` 转存 ContentIssue 时丢失。unreadable_source 虽被恢复类别过滤排除，但 missing_content 等类别的 repairable=false 无法继续约束调度；同一不可辨位置还可能从本地提示路径进入重读。

**设计决定：** 保存问题来源、所属印刷区域、repairability、核验范围和处置状态。仅对有证据、可改善的印刷问题派发恢复任务。

### 3.4 “局部重读”实际反复读取大范围

`_complete_crop_box()` 把目标与所有相交粗区域取并集，再扩展跨界行。第一页三个不同目标最后均复用 crop `d9f8cabb70f24af49cd1ae18f68eca09`，范围约为 x=0.111–1.0、y=0–0.821，覆盖大半页。

这些请求的目标不同，所以不是完全相同的请求；但输入区域没有真正缩小，既浪费观察资源，又增加模型返回邻近内容的机会。

**设计决定：** 分开 `target_region`（结果归属）与 `context_crop`（周边观察）。裁切可以含上下文，写入范围不能跟着扩大。公式/表格以完整语义单元扩展；不能因为相交就吞并整个粗区域。

### 3.5 候选冲突进入正文，恢复越多重复越多

`local_content_candidate()` 在目标无 block_id 时按框相交收取局部块。`merge_region_content()` 只有内容结构严格一致、框位置足够相似（IoU≥0.82）且行对应时才去重；其他结果会追加到 merged.blocks。发现冲突时也保留双方在同一正文列表中。

同一原文被分成不同段/行，或模型框有偏移，就可能无法去重。随后程序重新排序全部块，使无关正文也受到影响。

**设计决定：** 候选历史与采用稿分离。同一区域允许多个候选，但输出只能引用一个采用版本；未解决的冲突不能通过“全部追加”进入正文。

### 3.6 坐标漂移进一步制造排版失败

首轮第一页的许多行 bbox=null，块框也存在可见偏移。一个底部交集公式的模型块框为 [0.18,0.925,0.78,0.955]；输出错误关联框却缩成 [0.7771,0.9436,0.7822,0.9488]，落在页码附近的微小墨迹区域。最终记录有 4 个字形伸出纸张、原行或编号超出 15.40 bp。

`layout_solver._match_region()` 对公式调用 measure_bbox；框内存在墨迹就可能产生测量结果，没有充分证明它属于该公式。`_set_geometry()` 又把这种位置标为 local_measurement。测到像素与测对公式不是同一回事。

**设计决定：** 坐标同时保存测量来源和匹配状态。全局行序、尺寸、邻接关系和公式组件必须一致，才允许绑定。匹配未知只影响版式，不抹掉文字。

### 3.7 改进判定依赖易漂移的问题键

`content_improves()` 使用 category、block_id、source_bbox 的精确元组比较，并要求新问题集合是旧集合的子集。模型下一次把同一问题框略作移动，就可能被当作新问题。

本次候选确有重复和顺序问题，退回具有依据；不能据此认定只要放宽比较就会成功。

**设计决定：** 按稳定 region_id/line_id/cell_id 追踪问题，坐标是证据属性。逐区域决定采用或退回，保护已通过区域；结构变化通过显式旧新归属映射处理。

### 3.8 源图兜底违反本次输出要求

现有整页/区域保留能避免丢失来源，但会把手写批注一起带入 PDF。最近第一页的 page_preserved 不能作为本次目标下的合格结果。

**设计决定：** 成品中禁止用含批注的整页或混合裁切兜底。源图仅用于内部对照；未能识别的印刷片段以独立未决状态保存，预览可显示占位，不能把批注作为正文输出。

## 4. 新流程

### 阶段 A：源页诊断与范围冻结

- 保存不可变源页、旋转和裁切映射；有去倾斜操作时保存可逆变换。
- 判断 PDF 原生字层是否与可见印刷内容对应；对应后可作为候选，隐藏旧 OCR 不能直接成为真值。
- 使用源资产生成适当分辨率的观察图；放大扫描位图不等于恢复细节。当前已有从 PDF 重新栅格化高清图的能力，应复用。
- 把用户选择的印刷原文范围冻结在 run 快照和导出清单中，防止恢复旧任务时混用旧的“所有墨迹”目标。

### 阶段 B：先建立区域和阅读顺序

每个 Region 保存稳定 ID、页版本、位置、栏归属、顺序关系、来源层及后续转录类型。

来源层为 printed、annotation、mixed、decoration、noise 或 unknown。正文与批注可以空间重叠，不能只用互斥矩形假装分离。

本地行带/连通区域用于提出边界。简单页可直接形成计划；存在重叠、密集公式、表格或分栏歧义时，增加一次只做区域分类和关系判断的观察请求，不同时要求完整转录。

模型分类也需核验；unknown 不能静默删掉，更不能因为“像手写”就删掉原书的花体数学字母、斜体、黑体、公式上下标。

阅读顺序在转录前建立，局部恢复不能重新排序全部正文。对模糊关系显式记录不确定边，避免伪造顺序。

### 阶段 C：按印刷区域转录

- 普通文字：原视觉行、段落、文字片段及行内数学；细字体测量延后到版式阶段。
- 独立公式：完整公式组、上下标、分子分母、矩阵及编号；不按数学常识改原式。
- 表格：完整表头、网格与单元格归属；大表可按完整行组分块，固定全表坐标身份。
- 印刷图形：干净原图资源可以保留；图注独立转录。图形上有批注时，不能把混合裁切直接当干净图输出。
- annotation、noise 不进入转录队列；mixed 只转录实际可辨印刷内容，被遮挡片段记录 unresolved_span 和证据。

每次请求绑定一组明确 region_id，模型返回 region_id 内的内容；边界几何可作为观察字段，但不能由转录模型重新划定采用区域。上下文图不授予输出邻近区域的权限。

相邻且简单的区域可在同一请求中批量处理；密集、复杂区域单独处理。普通整页也可以作为单个区域任务，避免为简单页面增加无效分段开销。

### 阶段 D：区域核验与覆盖归账

先做本地约束检查：区域归属、重复采用、行序、公式和表格基本结构。结构合法只代表可处理，不代表字符正确。

视觉核验逐印刷区域绑定候选，返回 checked_region_ids、逐区域 verdict、差异定位和处置。覆盖审查从源页出发检查是否遗漏印刷区域，独立于候选文字核对；不以“full_page_reviewed=true”一个布尔值替代所有区域的结论。

每条本地观察必须得到一种处置：已对应印刷区域、印刷遗漏已确认、批注不在范围、非文字装饰、扫描噪声，或仍未确定。没有被明确处理的观察保持待检查，但不自动成为文字错误。

批注不可辨与正文通过可以同时成立。反过来，批注遮挡正文时，即使公式按常识可以猜到，也不能通过。

### 阶段 E：有界修复与原子采用

1. 优先解决已经确认的印刷遗漏、字符差异及公式/表格错误；几何问题转交版式任务。
2. 为目标生成不同于失败路径的有效动作：提高源细节、调整完整公式边界、拆分过大任务或只修顺序。无新增证据的重复请求不派发。
3. 把新结果存为该 region 的候选；不得 append 到已采用正文。
4. 核验目标和必要邻接边界。通过后用 base_revision 检查原子替换；失败保留旧稿和差异，不覆盖其他已通过区域。
5. 对新增区域必须证明它属于原计划未覆盖的印刷内容；对 split/merge 提供旧新区域映射，禁止靠 IoU 或相同文字单独决定去重。
6. 同一轮不同区域分别采用。一个区域不改善，不应抹掉另一区域已核实的改善。

每个目标默认最多一次有实质变化的重读；必要的第二次必须说明改变了什么证据或任务边界，并受总预算限制。预算不足时保存部分成果与未决区域，不承诺必然修好。

### 阶段 F：冻结内容后排版

只有确定采用的印刷内容进入布局。行框来自已经匹配的区域/行证据；公式整体必须匹配完整组件，不能锚定到孤立点或页码。

布局失败只生成布局问题，不触发 OCR 重写。已识别内容可提供结构化 JSON 和可编辑正文；近似重排必须明确区别于忠实原版。

修复字体、间距和坐标时不得改变字符。页面越界仍须检查，但不能用“改回带批注源页”作为通过条件。

### 阶段 G：按结果能力输出

结果分别显示：印刷内容是否完整、是否有遮挡未决、版式是否还原、各格式是否生成。任务结束不等于识别成功。

建议用户可读状态：完整印刷内容、部分印刷内容（N 处受遮挡/未辨认）、无可用内容；版式与文件生成另列。

成品禁止包含 annotation 层及未知混合原图。局部不明文字在预览中使用有说明的占位；导出清单说明缺失位置。正式输出是否含占位必须显式标为部分结果，不能声称完整书稿。含批注的源 PDF/图片只留在内部对照与诊断附件中，不能自动打包进成品 ZIP。

## 5. 最小数据契约

| 对象 | 核心字段与不变量 |
| --- | --- |
| RecognitionScope | printed_original_only；随 run 冻结 |
| PageRegion | region_id、source_version、layer、kind、bbox/mask、reading_order、boundary_status；保存身份与证据 |
| RegionCandidate | candidate_id、region_id、base_revision、visual_lines/公式/表格、unresolved_spans、response_id；独立于采用稿 |
| RegionAdoption | region_id → adopted_candidate_id；同一区域仅一个活动版本 |
| CoverageObservation | observation_id、source_bbox、origin、scope_disposition、mapped_region_ids；墨迹提示独立保存 |
| Verification | candidate_id、checked_region_ids、content_verdict、coverage_verdict、issues；不靠整页布尔值推导所有块通过 |
| ContentIssue | issue_id、stable_target_id、origin、category、repairability、evidence、status、supersedes_issue_id |
| GeometryEvidence | target_id、measurement_basis、match_status、source_bbox；local_measurement 不能代替匹配通过 |
| ExportManifest | scope、内容/布局修订、未决区域、各格式状态、原图包含策略；保证不输出批注 |

与现有 PageContent/PageLayout 对接时，PageContent 由已采用区域版本派生。候选库不能再兼任正文列表。旧 V2 修订保持原样，其识别范围记为 legacy_all_visible，不能直接继承为印刷原文已通过。

## 6. 请求预算与调度

继续保留独立上下文、请求记账、未知消费保护、暂停恢复、人工稿修订保护和格式独立导出。

请求计划按页面复杂度确定：简单页可识别加核验；复杂页先观察区域，再按大小批量转录和核验。不要强行让所有页面固定使用相同次数。

在派发前为该任务保留核验额度；复杂度导致预计预算不足时先合并简单区域或产生明确部分结果，不静默扩大总预算。首轮覆盖全书优先于单页无限修复。

请求幂等键应绑定页版本、识别范围、区域版本、任务类型和证据版本。不同问题指向同一印刷目标且需要同种观察时合并派发；不要只按 issue_id 去重，也不能仅凭同一张上下文裁图就合并不同的实际目标。

默认额度、像素尺寸和分块阈值需要通过样本评估确定；本设计不虚构速度、价格或准确率提升数字。

## 7. 实施顺序

### P0：先止住错误恢复

涉及 content_contract.py、workflow_model_contract.py、quality_service.py、prompts.py、storage.py、pipeline.py。

加入并冻结印刷范围；保存 repairability；分离本地观察与内容问题；核验按区域处置；禁止扫描线/批注问题进入印刷恢复队列；禁止含批注原图进入成品。不能只修改提示词而保留旧的质量与输出语义。

### P1：重做区域任务与候选采用

涉及 source_analysis.py、content_contract.py、pipeline.py、storage.py。

## 8. 验收条件

以下是待执行条件，不是本次已经通过的测试。

1. 当前两页作为回归样本：正文、公式、标题、页码应转录；页首手写证明、页边笔记、下划线及杂点不得进入成品。遮挡处明确未决。
2. 原书花体数学字母、斜体变量、印刷下划线、表格线、图形线条不能被当作手写任意删除。
3. 返回文字正确但行 bbox=null 时，不能凭坐标缺失判定正文漏识别；几何另列。
4. 一处不可辨批注不能把其他已核验正文降为不确定；混合区域中真实遮挡的字符不能被强行判为通过。
5. 同一区域两套转录不同，采用稿仍只有一套；不同分块方式不能产生重复句、重复公式或改变无关段序。
6. 三个问题共用一大裁图时，目标归属仍互不污染；修复只替换所绑定区域，必要的同目标请求合并。
7. repairable=false 的内容问题不得被类别或本地提示绕过；噪声和批注不消耗正文修复额度。
8. 同一问题证据框小幅移动不能被当成全新问题；真实新增错误必须被识别，不能借放宽框比较强行接受。
9. 公式框漂移到页码/标点时拒绝匹配，不能把无关墨迹提升为可信公式坐标；字符内容仍可保存。
10. JSON/PDF/LaTeX 及资源 ZIP 均不得通过源图兜底带回手写批注；无法去除批注且保真保留的图形须明示部分缺失。
11. 输出截断、局部结构错误、预算耗尽、暂停恢复和人工稿并发修改仍可控，已有可用区域不丢失。
12. 至少覆盖干净正文、密集公式、双栏、表格、图注、手写叠印、低清/旋转和损坏字层等固定样本。逐字误差、公式符号与结构差异、漏印刷区域、重复区域、批注混入、遮挡处无依据补写分别计数。

结构性验收要求：采用稿重复区域为零、已标注批注混入为零、明确遮挡处无依据补写为零。文字准确率及复杂页质量须实测公布，不能用可编译、模型一致或固定响应测试代替。
