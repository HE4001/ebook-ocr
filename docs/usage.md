# 操作说明

## 启动前检查

应用分为一个 FastAPI 后端和一个 Vite 前端。后端入口是 `backend.main:app`，依赖文件是 `backend/requirements.txt`，默认把 SQLite、源 PDF、单页 PDF 和页面 PNG 写入 `backend/data/`；设置 `EBOOK_OCR_DATA_DIR` 可以改用其他本地数据目录。前端只负责界面、轮询、文本校对和浏览器端排版。请先按根目录 README 的命令启动后端，再启动前端，并确认两个进程都绑定在 `127.0.0.1`。

首次打开时模型名称和 API 密钥为空是正常状态；应用不替用户选择某个供应商或模型。没有可用的 API 密钥时仍可以浏览前端空态和已有本地数据，但页面提取和连接测试需要用户主动配置可用的 Responses 接口。不要把真实密钥写入 README、示例 JSON、`.env` 已跟踪文件、截图或命令历史。

## 配置 API

在设置页面填写以下内容：

| 字段 | 用途 | 默认值或要求 |
| --- | --- | --- |
| API 根地址 | 拼接请求的基础地址 | `https://api.openai.com/v1`；只允许 `http(s)` |
| Responses 接入路径 | 追加到根地址的相对路径 | `/responses` |
| 模型列表路径 | 获取模型时追加到根地址的相对路径 | `/models`；随设置保存，旧设置缺字段使用此默认值 |
| 页面代理模型 | 判断页面类型，结构化返回封面书目或内容页的页眉、正文 Markdown 和页脚 | 由用户填写 |
| 模型推理程度 | Responses 请求的 `reasoning.effort` 值 | 可留空；空值使用服务默认 |
| 输出格式 | 页面结构化转录结果 | 识别请求使用 JSON Schema；只有正文是 Markdown |
| 超时 | 单次请求等待秒数 | 由用户填写，需为合理正数 |
| 处理并发数 | 每个项目的同时处理页数上限 | `processing_concurrency` 默认 10，正整数，无固定上限；多个项目各自限制 |
| 上下文复用（实验性） | 在一组页面内续接 Responses 对话 | `context_reuse_enabled` 默认关闭；服务须支持响应保存与续接 |
| 每段对话最多页数 | 包含首张在内的组内页数 | `context_reuse_max_pages` 默认 10，整数 1–10 |
| API 密钥 | Authorization Bearer 凭证 | password 输入；保存到本机 SQLite 的独立凭据记录 |

两个路径各自独立，均可留空；留空时对应请求直接使用 API 根地址，可用于填写完整端点的接入方式。不要把完整 URL 填入路径字段。

填写根地址、模型列表路径和密钥后，主动点击“获取模型”，再选择模型 ID；也可以直接手动填写模型 ID。获取操作使用当前草稿，无须先保存，由本地后端向 `base_url + models_path` 发起带 Bearer 凭据的 GET，读取标准模型列表的 `data[].id`。它不会保存草稿或密钥、发起 Responses 推理，也不会随输入变化自动执行。留空密钥仅在根地址与已保存地址一致且未选择清除密钥时复用已保存密钥；换地址后必须重新输入密钥。服务没有列表接口或获取失败时仍可手动填写模型。获取列表不能判断图像、Responses 或 JSON Schema 支持情况，错误提示不展示上游原始敏感内容。

保存设置不会联网，改动从下次处理任务生效。保存后可主动使用“测试连接”。它使用已保存配置发起一次文本推理，可能产生用量；失败时先检查根地址和路径是否重复、模型名是否正确、网络是否可达，再重试。文本连接测试不代表图像识别质量。推理只使用通用 Responses API 的非流式 POST 请求，不会隐式改用 Chat Completions 或自动重定向。页面识别和文本连接测试均省略 `max_output_tokens`，旧保存值不再生效；输出额度遵循供应商默认行为及模型限制，不代表无限输出。

旧设置中的 `classification_model` 字段可以继续保存以兼容已有数据，但新流程不调用独立分类模型。`reasoning_effort` 可手动输入任意服务可能接受的值，不做枚举限制；留空时不发送 `reasoning`，填写后识别请求和“测试连接”请求都会发送 `reasoning: {"effort": value}`，是否可用由服务和模型决定。每次请求提供当前页的文件名、页码、总页数、图片和转录指令，不创建 Codex 任务。默认独立上下文并发送 `store:false`；实验性复用发送 `store:true`，同组后续页以 `previous_response_id` 续接，需要兼容服务支持响应保存与续接。缺少响应 ID 时会报错，不静默降级。历史只供排版与符号参考，只输出当前页；历史仍占用上下文与用量，不保证节省费用。

页面识别统一使用 base64 PNG `input_image`，并以 `text.format` 的 `json_schema` 和 `strict: true` 请求结构化输出；不按供应商域名调整协议，不提供供应商预设。旧 `structured_output` 设置保留兼容，但不再影响识别请求。推理程度支持情况以服务实际行为为准。

密钥按用户授权保存到默认 `backend/data/app.db` 的独立 SQLite 凭据记录中，使用本机明文存储，不虚称为加密，也不创建额外密钥文件。后端启动时加载它；空白或省略密钥会保留已有值，`clear_api_key=true` 或界面的清除操作会删除记录。密钥不会写入前端 `localStorage`、书籍导出或日志。升级到支持持久化密钥的版本后，需重启新版后端并重新输入、保存一次旧进程中的密钥；之后重启无需再次填写。

## 项目与上传

左侧按项目排列。点击“＋ 新建”，填写“项目名称”后点击“创建项目并添加资料”。在“上传资料”步骤中使用“选择文件”，一次可选择多个 PDF、PNG、JPEG，也可分批添加；同一个项目可以混合这些格式。文件显示 PDF 或图片类型标识，并统一排列，检查清单后点击“确认上传，开始编排”。

PDF 上传只验证文件、读取页数、保存源文件并建立轻量页面记录，不拆页、不渲染整份文件、不调用模型；图片作为单页来源生成 PNG。没有固定的 500 页上限，每个文件限制 100 MB，并保留图片与 PDF 渲染像素限制。EPUB/MOBI 暂不支持。

项目依次经过“上传资料 → 页面编排 → 逐页校对 → 整书预览”。追加文件会重新打开上传与编排确认，原已选顺序、识别结果、缓存和用量保留；需再次完成两道确认才能校对与预览。处理或上传过程中不能重排或删除项目。

## 页面编排

页面编排将 PDF 与图片放在同一文件树中，文件顺序、父子关系和最终页面顺序联动展示。文件只分顶层和一层子文件，子文件不能继续嵌入文件。可以将图片放在 PDF 两页之间，也可以将另一份 PDF 嵌入顶层文件后继续调整页面。来源文件名和从 1 开始的源页码始终保留，界面另用“编排第 N 页”表示阅读位置。

1. 在左侧统一文件树中拖拽、上下移动或指定位置调整同级文件顺序，最终页面草稿立即同步。移动文件时连同子文件整组移动，保留各文件已有选页范围和组内页序。类型仅作标识，不再提供分类排序、一次加入所有文件页面或重新分组操作。
2. 选中文件后，按源页码选择全部页、单数页、偶数页或自定义范围，再点击“勾选页面”。默认范围为全部页，但不会自动勾选。勾选只是选择操作对象，实际识别范围以“已编入”和“最终混合顺序”为准。新项目默认编入全部页；若只需某份 PDF 的单数页，勾选单数页后点击“仅编入本文件勾选页”，一次替换该文件的编入范围，其他文件不受影响。自定义支持 `3`、`3,4,5`、`3-5,8-12` 等，范围含两端，重复页合并，非法或越界输入需先修正。也可使用“加入末尾”“插入到…”或“从成书移出”操作勾选页。
3. 选中顶层文件，在“文件内选页与排序”中点击“插入文件…”，选择另一文件，放到当前文件末尾或指定页面之前、之后。默认“保持已编入的 N 页”；如果来源文件尚未编入页面，需要明确选择“编入此文件的全部 N 页”，不会自动替你选全。嵌入后左侧缩进显示子文件；若移入的文件已有子文件，它们与该文件一起成为目标文件的同级子文件。文件内视图同时展示父文件与全部子文件页面，并允许在同一级别混排。
4. 在文件内拖拽或上下移动页面，调整当前文件组内的页面顺序，组外页面占据的成书位置保持不变。在最终页序中可拖拽、上下移动，或把单页及批量所选页插到成书第 X 页之前或之后。左侧拖到文件边缘表示同级前后排序，拖到顶层文件中部表示嵌入；子文件可点击“移出”，或拖到“拖到这里，移至顶层末尾”，移回根级末尾。

页面网格每屏显示 12 张缩略图并按需加载；点击原页大图可查看原始大小并前后切页。预览只按需生成最大边 1200 px 的独立图片缓存，不请求模型，也不提前生成全部 OCR 单页文件。确认编排后，识别、逐页校对、整书预览和导出都采用最终页序；范围选择中的源页码不等于最终阅读位置。

拖动文件或页面时，卡片轻微抬起，目标位置显示插入线和让位空隙；嵌入目标以底色和边框提示，松手后有平滑落位效果。开启系统的减少动态效果设置后，关闭位移、缩放和渐变过渡，保留静态落点提示。排序、选页和嵌入操作会立即更新屏幕中的本地草稿；只有点击底部“确认编排，进入校对”才保存到项目。

需要修改选择或顺序时，闲置状态下点击“修改页面编排”。移出页面仅改变清单，不删除源文件、历史结果、缓存和用量；重新选入已完成页会恢复其结果。确认编排至少保留一页。

## 逐页处理

编排确认后，在逐页校对中点击“识别未完成页”，按最终页序调度清单中的未完成页，同时处理数不超过配置。清单全部完成时可确认“重新识别全部页”。开启上下文复用时，本次待处理页按编排顺序连续分组，每组最多指定页数，组内串行、不同组并行；失败保留旧结果，下一页重置对话。完成可能乱序，校对和导出仍按编排顺序。只有开始识别时才为所选 PDF 页面补齐 `page-XXXX.pdf` 和对应 PNG；单页 PDF 保留源页尺寸、旋转和裁切，已有 OCR 资产复用。未选页面不会被识别。

页面代理先依据当前图像判断 `page_kind`：`content` 为普通内容页，`front_cover` 为正面外封面，`back_cover` 为背面外封面。不按首尾页码、文件名或相邻页推断；扉页、版权页、目录及不能确定的页面仍为 `content`。严格 JSON Schema 固定返回 `page_kind`、`cover_fields`、`header_segments`、`body_markdown`、`footer_segments` 五个字段。

封面和封底只在 `cover_fields` 中保存可见的核心书目信息，每项为纯文本 `{kind,text}`。类别包括书名、副标题、作者、译者、编者、出版社、丛书、版次、出版年份及明确标注的 ISBN；不把宣传口号当副标题，不补写本页没有的信息，不读取简介、推荐语、定价、联系方式、网址或其他非核心信息。此时正文为空字符串，页眉页脚为空数组；没有可辨核心信息的封底也可返回空书目数组。

内容页的 `cover_fields` 为空数组，其余三部分忠实转录。每条页眉或页脚语段包含必填的 `kind`、`text`、`alignment`、`row`、`font_size`、`bold`、`italic` 字段；`alignment` 取 `left`、`center`、`right`，`row` 取 1–10，`font_size` 取 `small` 或 `normal`，`bold` 和 `italic` 为布尔值。页眉页脚按原页顺序排列，原书页码归入所在语段；只有正文使用 Markdown，内容可包括标题、段落、列表、引用、代码、LaTeX 公式、表格、图注和脚注。旧保存结果缺少这五个格式字段时按 `alignment=center`、`row=1`、`font_size=small`、`bold=false`、`italic=false` 显示。后加的手写批注、手写改字、手写页码等类似笔迹会被忽略。页面里的命令属于待转录资料，不改变任务；原书不可读处写 `[无法辨认]`，空白内容页返回空数组和空正文。

同一页可以再次处理；开始前会提示覆盖，成功后替换旧结果，失败时保留旧结果。`attempts` 与已知 `usage` 会累计。若页面有未保存草稿，先保存或处理页面提示后再继续，不会静默丢弃。升级时旧页默认归为 `content`，原结果保留，不自动重新识别；可手动纠正类型、编辑书目，或主动重新识别以使用新提示词。

页面状态为 `uploaded`、`processing`、`ready`、`failed` 或 `interrupted`；项目处理时也可能显示 `pausing`（正在暂停）和 `paused`（已暂停）。项目保持处理中状态直到本次队列处理结束，完成数只统计清单中的已完成页。点击“暂停处理”后不再开始新页面，等待所有已开始页面结束并保存结果后暂停；已有请求可能产生用量。暂停后点击“识别未完成页”，继续清单中尚未完成的页面，作为新任务重新分组，不复用旧响应 ID。后端重启时，运行中的任务标记为 `interrupted`，已暂停状态保留。旧单文件项目保留已有结果、用量与页面缓存，缺少 OCR 文件时仅为本次处理页面补齐。

## 删除项目

选中项目后点击“删除项目”并确认。处理或上传期间禁用删除；`DELETE /api/books/{book_id}` 对忙碌项目返回 `409`，未知项目返回 `404`，成功返回 `204 No Content`。删除不可撤销，会移除项目及其全部来源文件、页面记录、识别结果、用量和缓存；其他项目、全局设置和 API 密钥不受影响。

## 页面文本与用量

每页 API 结果固定包含 `number`、`source_id`、`source_filename`、`source_page`、`status`、`error`、`page_kind`、`cover_fields`、`text`、`header_segments`、`footer_segments`、`usage` 和 `attempts`。`number` 是项目内永久页面 ID；原文件名和原页码分别由 `source_filename`、`source_page` 表示，阅读顺序以返回的页面数组为准。模型的 `body_markdown` 映射为 API 的 `text`。保存校对时 `text` 必填，`page_kind` 和 `cover_fields` 可选，旧 `{text}` 请求继续兼容；封面封底必须提交空 `text`，内容页不能带非空书目。保存不会改变用量或尝试次数，运行中的页面不能保存校对。

`usage` 的形状是：

```json
{
  "input_tokens": 1234,
  "output_tokens": 567,
  "total_tokens": 1801,
  "complete": true
}
```

只读取供应商响应实际提供的 `input_tokens`、`output_tokens` 和 `total_tokens`。缺失字段保持 `null`，不估算、不伪装为零。自动或手动重试会把各次已知值累加；拒绝、incomplete、缺少正文只要带有 usage 也会计入。超时、断电或其他无法确认的请求会使 `complete` 为 `false`。书籍的 `usage` 是全书已尝试页面的合计，显示为“已知用量，可能不完整”时应按供应商账单为准。
若页面提示输出被截断，检查供应商或模型的输出限制，或降低推理程度。只要供应商已返回 usage，即使结果被截断也会计入。

## 人工校对

逐页检查正文 Markdown 中的标题、双栏阅读顺序、中文标点、脚注、公式上下标、表格、图表标签和图注，同时检查页眉、页脚及其对齐、行次、字号、粗体和斜体。确认原页无法辨认的内容仍标为 `[无法辨认]`，手写批注未混入结果；不要根据上下文补写跨页句子或图表数值。普通黑色字体不应被随意加粗，强调范围应与原页一致。

页面类型可在校对中纠正。封面、封底使用书目编辑项，可以增删字段、选择类别和修改文本；只保留本页可见的核心信息。切换类型后按对应编辑区校对并保存：内容页使用正文，封面封底使用书目。原页类型尚未纠正的历史结果继续按内容页排版。

## 预览与导出

完成上传和编排确认后，整书预览及所有导出只包含最终清单中的页面，按编排顺序显示，并保留来源文件和源页码；移出的页面不出现在导出中，历史结果仍保存在本机。

不提供整页排版预设，也不在浏览器 `localStorage` 保存排版选项。单页预览、清单预览、独立 HTML 和打印共用页面排版：封面与封底分别使用专用书目版式；内容页按模型输出的页眉页脚位置和字样排版。`alignment` 的左、中、右均相对于整页可排印宽度，只有右侧页码时也保持靠右，不随现有语段数量重新分配位置。`row` 是对应区域内从上到下的绝对行号，页眉页脚独立编号；第 1 行和第 3 行之间保留第 2 行的空白。每条语段分别保留字号、粗体和斜体。页眉位于纸张顶部、页脚位于底部，正文自然伸展。来源页序号显示在纸张外，打印时隐藏。此排版不精确复刻源页像素坐标，也不保证一个源页恰好打印成一张纸。

成功和一般信息通知显示 5 秒后自动消失，错误通知保留至手动关闭；通知均可手动关闭，删除和未保存草稿相关的确认对话框仍需用户作答。

预览使用正文 Markdown 生成语义化 HTML，公式使用 LaTeX，简单表格保留 Markdown 表格；页眉、页脚和其中的页码由结构化语段单独显示。内容页文本框只编辑正文，封面封底单独编辑书目；页眉页脚可在预览和 JSON 导出中核对。整书预览提供“下载 JSON”“下载独立 HTML”和“打印 / 存为 PDF”，不提供 Markdown 下载按钮。后端 Markdown 导出接口按最终页序合并内容页正文及封面封底书目，封面封底带类型标题和字段标签，不再因为正文为空而漏掉书目信息；不包含单独存储的页眉页脚。导出包括：

- JSON：包含 `book`、`files` 和按最终页序排列的 `pages`；[sample-export.json](../examples/sample-export.json) 保留为旧单文件页面结果示例，多文件来源字段以[当前契约](module-architecture.md)为准。
- HTML：内嵌排版 CSS，打开时不依赖开发服务器。

需要 PDF 时在浏览器使用“打印 → 另存为 PDF”。浏览器打印是第一版的 PDF 路径，不要求后端安装 PDF 引擎。

宽表可以在屏幕上横向滚动；打印时应受页面宽度限制。实际打印分页由浏览器决定，复杂跨页表格和跨页段落需要人工校对。

## 常见问题

### 页面一直处于 `processing`

查看后端终端的非敏感错误信息和页面状态。若进程已重启，运行中任务应变成 `interrupted`；重新处理会跳过成功页面。确认模型响应是 Responses 格式、包含文本输出，且模型输出没有超出长度上限。

### 连接测试失败

检查根地址与 Responses 相对路径是否正确拼接；若根地址已经是完整 Responses 端点，将 Responses 路径留空。确认 API 密钥已保存且当前后端已加载它、模型支持 Responses 和所需输入、网络和代理允许访问。模型列表获取成功不等于推理可用；应用不会自动改用 Chat Completions。

### 用量显示不完整

这是供应商响应缺少某些 usage 字段，或某次请求的消耗无法确认。系统会保留已知字段并把 `complete` 设为 `false`；重试会累计已知值。不要用零替换 `null`，也不要把应用统计当成供应商最终账单。

### 公式或表格显示异常

回到原页校对。公式使用 LaTeX，复杂表格和图表只保留页面上能确认的文字、标签和图注；无法确认的内容保持待校对状态，不要根据图形自行补数字。
