# 操作说明

本版默认流程为 **选择文件 → 选页 → 识别 → 结果**。选页后点击一次“开始识别”，系统自动取得可编辑文字与结构、复核完整源页覆盖、有限恢复、派生布局和生成输出，不等待逐页校对、批准疑点或填写坐标。高级编辑仍可主动使用。本轮 OCR V2 只实现并静态阅读，**未测试、未运行验证**；没有执行测试、构建、类型检查、lint、试编译、服务启动、模型调用或迁移。旧文档中的运行记录仅作历史参考。

## 启动与配置

Windows 双击根目录 `ocr.bat` 打开服务管理菜单，回车启动并打开页面；菜单也可停止、重启和刷新状态。关闭窗口后服务继续运行。命令行入口保留 `ocr.bat Start -NoBrowser`、`Stop`、`Restart` 和 `Status`。停止或重启可能中断任务，恢复规则见下文。本说明中的启动命令未在本轮执行。

后端为 FastAPI，入口 `backend.main:app`，前端为 React/Vite，分别绑定 `127.0.0.1:8000` 和 `127.0.0.1:5173`。默认数据写入 `backend/data/`；可用 `EBOOK_OCR_DATA_DIR` 指定其他本地目录。启动前需安装 Python、Node.js 和 pnpm，版本及手动启动步骤见 [README](../README.md)。启动器复用已安装依赖，缺少组件时按项目依赖文件准备；日志在 `.cache/launcher/`。

重排候选的 PDF 需要本机 XeLaTeX、Fandol 字体和模板宏包。一键启动优先使用有效的 `EBOOK_OCR_XELATEX`，再查 PATH 和常规 TinyTeX 目录；缺少时准备 TinyTeX/模板组件。直接启动后端只查找编译器，不安装依赖。缺少编译器只影响重排输出，已保存内容和 JSON 仍可用。协调器确定需要保留整页时，直接从原 PDF 或原图及冻结来源几何生成 PDF，不依赖字体、编译器或精确布局，并明确标为源页保留。已冻结的重排快照缺候选缓存时报告 PDF 失败，不在下载时偷偷改成源页。完整自定义文档所需的额外宏包由用户提供。编译关闭 shell-escape 并保留超时，详细环境说明见 [LaTeX 参考](LATEX_LAYOUT.md#编译环境)。

在设置中填写协议、API 根地址、模型和密钥并保存：

| 字段 | 用途 |
| --- | --- |
| API 协议 | 显式选择 `openai_responses` 或 Google Gemini 原生 `gemini`，不自动换供应商 |
| API 根地址 | OpenAI 默认 `https://api.openai.com/v1`；Gemini 通常为 `https://generativelanguage.googleapis.com/v1beta`，只接受 HTTP(S) |
| Responses 路径 | 仅 OpenAI 使用，默认 `/responses`；留空时直接请求根地址 |
| 模型列表路径 | 通常为 `/models`；留空时根地址本身就是模型集合 |
| 页面代理模型 | 识别、独立审查和局部修复所用的视觉/结构化输出模型，由用户选择或填写 |
| 推理程度 | 手动输入，留空不发送，使用服务默认 |
| 超时 | 单次请求的等待秒数 |
| 处理并发数 | 模型并发默认 2；渲染并发默认 1，串行生成 |
| API 密钥 | 当前协议和地址的凭据，存入本机 SQLite |

不要将完整 URL 填入相对路径字段。Gemini 生成请求会在模型集合后追加 `/{模型名}:generateContent`，不要把单个生成端点当作集合地址。OpenAI 不回退 Chat Completions，不跟随自动重定向；Gemini 使用 API Key，不提供 Vertex OAuth。

主动“获取模型”使用当前设置草稿读取供应商模型列表，不发推理请求，不保存草稿或密钥。没有列表接口时可直接填模型 ID。列表成功不代表视觉或 Schema 可用。“检查已保存配置”只检查本地模型和密钥是否存在，不请求模型，也不表示连接或推理成功。实际图片及 JSON Schema 能力由正常首页面请求确认，任务不额外发付费预检。

OpenAI 非空推理参数作为 `reasoning.effort` 发送；Gemini 的 `minimal/low/medium/high` 作为 `thinkingLevel`，不小于 -1 的整数作为 `thinkingBudget`。应用不按模型名猜支持能力。识别、审查和修复使用协议各自的结构化输出参数：OpenAI 为 `text.format/json_schema`，Gemini 为 `responseMimeType/responseJsonSchema`。旧 `structured_output` 和分类模型保留兼容；实验性上下文复用及其设置已移除，旧保存值不再生效。每次识别、审查、修复及重试均使用独立上下文，OpenAI 发送 `store:false`，Gemini `contents` 仅包含当前页及本次请求所需资料，不累计其他请求的图像、响应或思考签名。不发送 OpenAI `max_output_tokens` 或 Gemini `maxOutputTokens`。

HTTP 错误显示状态码及限长的供应商 `message`、`param`、`code`，已知密钥脱敏，不公开完整原始响应。400、认证、Schema 等配置错误集中停止无效调用，并保留已产生结果及用量；只有明确暂时错误可重试。

保存配置不联网，从下次新任务生效。运行中的任务保持原地址、协议、模型与设置。暂停或中断后恢复也使用原快照；若当前地址或协议已换，恢复返回明确冲突，需恢复原接入并保存相应密钥。新接入密钥不会发到旧运行的地址。

密钥明文保存在本机数据库独立凭据记录，不放入浏览器 `localStorage`、运行快照、书籍导出或日志。同一规范地址和协议下省略或留空密钥保留旧值；切换接入时必须输入新密钥或明确清除。数据库备份也可能含密钥，勿作为公开发布包。

## 选择文件、选页与一次识别

点击“新建项目”，选择一个或多个 PDF、PNG、JPEG。上传后进入选页，默认全部选中，可按源文件、源页范围选择并保存页序，再进入识别页一次启动。上传和选页不调用模型。PDF 先读取页数、保存原文件并建立轻量来源记录，源图和预览按需准备；图片形成单页来源。每个文件上限 100 MB，EPUB/MOBI 暂不支持。多文件上传按文件保存：失败项返回文件名与原因，成功项不会因其他文件失败回滚。

选页保存有序 `page_id` 及对应 `source_version`，形成独立选择草稿。取消选择不会删除源文件、源页、历史修订或用量；未选页仍可通过稳定 ID 预览。页面 `number` 是永久整数编号，`page_id` 是永久 UUID，均不同于源文件的 `source_page`。运行的 `position` 与错误详情中的位置为零基，界面页次从一开始显示。旧页面编排及文件嵌入只在可选高级工具中使用。

识别页显示处理范围及已有结果，模型和额度细节可展开。启动时冻结选择修订、页序、来源版本、基准稿件与设置；运行中保存新选择只更新下一次草稿，不能改变当前运行。上传、源页编排与删除项目在未结束任务期间受限。新项目默认按原页尺寸输出，已有保存设置不改写。已中断任务可主动恢复，也可创建补做运行；另有未结束运行时不能启动或恢复竞争任务。

已有人工稿默认保留。只有开始前明确指定的替换范围可自动采用新候选，旧修订仍归档；运行中主动保存新稿后，后台候选不能覆盖它。本轮候选、结果及输出仍独立保存，结果详情读取本次运行的候选，避免拿当前旧稿冒充本轮结果。受保护稿件及采用冲突有明确说明。

## 自动阶段、额度与状态

自动流程先准备来源并进行一次粗版面分析，使用完整页概览和必要原始高清裁切识别，保存类型化内容后独立复核完整源页。复核既核对已有块，也寻找没有块 ID 的遗漏；有明确证据且额度允许时局部重读并复核。布局随后从已保存内容派生，渲染只处理输出。合法 JSON、模型自报置信度或编译成功都不能单独代表识别通过。

正常页面一次识别加一次独立复核。N 页默认共享额度为 `6N`；每页物理请求上限 `12`，明确暂时错误重试共享最多 `2` 次，局部恢复最多 `2` 轮，候选编译最多 `3` 次。请求前原子预约，失败和结果未知的已发送请求也计数。额外处理先保护其他页面的基础识别和首次复核，恢复与修后复核一起预约；默认渲染并发为 `1`。不通过反复改字、编译或异常缩字制造成功。

收到有界正文后先保存到本地，再严格解析；完整响应中合法块可以保留，截断、空数组和字段错误不会冒充完整识别或空白。已保存正文可本地重解析，不再次付费请求。保存失败明确记录“已收到但未保存”，消费未知不自动重发。普通界面和输出只给定位、原因与结果，不显示原始模型正文、密钥或请求图像。

额度不足时，系统自动结束可完成的阶段，对未完成检查标记问题并保留源内容，不弹出逐页续费或批准关卡。之后可以主动发起新任务。

页面处理结束与实际成果分开：

| 成果 | 含义 |
| --- | --- |
| 可编辑结果 | 已保存文字和结构，另行说明内容是否可靠、布局是否忠实 |
| 部分区域保留原图 | 部分内容无法可靠重排，必要源区域保留，已有可编辑内容仍保留 |
| 整页保留原图 | 保留可读取的原页，不能计作 OCR 文字化成功 |
| 未取得结果 | 来源不可读或尚无可用内容/原页结果，列出具体原因 |

内容结论为 `usable/uncertain/unavailable/unverified`，布局结论为 `faithful/approximate/unavailable/unverified`；PDF、LaTeX、JSON 各有 `pending/generating/available/failed` 状态。旧 `ready`、运行 `finished` 或满格进度只表示相应执行状态，不代表识别通过。问题说明不是人工待办，不阻止其他页面继续。

不确定内容按差异、响应状态或覆盖证据进行有界恢复；局部重读只看来源，不把旧答案当真值。仍无法确定时保留最佳内容与必要源区域，必要时保留整页。当前复杂表格保留完整表格和表头源区域，JSON 保留类型化单元格及合并关系，布局为近似；缺可靠完整边界时不能造网格，交由必要原页保留。不可读的源页明确列出，不能省略后宣称完整。默认正文不插入额外水印或猜测文字。

点击暂停后停止新阶段和请求预留，已发送请求继续结算，不取消这些请求。状态先为“正在暂停”，结算后为“已暂停”。恢复使用同一 run ID、冻结范围、设置和已完成阶段，不另开队列。服务退出后恢复记录中断状态；无法确定结果的已发送请求计一次，不静默重发。

用量只记录供应商实际提供的输入、输出和总 token。缺失字段为 `null`，不估算为零；已知值累计，无法确认的请求令 `complete=false`。显示“已知用量，可能不完整”时以供应商账单为准。

## 结果、预览与一致导出

任务结束后后台自动冻结输出快照，无需打开页面或手动导出才继续。JSON、PDF 和 LaTeX 资源包引用同一页序、来源版本和精确候选内容/布局修订；与当前采用稿分别保存，历史人工稿不会被当作本轮候选。历史结果源预览携带运行 ID 和来源版本，读取冻结来源，之后改源或改选择不会让旧结果显示新源页。

- `json`：优先生成，包含本快照、类型化内容、可缺失的派生布局及各页处置；内容已保存但无布局时仍可用。
- `pdf`：完整范围的冻结 PDF，既可下载也可预览。任一页源文件、几何或对应重排候选缺失时，该格式失败并列全缺页，不静默生成不完整文件。
- `latex`：按相同页序打包源码、JSON 与所有引用源区域资源；必要整页保留使用源页引用，封面和目录也从完整类型化内容生成。

每格式即时保存状态和原因，失败不影响其他可用格式。错误详情给全部缺页的页面身份、快照位置、源文件与源页、来源版本、精确修订及原因。PDF 可用不代表文字化或布局忠实，源码包缺资源也不能标为可用。下载只读冻结资产，不额外识别、复核或编译。补做可复用相同输入与设置的 PDF；包含快照身份的 JSON/LaTeX 为新快照重新生成。

改动当前选择、纸型、排版或保存新稿后，旧运行和输出快照仍代表原冻结版本。需要补做时主动创建关联旧运行的新任务，复用已保存内容和已完成基础阶段，只给缺失阶段分配调用；改变来源的页面不能复用旧结果。旧“当前已保存稿”导出继续属于高级兼容入口，不会把旧稿变成已自动复核。打印时使用 PDF 自身纸张尺寸。

## 可选高级编辑与旧接口

高级工具保留原图/输出对照、自由 LaTeX、封面书目、原行/公式组布局校准和草稿编译。自由源码可为 LaTeX 片段或完整文档；实际修改后切为 `custom_latex`，旧布局和历史稿保留。完整文档保持自身纸型、字体与分页；模板片段使用项目纸型；原书还原页按源画布映射。

运行中也可保存当前页，前端携带 `expected_content_revision` 和 `expected_layout_revision`；冲突返回 409，需要加载最新修订后再保存。校准始终检查双修订，后台自动采用也检查基准修订。旧校准表单不含源资源处置选项，保存时保留同源页面的图形、源区域/源页资产及保留说明，不会因改动一行自动变成已完整转录。保存不增加模型用量，未保存草稿不参与整书导出。手工编辑不构成识别的必经步骤。

纸型与排版可独立保存，包括 A4、A5、A6、B5、B6 和 6×9 英寸。修改当前设置不改变运行快照；旧输出仍可下载。旧 `process/pause` 路由和采用 `expected_arrangement_revision` 的运行属于 V1 显式兼容，新默认流程只使用 V2 选择修订。恢复已知 V1 运行继续走 V1 处理器，不把旧布局/源码误当作 V2 内容契约。

旧编辑、校准、单页/整书编译、`export`、`export.tex`、`export-manifests` 与 digest PDF 缓存接口继续兼容。新流程使用输出快照下载；旧直接导出反映调用时当前已保存内容。`export.tex` 的无资源单文档仍为 `.tex`；多个文档或含引用资源时返回 ZIP，包含源码、映射及全部引用资源，资源缺失或越界返回 422。完整自定义源码不改写。LaTeX 语法及旧布局细节见 [旧 LaTeX 参考](LATEX_LAYOUT.md)，[旧功能参考](REFERENCE.md) 与 [旧模块参考](module-architecture.md) 不再定义新版必经流程。

## 新 API

下表路径均以 `/api/books/{book_id}` 开头，run、源页及快照必须属于当前项目。正常页面先读摘要，选页及内容按需分页，不批量携带整书正文。

| 方法与路径 | 内容 |
| --- | --- |
| GET `/overview` | `BookDetail`，包含项目、源文件与空 `pages` |
| POST `/files` | 多文件上传，返回 `Arrangement` 加 `import_errors:[{filename,reason}]`，保留部分成功 |
| GET、PUT `/selection` | 读取/保存 `SelectionDraft`；保存传 `page_ids`、`source_versions`、`expected_selection_revision` |
| GET `/source-pages?offset=0&limit=100&source_id=...` | `{items,total,offset,limit}`；`source_id` 可省略，全部源页独立于当前选择，limit 最高 500 |
| GET `/source-pages/{page_id}/preview` | 稳定源页 PNG；可用 `source_version` 校验当前版本，历史结果传 `run_id` 读取冻结来源 |
| POST `/runs` | V2 `selection_revision`、`client_request_id`、可选 `policy`、`request_limit`、`continuation_run_id`；范围来自保存选择，不重传页码 |
| GET `/runs/summaries`、`/runs/{run_id}/summary` | 轻量运行摘要、阶段计数、已知用量、输出快照及各格式状态 |
| GET `/runs/{run_id}/outcomes?offset=0&limit=100` | `PageOutcomeSummary[]`；limit 最高 500，包含本轮内容/布局/源处置结论 |
| GET `/runs/{run_id}/pages/{page_id}/content` | 本次运行精确候选的 `PageContent`；尚未取得内容为 `null` |
| POST `/runs/{run_id}/pause`、`resume` | 暂停或恢复同一运行，返回 Run |
| GET `/output-snapshots/{snapshot_id}` | `OutputSnapshot`：冻结页序、来源/精确修订及各格式状态 |
| GET `/output-snapshots/{snapshot_id}/{json\|pdf\|latex}` | 仅下载该快照已可用资产；PDF `?inline=true` 用于预览，默认 attachment |
| GET `/output-snapshots/{snapshot_id}/errors` | `{pdf:[...],latex:[...]}`，完整缺页详情，严格核对快照身份 |
| GET 项目根路径、`/runs`、`/runs/{run_id}` | 高级兼容完整详情；正常轮询使用 summary |

错误详情每项字段为 `page_id`、零基 `position`、`source_filename`、`source_page`、`source_version`、可空 `revision_id` 和最多 1000 字符的 `reason`，不含模型正文。下载资产的解析路径必须位于当前书目录内；补做快照允许引用以前快照中未变化的 PDF。

重复 `client_request_id` 返回原运行，暂停/结束运行不会因重复创建自动启动。另一个运行处于排队、运行、正在暂停或已暂停时，新运行返回 409。来源或选择修订冲突返回 409；范围无效返回 422；页面/任务/快照不存在返回 404。格式未 available 返回 409，资产缺失或路径越界返回 404；错误记录身份或结构异常返回 409，不暴露其原始内容。

旧 `results/issues/export-manifests` 继续用于高级兼容；V2 运行导出只读其自动输出快照，旧清单入口不另造竞争产物。已知 V1 请求仍使用 `expected_arrangement_revision` 及旧范围字段，版本分派保持显式。

## 升级与故障处理

新版首次启动按增量迁移写前备份：正文升级为 `app-before-latex.db`，布局升级为 `app-before-layout.db`，工作流升级为 `app-before-workflow.db`，本轮 OCR V2 升级另保存 `app-before-ocr-v2.db`。已有备份不覆盖。V2 在现有表中增加选择草稿及其修订、运行版本和响应元数据字段；从原选页顺序与来源版本建立初始选择，已有运行保留 V1 标识，不自动变成 V2 识别结果。迁移保留源文件、旧稿、修订、页序及用量，不调用模型，不把历史 `ready` 转成质量通过。原 Markdown 仅在内部 `pages.legacy_markdown` 保留，不公开到 API。迁移代码未在本轮试跑。

升级或换电脑前停止服务并复制项目及自定义数据目录。数据库及备份可能含明文凭据。没有一键历史恢复界面；需回退时保留当前库，在独立目录恢复与版本相容的备份。旧电脑的虚拟环境、前端依赖和启动器缓存应保留备份后在新机器重建。

任务长时间处理中时查看当前阶段及展开后的技术详情；重启后可恢复同一中断运行，已发送结果未知的请求不会重发。服务配置错误先修正协议、地址、模型、密钥或 Schema 能力；模型列表和本地配置检查不能代替真实工作能力。PDF/LaTeX 失败时查看各格式原因及完整缺页列表，已有 JSON 内容仍可下载。必要源图保留有明确结论，用户可主动高级编辑或补做，但系统不等待这一步。

启动器目录不匹配、端口占用和依赖安装问题可查 `.cache/launcher/` 日志及 [旧启动说明](LATEX_LAYOUT.md#编译环境)。[历史修复报告](RENDERING_REPAIR_VERIFICATION.md) 与 [历史验收清单](acceptance.md) 不能证明本版的运行效果。
