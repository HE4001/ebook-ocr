# 操作说明

本版默认入口是无人值守任务：上传资料后一次开始，系统自动完成识别、几何与字体估计、编译、独立内容审查、有限修复、结果和导出。用户无需逐页校对、批准疑点或填写坐标。高级编辑仍可主动使用。本轮重构**未测试、未运行验证**；旧文档中的测试和浏览器记录仅作历史参考。

## 启动与配置

Windows 双击根目录 `ocr.bat` 打开服务管理菜单，回车启动并打开页面；菜单也可停止、重启和刷新状态。关闭窗口后服务继续运行。命令行入口保留 `ocr.bat Start -NoBrowser`、`Stop`、`Restart` 和 `Status`。停止或重启可能中断任务，恢复规则见下文。本说明中的启动命令未在本轮执行。

后端为 FastAPI，入口 `backend.main:app`，前端为 React/Vite，分别绑定 `127.0.0.1:8000` 和 `127.0.0.1:5173`。默认数据写入 `backend/data/`；可用 `EBOOK_OCR_DATA_DIR` 指定其他本地目录。启动前需安装 Python、Node.js 和 pnpm，版本及手动启动步骤见 [README](../README.md)。启动器复用已安装依赖，缺少组件时按项目依赖文件准备；日志在 `.cache/launcher/`。

重排候选的 PDF 需要本机 XeLaTeX、Fandol 字体和模板宏包。一键启动优先使用有效的 `EBOOK_OCR_XELATEX`，再查 PATH 和常规 TinyTeX 目录；缺少时准备 TinyTeX/模板组件。直接启动后端只查找编译器，不安装依赖。缺少编译器时重排候选报告依赖错误；能读取源内容时可生成保留源页的 PDF 并带问题完成，源也无法形成输出时才技术失败。源文件、旧稿及可形成的源码和 JSON 仍保留。完整自定义文档所需的额外宏包由用户提供。编译关闭 shell-escape 并保留超时，详细环境说明见 [LaTeX 参考](LATEX_LAYOUT.md#编译环境)。

在设置中填写协议、API 根地址、模型和密钥并保存：

| 字段 | 用途 |
| --- | --- |
| API 协议 | 显式选择 `openai_responses` 或 Google Gemini 原生 `gemini`，不自动换供应商 |
| API 根地址 | OpenAI 默认 `https://api.openai.com/v1`；Gemini 通常为 `https://generativelanguage.googleapis.com/v1beta`，只接受 HTTP(S) |
| Responses 路径 | 仅 OpenAI 使用，默认 `/responses`；留空时直接请求根地址 |
| 模型列表路径 | 通常为 `/models`；留空时根地址本身就是模型集合 |
| 页面代理模型 | 识别、独立审查和局部修复所用的视觉/结构化输出模型，由用户选择或填写 |
| 推理程度 | 手动输入，留空不发送，使用服务默认 |
| 超时 | 单次请求的等待秒数 |
| 处理并发数 | 每个项目同时处理页数上限，默认 10 |
| API 密钥 | 当前协议和地址的凭据，存入本机 SQLite |

不要将完整 URL 填入相对路径字段。Gemini 生成请求会在模型集合后追加 `/{模型名}:generateContent`，不要把单个生成端点当作集合地址。OpenAI 不回退 Chat Completions，不跟随自动重定向；Gemini 使用 API Key，不提供 Vertex OAuth。

主动“获取模型”使用当前设置草稿读取供应商模型列表，不发推理请求，不保存草稿或密钥。没有列表接口时可直接填模型 ID。列表成功不代表视觉或 Schema 可用。“检查已保存配置”只检查本地模型和密钥是否存在，不请求模型，也不表示连接或推理成功。实际图片及 JSON Schema 能力由正常首页面请求确认，任务不额外发付费预检。

OpenAI 非空推理参数作为 `reasoning.effort` 发送；Gemini 的 `minimal/low/medium/high` 作为 `thinkingLevel`，不小于 -1 的整数作为 `thinkingBudget`。应用不按模型名猜支持能力。识别、审查和修复使用协议各自的结构化输出参数：OpenAI 为 `text.format/json_schema`，Gemini 为 `responseMimeType/responseJsonSchema`。旧 `structured_output`、分类模型和实验性上下文复用设置保留兼容，新自动审查使用独立上下文，不依赖整本历史。不发送 OpenAI `max_output_tokens` 或 Gemini `maxOutputTokens`。

HTTP 错误显示状态码及限长的供应商 `message`、`param`、`code`，已知密钥脱敏，不公开完整原始响应。400、认证、Schema 等配置错误集中停止无效调用，并保留已产生结果及用量；只有明确暂时错误可重试。

保存配置不联网，从下次新任务生效。运行中的任务保持原地址、协议、模型与设置。暂停或中断后恢复也使用原快照；若当前地址或协议已换，恢复返回明确冲突，需恢复原接入并保存相应密钥。新接入密钥不会发到旧运行的地址。

密钥明文保存在本机数据库独立凭据记录，不放入浏览器 `localStorage`、运行快照、书籍导出或日志。同一规范地址和协议下省略或留空密钥保留旧值；切换接入时必须输入新密钥或明确清除。数据库备份也可能含密钥，勿作为公开发布包。

## 上传、可选编排与一次开始

点击“新建项目”，上传一个或多个 PDF、PNG、JPEG。新上传页默认全部选中；可直接进入任务总览开始，不需要分别确认上传与编排。上传不调用模型。PDF 只读取页数、保存原文件并建立轻量页面记录，源页图像在使用时按需准备；图片形成单页来源。每个文件上限 100 MB，EPUB/MOBI 暂不支持。

需要改变范围或顺序时打开页面编排。可按源页码筛选、在文件或页面之间排序、穿插图片，也可使用一层文件嵌入；保存后才改变当前项目页序。取消选页只改变成书范围，源文件、历史修订和用量保留。页面 `number` 是永久整数编号，`page_id` 是永久 UUID；返回数组顺序表示编排位置，均不同于源文件的 `source_page`。

在任务面板一次确认处理范围、模型/输出设置、请求额度和可选人工稿替换范围。启动时冻结页序及其修订、来源身份、基准稿件和设置；运行中不能追加页面到该任务。上传、重排、选页增删和删除项目在运行、正在暂停或已暂停时受限。已中断任务可主动恢复，也可另开任务；有另一个未结束运行时不能恢复旧运行。

已有人工稿和旧稿默认保留，受保护页面自动形成“带问题完成”，说明历史稿未经过本轮审查。只有开始前明确指定的替换范围可以自动采用新候选，旧修订仍归档。运行中用户主动保存后，后台候选的基准修订已过期，不能覆盖新稿。

## 自动阶段、额度与状态

自动阶段依次为准备来源、全页识别、本地布局/字形拟合、生成编译、独立内容与布局复核、必要局部修复、终结。内容审查看完整源页，合法 JSON、模型自报置信度或编译成功均不能单独代表识别通过。

正常页面一次识别加一次审查。每页最多一轮局部模型修复及一次复审，共享最多两次暂时错误重试，物理请求最多六次。N 页默认总额度为 3N，可在开始前改动；请求前原子预留，失败和结果未知的已发送请求也计数。额外修复请求先给其它未完成页保留基础识别/首审名额。候选编译每页最多四次，不通过反复重写或异常缩字制造成功。

额度不足时，系统自动结束可完成的阶段，对未完成检查标记问题并保留源内容，不弹出逐页续费或批准关卡。之后可以主动发起新任务。

页面执行与质量分开：

| 结果 | 含义 |
| --- | --- |
| 自动通过 `auto_passed` | 内容、布局和覆盖检查充分，未发现阻塞问题 |
| 带问题完成 `completed_with_issues` | 有不确定转录、受保护旧稿、未完成检查或源图保留；可用产物自动提供 |
| 失败 `failed` | 来源、服务配置或输出生成发生技术失败，原因和已有结果保留 |

内容、布局、覆盖分别显示 `passed/uncertain/unverified/failed`。旧 `ready` 只是旧执行状态，不能当作自动通过。问题列表是解释结果的只读说明，不是人工待办，也不影响其它页面继续。

不确定内容先定位差异并在额度内尝试一轮局部修复。仍无法确定时保留最佳候选及源区域；必要时自动保留整张源页，明确标为未可靠转录。不可读的原文件会记录失败和缺失页，不能悄悄省略后宣称完整。源图保留不计作成功文字化；默认正文不插入额外水印或猜测文字。

点击暂停后停止新阶段和请求预留，已发送请求继续结算，不取消这些请求。状态先为“正在暂停”，结算后为“已暂停”。恢复使用同一 run ID、冻结范围、设置和已完成阶段，不另开队列。服务退出后恢复记录中断状态；无法确定结果的已发送请求计一次，不静默重发。

用量只记录供应商实际提供的输入、输出和总 token。缺失字段为 `null`，不估算为零；已知值累计，无法确认的请求令 `complete=false`。显示“已知用量，可能不完整”时以供应商账单为准。

## 结果、预览与一致导出

任务结束后后台自动生成导出清单，无需打开页面或手动触发才继续。PDF、LaTeX 资源包和 JSON 使用同一页序与已采用修订快照，未采用的后台候选不会作为最终稿导出。问题、处置与源身份进入清单和 JSON。

- `pdf`：完整范围可形成的 PDF，可在界面预览。
- `partial_pdf`：有技术缺失时的部分 PDF，明确标为不完整，并列出缺失页。
- `latex`：编号源码、页映射、清单和所有被引用源区域资源组成的 ZIP；高级完整文档保留自身源码。
- `json`：冻结清单、修订结果、独立评估、导出处置、问题、完整性和 PDF 页映射。

导出元数据 `complete`、`quality`、`error`、`missing_pages` 用于解释结果，不是下载路径。带问题完成与质量降级不冒充全部识别正确。PDF 可读但源码资源缺失时也会报告不完整。运行产物复用候选缓存，不为下载额外执行 OCR 或复审。

改动当前纸型、排版或保存新稿后，旧运行及既有导出清单仍代表原冻结版本；需要新版本时创建“当前已保存稿”清单，或主动启动新任务。当前已保存稿导出不会把旧稿变为自动通过。打印时使用 PDF 自身纸张尺寸。

## 可选高级编辑与旧接口

高级工具保留原图/输出对照、自由 LaTeX、封面书目、原行/公式组布局校准和草稿编译。自由源码可为 LaTeX 片段或完整文档；实际修改后切为 `custom_latex`，旧布局和历史稿保留。完整文档保持自身纸型、字体与分页；模板片段使用项目纸型；原书还原页按源画布映射。

运行中也可保存当前页，前端携带 `expected_content_revision` 和 `expected_layout_revision`；冲突返回 409，需要加载最新修订后再保存。校准始终检查双修订，后台自动采用也检查基准修订。旧校准表单不含源资源处置选项，保存时保留同源页面的图形、源区域/源页资产及保留说明，不会因改动一行自动变成已完整转录。保存不增加模型用量，未保存草稿不参与整书导出。手工编辑不构成识别的必经步骤。

纸型与排版可独立保存，包括 A4、A5、A6、B5、B6 和 6×9 英寸。修改当前设置不改变正在运行的输出快照；与新设置相关的当前布局结论失效，旧清单仍可下载。旧 `process/pause` 路由薄包装新运行，遵循同一额度及旧稿保护，不能绕过替换授权。

旧编辑、校准、单页/整书编译、`export`、`export.tex` 与 digest PDF 缓存接口继续兼容。新流程应使用冻结清单下载；旧直接导出反映调用时当前已保存内容。`export.tex` 的无资源单文档仍为 `.tex`；多个文档或含引用资源时返回 ZIP，包含源码、映射及全部引用资源，保持书目录相对路径，资源缺失或越界返回 422。完整自定义源码不改写。LaTeX 语法及旧布局细节见 [旧 LaTeX 参考](LATEX_LAYOUT.md)，[旧功能参考](REFERENCE.md) 与 [旧模块参考](module-architecture.md) 不再定义新版必经流程。

## 新 API

所有路径均以 `/api/books/{book_id}` 开头，run 和 manifest 必须属于该书；详情及下载使用 UUID，不要求摘要。

| 方法与路径 | 内容 |
| --- | --- |
| POST `/runs` | `RunCreate`：可选 `page_ids` 或永久 `pages`、`expected_arrangement_revision`、`policy.replace_page_ids`、`request_limit` 和 `client_request_id`；返回 Run |
| GET `/runs`、`/runs/{run_id}` | 最新优先的列表及运行详情、阶段、计数、用量、输出清单 ID |
| POST `/runs/{run_id}/pause`、`resume` | 暂停或恢复同一运行，返回 Run |
| GET `/results?offset=0&limit=100` | 当前采用稿的分页页面结果 |
| GET `/issues?offset=0&limit=100` | 分页问题说明 |
| POST `/export-manifests` | `expected_arrangement_revision`、可选 `page_ids` 和 `run_id`；冻结并生成统一产物 |
| GET `/export-manifests/{manifest_id}` | 清单及产物元数据 |
| GET `/export-manifests/{manifest_id}/{pdf\|partial_pdf\|latex\|json}` | 下载固定四种格式，路径限制在该书目录内 |

重复 `client_request_id` 返回原运行，不重复调度；已暂停或完成的原运行不会因重复创建而自动启动。另一个运行处于排队、运行、正在暂停或已暂停时，新运行返回 409。已有运行的导出使用其冻结编排修订，之后改变当前页序不影响旧清单读取和下载。子范围导出不覆盖运行的完整自动产物入口。

## 升级与故障处理

新版首次启动按增量迁移写前备份：正文升级为 `app-before-latex.db`，布局升级为 `app-before-layout.db`，工作流升级为 `app-before-workflow.db`。已有备份不覆盖。迁移保留源文件、旧稿、修订、页序及用量，不调用模型，不把历史 `ready` 转成质量通过。原 Markdown 仅在内部 `pages.legacy_markdown` 保留，不公开到 API。迁移代码未在本轮试跑。

升级或换电脑前停止服务并复制项目及自定义数据目录。数据库及备份可能含明文凭据。没有一键历史恢复界面；需回退时保留当前库，在独立目录恢复与版本相容的备份。旧电脑的虚拟环境、前端依赖和启动器缓存应保留备份后在新机器重建。

任务长时间处理中时查看运行详情和本地日志；重启后可恢复同一中断运行，已发送结果未知的请求不会重发。服务配置错误先修正协议、地址、模型、密钥或 Schema 能力；不要以模型列表或本地配置检查代替真实工作能力。PDF 错误先查看清单的 `error` 和 `missing_pages`，确认编译器及额外宏包。复杂内容自动保留源图是带问题结果，用户可以选择高级编辑或主动新任务，但系统不等待这一步。

启动器目录不匹配、端口占用和依赖安装问题可查 `.cache/launcher/` 日志及 [旧启动说明](LATEX_LAYOUT.md#编译环境)。[历史修复报告](RENDERING_REPAIR_VERIFICATION.md) 与 [历史验收清单](acceptance.md) 不能证明本版的运行效果。
