# 操作说明

## 启动前检查

Windows 双击根目录 `ocr.bat` 打开服务管理菜单，回车启动 / 打开页面，输入 `2` 停止、`3` 重启、`4` 刷新状态、`0` 退出窗口。关闭窗口后服务继续运行。也可用 `ocr.bat Start -NoBrowser`、`ocr.bat Stop`、`ocr.bat Restart`、`ocr.bat Status` 无交互执行；停止或重启会中断正在识别的任务。

应用分为一个 FastAPI 后端和一个 Vite 前端。后端入口是 `backend.main:app`，依赖文件是 `backend/requirements.txt`，默认把 SQLite、源 PDF、单页 PDF、页面 PNG 和 LaTeX 编译缓存写入 `backend/data/`；设置 `EBOOK_OCR_DATA_DIR` 可以改用其他本地数据目录。前端负责界面、轮询、LaTeX 校对及 PDF 展示，后端生成整书 LaTeX 并调用本机 XeLaTeX。一键启动会先准备依赖，再启动绑定在 `127.0.0.1` 的两个服务；手动启动命令见根目录 README。

启动前仍需准备 Python、Node.js 和 pnpm，启动器不安装这些运行时。`backend/requirements.txt` 指纹变化或必要模块缺失（含 `mistune`）时，启动器仅在项目 `.venv` 安装后端依赖；`frontend/package.json` 与 `pnpm-lock.yaml` 指纹变化或 Vite 缺失时，非交互执行 `pnpm install --frozen-lockfile`。安装成功后保存 `.cache/launcher/backend-dependencies.sha256` 与 `frontend-dependencies.sha256`，下次依赖齐全且指纹未变就复用，不必联网。服务已正常运行时 `Start` 直接打开页面，不进行依赖修改；升级后用 `Restart` 重新准备并启动。

PDF 功能需要 XeLaTeX、`ctexbook`、Fandol 字体及模板宏包。一键启动优先使用非空的 `EBOOK_OCR_XELATEX`；当前进程未设置该变量时读取用户级值。未配置或配置路径失效时先查 PATH，再查 APPDATA、PROGRAMDATA 下现代 `TinyTeX\bin\windows` 与旧版 `bin\win32` 目录。仍未找到编译器时，下载并校验官方 TinyTeX-1 包，安装到可用的 ASCII、无空格默认目录；选定 TeX Live 环境缺少宏包或字体时由 `tlmgr` 补齐，全部存在时不访问网络。所选编译器目录与变量由启动进程传给后端，不修改系统 PATH 或用户级配置。准备失败时显示错误并停止启动，完整行为见 [LaTeX 排版说明](LATEX_LAYOUT.md#编译环境)。

显式编译器配置只接收可执行文件名或路径，不能附带参数；一键启动遇到无效配置时显示警告并继续自动查找，准备成功后将有效路径传给后端；直接启动后端仍会拒绝无效配置。其他发行版若未提供 `tlmgr` 且缺少组件，需要自行通过发行版管理器补齐，完整环境可直接使用。直接启动后端使用相同编译器查找顺序，但不安装 TeX 或宏包；缺少编译器时仍可识别、校对及下载 LaTeX、JSON，PDF 操作会显示依赖错误。

旧版项目在新版后端首次启动时一次性转换 Markdown 正文。写入前备份为数据目录中的 `app-before-latex.db`；原文仅保留在内部 `pages.legacy_markdown` 供恢复，不进入 API。迁移不调用模型，保留人工校对、用量、处理状态与页序。数据库及备份可能含明文 API 密钥，请只作本地备份。初次 LaTeX 编码未安装依赖；此前依赖补全已同步后端、前端和本机 TinyTeX 及模板宏包、字体，该次未启动或重启服务，未执行数据库迁移或实际 PDF 编译，详情见 [LaTeX 排版说明](LATEX_LAYOUT.md#旧数据迁移与实现状态)。本轮一键依赖准备仅做静态阅读、编辑与审查，未执行安装、测试、构建、类型检查、文档编译或服务启动/重启。

首次打开时模型名称和 API 密钥为空是正常状态；应用不预设具体模型。没有可用的 API 密钥时仍可以浏览前端空态和已有本地数据，但页面提取和连接测试需要用户主动配置可用的 OpenAI Responses 或 Google Gemini 原生接口。不要把真实密钥写入 README、示例 JSON、`.env` 已跟踪文件、截图或命令历史。

## 配置 API

在设置页面填写以下内容：

| 字段 | 用途 | 默认值或要求 |
| --- | --- | --- |
| API 协议 | 显式选择请求格式 | 默认 `openai_responses`，可选 Google Gemini 原生（`gemini`）；旧设置沿用 OpenAI |
| API 根地址 | 拼接请求的基础地址 | OpenAI 默认 `https://api.openai.com/v1`；Gemini 官方地址 `https://generativelanguage.googleapis.com/v1beta`；只允许 `http(s)` |
| Responses 接入路径 | 仅 OpenAI 使用的相对路径 | `/responses`；Gemini 不使用 |
| 模型列表路径 | 获取模型时追加到根地址的相对路径 | `/models`；随设置保存，旧设置缺字段使用此默认值 |
| 页面代理模型 | 普通代理判断类型并转录内容页；独立特殊页面子代理读取封面封底书目，两者共用此模型 | 由用户填写 |
| 模型推理程度 | OpenAI 的 `reasoning.effort`，或 Gemini 的思考级别/预算 | 仅手动输入，无预设，默认为空；空值使用服务默认，取值见下文 |
| 输出格式 | 页面结构化转录结果 | 识别请求使用 JSON Schema；正文为 LaTeX 片段，书目及页眉页脚为纯文本 |
| 超时 | 单次请求等待秒数 | 由用户填写，需为合理正数 |
| 处理并发数 | 每个项目的同时处理页数上限 | `processing_concurrency` 默认 10，正整数，无固定上限；多个项目各自限制 |
| 上下文复用（实验性） | 在一组页面内保留普通代理上下文 | 默认关闭；OpenAI 续接响应，Gemini 重发本地完整历史 |
| 每段对话最多页数 | 包含首张在内的组内页数 | `context_reuse_max_pages` 默认 10，整数 1–10 |
| API 密钥 | OpenAI Bearer 或 Gemini `x-goog-api-key` 凭证 | password 输入；保存到本机 SQLite 的独立凭据记录 |

不要把完整 URL 填入路径字段。OpenAI 两个路径各自独立，均可留空，留空时对应请求直连根地址。Gemini 的 `models_path` 表示模型资源集合：通常为 `/models`，留空时根地址自身就是集合；生成请求会追加 `/{短模型名}:generateContent`，不要把单个生成端点作为集合地址。切换协议不会自动联网；界面可替换默认服务地址，但保留自定义地址。

填写协议、根地址、模型列表路径和密钥后，主动点击“获取模型”，再选择或手动填写模型 ID。操作以当前草稿调用本地 `POST /api/settings/models`，无须先保存。OpenAI 以 Bearer GET 读取 `data[].id`；Gemini 以 `x-goog-api-key` GET 读取模型集合，自动将 `nextPageToken` 作为下一页的 `pageToken`，只返回支持 `generateContent` 的完整 `models/...` 名称，手动输入也接受裸模型 ID。获取操作不保存草稿或密钥、不发起推理、不随输入自动执行。空密钥仅在规范化后的根地址和协议均与已保存配置一致、且未选择清除时复用。服务无列表接口或获取失败时仍可手填；列表不证明图像或 JSON Schema 能力，错误不透传上游敏感内容。

保存设置不会联网，改动从下次处理任务生效。保存后可主动使用“测试连接”，以已保存协议发起一次非流式文本推理，可能产生用量，不代表图像识别质量。失败时检查地址与路径是否重复、模型名、网络和密钥。请求不回退 Chat Completions，不自动重定向；Gemini 接入是 API Key 开发者 API，不提供 Vertex OAuth 或多账户系统。识别和连接测试均不发送 OpenAI `max_output_tokens` 或 Gemini `maxOutputTokens`，旧保存值不生效，输出额度遵循服务默认和模型限制。

旧 `classification_model` 字段保留兼容，但不调用独立分类模型。`reasoning_effort` 仅手动输入，无预设，默认为空；已有保存值会继续显示，清空并保存后不发送推理参数，使用服务默认。OpenAI 非空时传递 `reasoning: {"effort": value}`，不限制枚举。Gemini 的 `minimal/low/medium/high` 对应 `thinkingLevel`（Gemini 3），不小于 `-1` 的整数对应 `thinkingBudget`（Gemini 2.5；`-1` 动态、`0` 关闭是否可用取决于模型）。应用不按模型名猜测思考参数，实际支持以模型为准。

每页提供来源信息、图片和指令，不创建 Codex 任务。默认独立上下文；OpenAI 默认 `store:false`，实验性复用发送 `store:true` 并以 `previous_response_id` 续接，服务不支持续接或缺少响应 ID 时报错，不静默降级。Gemini 在每组客户端本地保留完整 `contents`，包括图片及原始模型 `thoughtSignature`，下次请求重新发送；这不是服务端 `cachedContent`。两种协议均组内串行、组间有界并行，组大小包含首张。历史只供排版和符号参考，只输出当前页；历史占用上下文与用量，不保证节省费用。失败后的下一页及新任务从新上下文开始。

普通与特殊页面代理均支持所选协议。OpenAI 使用 base64 PNG `input_image` 和 `text.format` 的 `json_schema`、`strict: true`；Gemini 使用原生 `systemInstruction`、`contents`/`inlineData`、`generationConfig.responseMimeType: application/json` 与 `responseJsonSchema`，不混入 OpenAI 参数。旧 `structured_output` 设置保留兼容，但不影响识别请求。Gemini 用量输入为 `promptTokenCount`，输出为 `candidatesTokenCount + thoughtsTokenCount`（缺失 thoughts 按 0，缺失 candidates 则输出未知），总量为 `totalTokenCount`；缺失用量不估算。

密钥保存到默认 `backend/data/app.db` 的独立 SQLite 凭据记录，本机明文存储，后端启动时加载。同一规范化根地址和协议下，空白或省略密钥保留已有值；有旧密钥时切换地址或协议，必须输入新密钥或明确 `clear_api_key=true`，否则保存返回 `400`。没有旧密钥时可以保存空配置。密钥不进入 `localStorage`、书籍导出或日志。升级持久化密钥功能后需重新输入保存一次旧进程密钥，之后重启无需再填。

## 项目与上传

左侧按项目排列。点击“＋ 新建”，填写“项目名称”后点击“创建项目并添加资料”。在“上传资料”步骤中使用“选择文件”，一次可选择多个 PDF、PNG、JPEG，也可分批添加；同一个项目可以混合这些格式。文件显示 PDF 或图片类型标识，并统一排列，检查清单后点击“确认上传，开始编排”。

PDF 上传只验证文件、读取页数、保存源文件并建立轻量页面记录，不拆页、不渲染整份文件、不调用模型；图片作为单页来源生成 PNG。没有固定的 500 页上限，每个文件限制 100 MB，并保留图片与 PDF 渲染像素限制。EPUB/MOBI 暂不支持。

项目依次经过“上传资料 → 页面编排 → 逐页校对 → 整书预览”。追加文件会重新打开上传与编排确认，原已选顺序、识别结果、缓存和用量保留；需再次完成两道确认才能校对与预览。处理或上传过程中不能重排或删除项目。

## 页面编排

页面编排将 PDF 与图片放在同一文件树中，文件顺序、父子关系和最终页面顺序联动展示。文件只分顶层和一层子文件，子文件不能继续嵌入文件。可以将图片放在 PDF 两页之间，也可以将另一份 PDF 嵌入顶层文件后继续调整页面。来源文件名和从 1 开始的源页码始终保留，界面另用“编排第 N 页”表示阅读位置。

1. 在左侧统一文件树中拖拽、上下移动或指定位置调整同级文件顺序，最终页面草稿立即同步。移动文件时连同子文件整组移动，保留各文件已有选页范围和组内页序。类型仅作标识，不再提供分类排序、一次加入所有文件页面或重新分组操作。
2. 新上传的页面默认全部勾选；追加文件时保留已保存的选择和顺序，只将新页面勾选并加入末尾。页面复选框决定成书范围：取消勾选即可排除该页，只有勾选页会进入下一步。可按源页码选择全部页、单数页、偶数页或自定义范围，再点击“应用范围”；这会替换当前文件自身的勾选范围，保留其他文件和嵌入子文件的选择。例如只需某份 PDF 的单数页，选择“单数页”并点击“应用范围”即可。自定义支持 `3`、`3,4,5`、`3-5,8-12` 等，范围含两端，重复页合并，非法或越界输入需先修正。切换文件、视图或翻页会保留勾选；“本屏”复选框只切换当前屏的页面。“移至末尾”“插入到…”作用于当前视图中的勾选页，“取消当前视图勾选”会将这些页排除。
3. 选中顶层文件，在“文件内选页与排序”中点击“插入文件…”，选择另一文件，放到当前文件末尾或指定页面之前、之后。默认“保持已编入的 N 页”；如果来源文件尚未编入页面，需要明确选择“编入此文件的全部 N 页”，不会自动替你选全。嵌入后左侧缩进显示子文件；若移入的文件已有子文件，它们与该文件一起成为目标文件的同级子文件。文件内视图同时展示父文件与全部子文件页面，并允许在同一级别混排。
4. 在文件内拖拽或上下移动页面，调整当前文件组内的页面顺序，组外页面占据的成书位置保持不变。在最终页序中可拖拽、上下移动，或把单页及批量所选页插到成书第 X 页之前或之后。左侧拖到文件边缘表示同级前后排序，拖到顶层文件中部表示嵌入；子文件可点击“移出”，或拖到“拖到这里，移至顶层末尾”，移回根级末尾。

页面网格每屏显示 12 张缩略图并按需加载；点击原页大图可查看原始大小并前后切页。预览只按需生成最大边 1200 px 的独立图片缓存，不请求模型，也不提前生成全部 OCR 单页文件。确认编排后，识别、逐页校对、整书预览和导出只包含勾选页，并采用最终页序；范围选择中的源页码不等于最终阅读位置。

拖动文件或页面时，卡片轻微抬起，目标位置显示插入线和让位空隙；嵌入目标以底色和边框提示，松手后有平滑落位效果。开启系统的减少动态效果设置后，关闭位移、缩放和渐变过渡，保留静态落点提示。排序、选页和嵌入操作会立即更新屏幕中的本地草稿；只有点击底部“确认编排，进入校对”才保存到项目。

需要修改选择或顺序时，闲置状态下点击“修改页面编排”，上次保存的勾选范围会保留，已取消勾选的页面不会自动恢复。取消勾选仅改变清单，不删除源文件、历史结果、缓存和用量；重新勾选已完成页会恢复其结果。确认编排至少勾选一页，全部取消勾选时不能进入下一步。

## 逐页处理

编排确认后，在逐页校对中点击“识别未完成页”，按最终页序调度清单中的未完成页，同时处理数不超过配置。批量操作只处理未完成页，清单全部完成后隐藏该按钮，不提供整批重新识别。当前校对页可点击“识别本页”，已有结果时显示“重新识别本页”（包括保留旧结果的失败页）；切换当前页后，操作只针对新选中的这一页，请求仅提交该页的永久页面 ID，即 `pages:[number]`。覆盖已有识别、校对结果或未保存修改前需确认；项目正在运行或正在暂停时不能再次启动识别。开启上下文复用时，本次待处理页按编排顺序连续分组，每组最多指定页数，组内串行、不同组并行；失败保留旧结果，下一页重置对话。完成可能乱序，校对和导出仍按编排顺序。只有开始识别时才为所选 PDF 页面补齐 `page-XXXX.pdf` 和对应 PNG；单页 PDF 保留源页尺寸、旋转和裁切，已有 OCR 资产复用。未选页面不会被识别。

普通页面代理先按当前图像的排版角色判断 `page_kind`：`content` 为普通内容页，`front_cover` 包括正面外封面及以全书书名、署名、出版社等为视觉主体且无连续正文的独立书名页、内封、扉页，`back_cover` 为背面外封面。黑白、纯文字、大面积留白或馆藏章不影响封面式书名页的判断，不要求彩色图案或封皮边缘。不按首尾页码、文件名或相邻页推断；章节标题页、版权页、目录及不能确定的页面仍为 `content`。普通代理的严格 JSON Schema 返回 `page_kind`、`page_side`、`header_segments`、`body_latex`、`footer_segments` 五个字段。内容页在本次请求直接完成转录；判断为封面封底时立即停止普通转录，返回类型、`page_side: unknown`、空正文和空页眉页脚。页侧只依据当前页脚判断，规则见 [LaTeX 排版说明](LATEX_LAYOUT.md#左右页与装订版)。

后端收到特殊类型后，自动转入独立的 `SpecialPageAgent`，读取同一张当前页图像；它收到来源信息和分流类型，使用单独提示词，按独立 JSON Schema 只返回 `page_kind` 和 `cover_fields`。特殊子代理沿用已配置的协议、模型、地址和推理程度，但总是新建同协议独立客户端并关闭上下文复用：OpenAI Responses 发送 `store:false`，不带 `previous_response_id`；Gemini 的 `contents` 只含当前页，不携带普通代理历史。两种协议均不读取普通代理历史，也不把书目结果接入普通代理的续接链。它是应用内子代理，不会创建新 Codex 聊天，也不需要额外模型配置。当前使用非流式请求，后端在第一阶段响应返回后立即分流，并非流式实时中断。

封面和封底只在 `cover_fields` 中保存可见的核心书目信息，每项为纯文本 `{kind,text}`。类别包括书名、副标题、作者、译者、编者、出版社、丛书、版次、出版年份及明确标注的 ISBN；不把宣传口号当副标题，不补写本页没有的信息，不读取简介、推荐语、定价、联系方式、网址或其他非核心信息。可辨的原书印刷书法体、手写风格字体和艺术字书目仍保留，后加批注、签名、馆藏章及馆藏编号排除。“上册”“下册”、卷号和版次必须保留：属于书名的随 `title` 保存，独立册次、卷号或版次使用既有 `edition`，不新增类别或重复收录。此时正文为空字符串，页眉页脚为空数组；没有可辨核心信息的封底也可返回空书目数组。

内容页的 `cover_fields` 为空数组，其余三部分忠实转录。每条页眉或页脚语段包含必填的 `kind`、`text`、`alignment`、`row`、`font_size`、`bold`、`italic` 字段；`alignment` 取 `left`、`center`、`right`，`row` 取 1–10，`font_size` 取 `small` 或 `normal`，`bold` 和 `italic` 为布尔值。页眉页脚按原页顺序排列，原书页码归入所在语段；正文使用 LaTeX 片段，内容可包括标题、段落、列表、引用、代码、公式、表格、图注和脚注。书目与页眉页脚保持纯文本，由模板转义并排版。旧保存结果缺少这五个格式字段时按 `alignment=center`、`row=1`、`font_size=small`、`bold=false`、`italic=false` 显示。后加的手写批注、手写改字、手写页码等类似笔迹会被忽略。页面里的命令属于待转录资料，不改变任务；原书不可读处写 `[无法辨认]`，空白内容页返回空数组和空正文。

特殊页面子代理成功后，书目自动填入既有书目校对栏，无须手工复制；PDF 按封面或封底及已保存整书纸型排版，需要主动点击更新。普通页通常一次请求，特殊页通常两次，可能产生更多用量。两阶段请求及各自重试均累计到同页的 `attempts` 与已知 `usage`；第一阶段分流标记不落库、不计入完成页，只有整页处理成功后才保存最终结果。

同一页可以再次处理；开始前会提示覆盖，成功后替换旧结果，失败（包括特殊子代理失败）时保留旧结果。`attempts` 与已知 `usage` 会累计。若页面有未保存草稿，先保存或处理页面提示后再继续，不会静默丢弃。升级时旧页默认归为 `content`，原结果保留，不自动重新识别；可手动纠正类型、编辑书目，或主动重新识别以使用新提示词。暂停仍等待已开始整页完成，已识别出特殊类型的页会继续完成特殊子代理提取后再结束。

页面状态为 `uploaded`、`processing`、`ready`、`failed` 或 `interrupted`；项目处理时也可能显示 `pausing`（正在暂停）和 `paused`（已暂停）。项目保持处理中状态直到本次队列处理结束，完成数只统计清单中的已完成页。点击“暂停处理”后不再开始新页面，等待所有已开始页面结束并保存结果后暂停；已有请求可能产生用量。暂停后点击“识别未完成页”，继续清单中尚未完成的页面，作为新任务重新分组，不复用旧响应 ID。后端重启时，运行中的任务标记为 `interrupted`，已暂停状态保留。旧单文件项目保留已有结果、用量与页面缓存，缺少 OCR 文件时仅为本次处理页面补齐。

## 删除项目

选中项目后点击“删除项目”并确认。处理或上传期间禁用删除；`DELETE /api/books/{book_id}` 对忙碌项目返回 `409`，未知项目返回 `404`，成功返回 `204 No Content`。删除不可撤销，会移除项目及其全部来源文件、页面记录、识别结果、用量和缓存；其他项目、全局设置和 API 密钥不受影响。

## 页面文本与用量

每页 API 结果固定包含 `number`、`source_id`、`source_filename`、`source_page`、`status`、`error`、`page_kind`、`page_side`、`cover_fields`、`text`、`header_segments`、`footer_segments`、`usage` 和 `attempts`。`number` 是项目内永久页面 ID；原文件名和原页码分别由 `source_filename`、`source_page` 表示，阅读顺序以返回的页面数组为准。模型的 `body_latex` 映射为 API 的 `text`，只存正文片段。`page_side` 为 `left|right|unknown`；旧结果默认 `unknown`，不会依据旧页脚或页序补算，主动重新识别后才能获得模型判断。保存校对时 `text` 必填，`page_kind` 和 `cover_fields` 可选，省略可选字段的 `{text}` 请求继续兼容，但正文须为 LaTeX；封面封底必须提交空 `text`，内容页不能带非空书目。正文校对保留页侧，切成封面封底会将其清为 `unknown`；没有手动编辑页侧的字段。保存不会改变用量或尝试次数，仅正在识别的页面不能保存校对，其余页面可在识别期间编辑并保存；待识别页一旦人工保存，本轮将跳过其识别以保留校对结果。

`usage` 的形状是：

```json
{
  "input_tokens": 1234,
  "output_tokens": 567,
  "total_tokens": 1801,
  "complete": true
}
```

只读取供应商响应实际提供的 `input_tokens`、`output_tokens` 和 `total_tokens`。缺失字段保持 `null`，不估算、不伪装为零。自动或手动重试会把各次已知值累加；拒绝、incomplete、缺少正文只要带有 usage 也会计入。超时、断电或其他无法确认的请求会使 `complete` 为 `false`。书籍的 `usage` 是全书已尝试页面的合计，显示为“已知用量，可能不完整”时应按供应商账单为准。
若页面提示输出被截断，检查供应商或模型的输出限制，或降低推理程度。只要供应商已返回 usage，即使结果被截断也会计入。

## 人工校对

逐页检查 LaTeX 正文中的标题、双栏阅读顺序、中文标点、脚注、公式上下标、表格、图表标签和图注，同时检查页眉、页脚及其对齐、行次、字号、粗体和斜体。确认原页无法辨认的内容仍标为 `[无法辨认]`，手写批注未混入结果；不要根据上下文补写跨页句子或图表数值。普通黑色字体不应被随意加粗，强调范围应与原页一致。

正文编辑区只接收 LaTeX 片段，不填导言区。选择文字后可用“居中”“左对齐”“右对齐”“无缩进”“段落分隔”“公式”按钮插入格式；空行分段，行内公式使用 `\(...\)`，独立公式使用 `\[...\]`。标题用带 `*` 的命令保留原文编号，脚注用原标号转录，不自动重新编号。字符转义和可用环境见 [正文语法](LATEX_LAYOUT.md#正文片段与校对)。

页面类型可在校对中纠正。封面、封底使用书目编辑项，可以增删字段、选择类别和修改文本；只保留本页可见的核心信息。切换类型后按对应编辑区校对并保存：内容页使用正文，封面封底使用书目。原页类型尚未纠正的历史结果继续按内容页排版。

## 整书纸张尺寸

在逐页校对工具栏或整书预览中选择纸张尺寸，选中后即保存到当前项目，刷新后保留；新项目与升级前的旧项目默认使用 A4。该设置对整本书生效，单页 PDF、整书 PDF 和 LaTeX 导出使用相同尺寸与页边距。原页图像仍按源文件比例展示。纸张设置独立于页面内容保存，识别期间也能调整，不调用模型，不改变识别结果、处理状态或用量；修改后需主动更新 PDF。

| 纸张 | 宽 × 高（毫米） |
| --- | --- |
| A4 | 210 × 297 |
| A5 | 148 × 210 |
| A6 | 105 × 148 |
| B5（ISO） | 176 × 250 |
| B6（ISO） | 125 × 176 |
| 6 × 9 英寸 | 152.4 × 228.6 |

模型识别出的封面、封底自动使用特殊排版；人工纠正页面类型后也会应用对应版式。封面按标题、署名和出版信息分层，封底书目靠底，字号与留白随纸型调整；版式提示位于纸外，不加入书内文字。符合封面式书名页条件的内封、扉页使用封面排版；内容页继续保留结构化页眉、正文和页脚，章节标题页、版权页、目录仍属于内容页。纸张较小时正文会重新换行，长内容可延伸到多张打印纸。

整书预览的“整书排版”可选宋体、黑体或楷体，调整字号、行距倍率、首行缩进（汉字）、段距（pt）和页边距（mm），点击“保存排版”后应用到整书及本页 PDF。字号和页边距留空使用纸型默认值；其他默认值为行距 1.6、缩进 2 汉字、段距 0。排版草稿未保存时，先保存或恢复已保存设置，再生成整书 PDF 或下载 LaTeX；本页 PDF 使用当前已保存排版。

## 预览与导出

整书预览可选择居中版式或打印版。默认居中；打印版根据已识别的源页侧别安排镜像装订边，未知页侧、无非空页脚和封面封底仍居中，长正文续页沿用源页侧别。具体规则见 [左右页与装订版](LATEX_LAYOUT.md#左右页与装订版)。装订选项不修改识别数据。

完成上传和编排确认后，整书预览及所有导出只包含确认时勾选的页面，按编排顺序显示，并保留来源文件和源页码；未勾选的页面不出现在导出中，历史结果仍保存在本机。

纸张尺寸及整书排版保存在后端项目记录中，不在浏览器 `localStorage` 保存。单页 PDF、整书 PDF 和 LaTeX 导出共用后端模板：封面与封底分别使用专用书目版式；内容页按模型输出的页眉页脚位置和字样排版。`alignment` 的左、中、右均相对于所选纸张的可排印宽度，只有右侧页码时也保持靠右，不随现有语段数量重新分配位置。`row` 是对应区域内从上到下的绝对行号，页眉页脚独立编号；第 1 行和第 3 行之间保留第 2 行的空白。每条语段分别保留字号、粗体和斜体。页眉位于纸张顶部、页脚位于底部，正文自然伸展。来源文件和源页码由界面及 JSON 保留，不额外生成书内标题、目录或页码。重排不精确复刻源页像素坐标，也不保证一个源页恰好排成一张纸。

成功和一般信息通知显示 5 秒后自动消失，错误通知保留至手动关闭；通知均可手动关闭，删除和未保存草稿相关的确认对话框仍需用户作答。

点击“更新本页 PDF”，用当前页面草稿与已保存整书排版编译本页，更新预览不会保存草稿。整书点击“生成/更新 PDF”，使用已保存页面及排版编译；编辑正文、保存内容、改变纸型、页序或装订选项后，旧预览会失效，需再次点击更新。编译失败时显示错误信息，不用旧 PDF 冒充最新结果。内容页只编辑正文，封面封底单独编辑书目；页眉页脚可在 PDF 和 JSON 中核对。

整书预览提供以下下载：

- LaTeX：完整 `.tex` 源文件，包含应用模板、已保存正文、结构化书目及页眉页脚，可使用 XeLaTeX 离线编译。
- PDF：下载当前成功生成的整书 PDF；没有最新 PDF 时先点击“生成/更新 PDF”。
- JSON：包含 `book`（含 `paper_size`、`layout` 和 `content_format: latex`）、`files` 和按最终页序排列的 `pages`；`pages[].text` 为 LaTeX 正文片段。[sample-export.json](../examples/sample-export.json) 是历史单文件 Markdown 示例，当前格式以 [接口契约](module-architecture.md) 为准。

打印时打开已生成的 PDF，使用 PDF 自身纸张尺寸，避免打印机缩放覆盖所选纸型。预览和 PDF 下载需要本机 XeLaTeX；LaTeX 与 JSON 下载不调用编译器。当前产品不提供 Markdown 编辑、预览、导出或独立 HTML 下载。

正文按源页分隔，长文本由 LaTeX 自然续页。宽表、复杂跨页表格和跨页段落需要人工校对，图形只保留可辨文字、标签与图注。

## 常见问题

### 重启提示状态属于其他项目目录

`The launcher state belongs to a different project directory` 表示 `.cache/launcher/pids.json` 记录的 `root` 与当前项目目录不一致，复制或搬迁项目时可能遇到。启动器统一以 UTF-8 读取状态，兼容中文路径；重启时会忽略异目录状态中的旧 PID 并清除当前目录的陈旧记录，只处理经进程命令行确认属于当前项目的监听进程，不会因此停止原目录的进程。

在当前项目目录重新执行 `.\ocr.bat Restart`，无需手动按旧 PID 结束进程。若 8000 或 5173 仍被其他程序或原目录服务占用，启动器会提示端口冲突；先在所属程序中停止服务，再重试。

### 一键启动在依赖准备阶段停止

先查看启动窗口的错误及 `.cache/launcher/` 日志。TinyTeX 解压及 TeX 工具日志保存在 `.cache/dependency-downloads/`，工具日志名称为 `latex-<工具>-<GUID>.out.log` / `.err.log`，输出也会显示在启动窗口。缺少 Python、Node.js 或 pnpm 时先安装相应运行时，再重新启动。Python 或前端安装失败时检查网络、包源及锁文件；启动器只在安装成功后记录指纹，修正问题后再次运行 `ocr.bat Start` 即可重试。TinyTeX 下载需要访问官方 GitHub 发布及 TeX Live 包源；哈希不符、解压失败、目标目录已存在或没有合适安装路径时会停止，不覆盖已有安装。已有正常服务不会被 `Start` 改动，更新依赖请用 `Restart`。

### 页面一直处于 `processing`

查看后端终端的非敏感错误信息和页面状态。若进程已重启，运行中任务应变成 `interrupted`；重新处理会跳过成功页面。确认响应符合所选协议、包含文本输出，且模型输出没有超出长度上限。

### 连接测试失败

检查协议、根地址和路径拼接；OpenAI 根地址为完整 Responses 端点时将 Responses 路径留空；Gemini 使用模型资源集合和 `:generateContent`，`models_path` 留空表示根地址就是集合。确认密钥属于当前地址和协议、模型支持所需输入及思考参数，网络和代理允许访问。模型列表成功不等于推理可用，应用不会自动改用 Chat Completions。

### 用量显示不完整

这是供应商响应缺少某些 usage 字段，或某次请求的消耗无法确认。系统会保留已知字段并把 `complete` 设为 `false`；重试会累计已知值。不要用零替换 `null`，也不要把应用统计当成供应商最终账单。

### 公式或表格显示异常

回到原页校对 LaTeX 片段，检查字符转义、数学定界符、括号、环境闭合和表格列数，再点击“更新本页 PDF”。复杂表格和图表只保留页面上能确认的文字、标签和图注；无法确认的内容保持待校对状态，不要根据图形自行补数字。

### PDF 生成失败

先查看界面错误。提示 `EBOOK_OCR_XELATEX` 配置无效时，修正其可执行文件名或路径，或清空该变量以恢复默认查找；启动器可能读取同名用户级值，也需检查并修正或删除该值，再重新启动后端。手动后端提示未找到 XeLaTeX 时，可改用 `ocr.bat Restart` 准备依赖，或自行安装完整发行版；其他安装位置可用 `EBOOK_OCR_XELATEX` 指定。提示缺少宏包或 Fandol 字体时，一键启动会尝试用 TeX Live 的 `tlmgr` 补齐，未提供该工具的发行版需用其管理器自行安装；直接后端不会下载依赖。正文错误先在本页草稿中修正并更新本页 PDF，确认后保存，再生成整书 PDF。编译超时可先检查复杂公式和宽表。此前默认路径与子进程 PATH 兼容性修复只作静态审查，修复后曾重载后端；本轮未运行编译或重启服务。
