# 电子书 OCR 全流程重构：无人值守识别规格

日期：2026-10-04。状态：实现与静态审查已交付，详见[交付说明](WORKFLOW_REDESIGN_DELIVERY.md)。未测试、未运行验证。本版按用户最新要求修订，取代此前“人工处理剩余疑点”和“代理执行测试”的安排。

执行入口：[Goal](WORKFLOW_REDESIGN_GOAL.md)。配套：[编码指南](WORKFLOW_REDESIGN_IMPLEMENTATION.md)、[交付条件](WORKFLOW_REDESIGN_ACCEPTANCE.md)、[进度](WORKFLOW_REDESIGN_PROGRESS.md)。

## 1. 两条最高要求

1. **识别流程不让人工介入。** 用户选择资料、页序和处理设置后，系统自动完成识别、版式恢复、内容复核、有限修复及结果生成。不得要求人逐页检查、确认文字、修改公式、填写坐标或标注参考答案。
2. **执行开发任务的所有代理都不得测试。** 主代理与子代理均不执行测试、构建、类型检查、lint、试编译、运行应用、接口探测、模型试跑、迁移试跑、浏览器验收或基准评测。不计算 SHA256、文件指纹或做其它与本次编码交付无关的验证。保留阅读代码与差异的必要静态审查。

产品在用户实际使用时执行自动内容复核、必要的数据校验及 PDF 编译，属于产品功能，仍要编码实现；开发代理不得以实现这些功能为由亲自运行它们来验证。不得将禁测解释为删除产品正常工作的判断逻辑。

## 2. 目标与范围

重构整个项目的导入、调度、识别、布局、自动质量处理、预览和导出，不针对现有几页做修补。默认交互从“逐页校对”改为“开始任务、查看进度、获取结果”。

保留 Windows 本地单用户定位、FastAPI、SQLite、React、现有模型协议和 XeLaTeX。复用已正确的坐标变换、渲染器、页序、用量记录和旧稿保护，不为重构而重写全部设施。

普通印刷正文、标题、页眉页脚、行内/多行公式、简单表格、双栏和脚注均属于自动处理范围。照片及复杂图形可保留源区域图像。对不可辨或自动修复仍不确定的内容，系统自动形成带问题标记的结果，不转交人工，也不编造“已准确识别”的结论。

不新增微服务、Redis、Celery、通用工作流引擎、插件平台、多代理运行框架或训练系统。开发时的子代理分工不等于产品运行时要创建多名 AI agent。

## 3. 当前需要改变的工作逻辑

| 当前问题 | 修改方向 |
| --- | --- |
| 工作台以“逐页校对”为主入口 | 改成任务总览、自动进度、结果与异常说明 |
| 未知字体、基线或尺寸直接提示人工校准 | 本地几何估计与有边界的字形拟合；未知物理尺寸记录依据，不要求填表 |
| 模型返回后保存为 ready，缺少自动复核闭环 | 将执行完成、质量状态与结果可用性分开 |
| 警告只提示用户对照原图修正 | 系统定位原因、尝试局部修复；不能修复则自动保留和标记 |
| 原图校准样本被用于说明排版成功 | 历史记录仅作背景；本轮不制作样本、参考答案或测试报告 |
| 编译模块从 pipeline 导入图像锁 | 共用图像处理归所属模块，解除反向依赖 |
| 文本连接检查与实际识别请求能力不一致 | 产品实际首次页面请求发现配置问题时集中停止；不新增独立付费预检 |

旧高级编辑与源码保存能力可保留作兼容工具，用户主动使用不受阻碍；任何识别任务都不得依赖这些工具或等待人工完成它们。

## 4. 新用户流程

### 4.1 一次启动

导入 PDF/图片，展示默认页序，允许用户调整处理范围与设置。在“开始处理”面板一次确认本轮范围、模型、输出纸型和调用额度，冻结运行快照。

不再把“确认上传”“确认编排”“逐页确认识别”拆成多个强制关卡。上传本身不触发模型调用；开始处理后，在既定范围与额度内自动推进，不逐页请求许可。

默认保护已有人工稿，排除其自动覆盖；如用户在开始前明确选择替换范围，系统按该范围生成并自动采用成功结果，同时保留旧修订。运行中出现用户新编辑时，后台旧候选不得覆盖。

### 4.2 全自动执行

系统依次完成源页准备、识别、几何恢复、生成、自动复核和必要修复。用户无需一直盯着任务，也无需打开页面使其继续处理。

工作台显示阶段、完成数量、带问题结果数量、失败数量及已知用量。普通内容不确定不会暂停整书，其它页面继续。

### 4.3 自动生成结果

处理结束后展示完整结果、问题摘要及来源定位。问题列表用于解释结果，不是需要人逐项完成的待办。

不存在“待人工校对”“等待确认才能继续”“请手动填写基线”等状态或必经步骤。用户可以查看问题或主动编辑，但不需要这样做才能让任务结束、生成可用输出或处理后续页面。

### 4.4 不确定内容的自动处置

按以下顺序执行，不能反复循环：

1. 使用原图、本地几何和独立上下文内容复核定位差异。
2. 在额度内进行一轮局部模型修复，再自动复核。
3. 无法确定的文字/公式区域保留最佳候选及源图区域。输出明确标明该区域未完成可靠转录；必要时以源区域图像保留可读内容，并在结果清单记录。
4. 不可辨到无法可靠转录的区域保留原图，不猜字、不补公式。图像替代不计作成功文字化。
5. 页面无法生成重排输出时，可自动使用该源页图像生成明确标记的保留页，保持页序和页数；这只是带问题结果，不能标为还原或识别通过。
6. 原文件也不可读取时记录失败及缺失页，明确输出不完整，不能悄悄省略该页后宣称完整成功。

上述源图保留是明确要求的产品行为，只有定位到不确定区域或确实失败时使用；禁止为省事把正常文字页全部变成图片。问题说明放在界面和导出清单，默认不向原书正文插入猜测文字或额外水印。

### 4.5 导出

所有格式采用同一页序及修订快照。提供 PDF、LaTeX/资源包和结构化 JSON，携带自动处理状态及问题清单。

完整自动通过与带问题完成分别标识，但均自动生成可用产物，不设置逐页人工审批。内容保留为图像时，资源必须随源码导出。技术失败导致无法形成完整输出时明确呈现失败，保留已有结果与源文件。

## 5. 固定自动流水线

~~~text
启动任务
→ 准备源页和运行快照
→ 一次全页识别
→ 本地几何与字形拟合
→ 生成并编译候选
→ 自动检查结构、内容和实际输出
→ 若可修复：一轮局部修复并再次复核
→ 自动采用 / 自动保留源区域并标记 / 技术失败
→ 按页序汇总和导出
~~~

### S0 源页准备

使用已有 PyMuPDF/Pillow 读取旋转、有效画布、文本层候选和图像。原文件保持不变。变换可逆，以资产 ID、源版本和修订号关联数据，不新增 SHA256 或文件指纹系统。

文字层仅作为证据，不能因为存在就认为内容正确。轻量墨迹分析提供行带、栏及重复页眉候选；复杂数学以区域或公式组处理，不机械地把每段墨迹切成一行。

### S1 识别

正常扫描页一次全页请求，返回原行、阅读顺序、区域、公式组和不确定项。仅转录，不润色，不按常识补足原文。

模型不负责数据库身份、修订号或真实物理尺寸。字体、字号、基线允许未知，后续由自动阶段处理。识别与审查分开上下文；不强制把整本书历史传给模型。

后加笔迹与印刷内容冲突时自动标记并保留源区域，不能删除可能属于原书的符号。

### S2 自动布局

- 在区域内按顺序匹配原图行带与识别原行；漏行不能通过错配下一行掩盖。
- 正文基线、行距结合字身和行带估计；公式与上下标单独测量。
- 从现有可用宋/黑/楷等字族中进行小范围拟合，按样式组共享字号，不逐行压扁字符。
- 图片没有物理 DPI 时采用项目纸宽及原图比例，记录尺寸依据，不要求人工输入。
- 书级样式摘要只使用相互一致的自动页面，页面证据优先；更新摘要不无休止回写旧页。
- 禁止删字、裁字、异常缩小字号来制造排版成功。

初始候选编译后最多进行两次本地几何调整，模型内容修复后最多再编译一次。每页自动流程最多四次候选编译；这些是产品运行限额，开发代理不得进行试编译。

### S3 自动复核

结合三类信息：源页区域/文字层/墨迹与结构完整性，独立上下文模型对原图和候选的内容比较，以及现有真实输出的缺字/越界/页数/基线诊断。

内容审查要看完整源页，不能只看已经识别出的行，否则无法发现整块遗漏。模型自报置信度不能单独作为成功条件，合法 JSON 或编译成功也不等于内容正确。

未知、截断、缺少覆盖和相互冲突的结果自动进入有限修复或源图保留分支，不进入人工队列。

### S4 局部修复

只修改定位到的行、公式组或区域。提案包含目标、旧值与基准修订，可增加有源图依据的漏块，不接受任意代码或任意 JSON 路径操作。

每页最多一轮模型修复和一次复审。没有改善或出现新问题时保留原候选并走既定自动处置，不反复重写整页。服务配置错误不当作内容错误发起修复。

### S5 自动完成

执行与质量分别记录：

- 自动通过：当前内容、覆盖和版式检查充分，未发现阻塞问题。
- 带问题完成：已完成有限处理，仍有不确定转录或源图保留区域；可用产物自动提供。
- 失败：配置、源文件或输出生成出现无法继续的技术错误，原因明确且结果保留。

没有人工决定状态。带问题完成不能显示为“全部识别正确”。

## 6. 调用、恢复和复杂度约束

正常每页一次识别加一次审查；最多再有一次局部修复和一次复审。所有阶段共享最多两次暂时错误重试，每页物理请求最多六次，失败请求也计入。

N 页任务默认物理请求上限为 3N，启动面板允许用户修改。先保留尚未完成页面的基本识别/审查额度，再分配修复额度；计数在请求前原子预留，不能并发越限。没有额外探测或预检调用。

额度不足时自动结束已能完成的阶段并标记未完成检查，保留源内容，不弹出逐页续费/审批来维持任务。用户之后可主动发起新任务。

只有明确可重试的暂时错误使用重试额度；400、认证、Schema 拒绝等集中报告，停止无效调用。错误结果保留已知用量，未知不能写成零。不能确定是否已消费的请求计一次，重启后不静默重新发送。

用现有 asyncio 和 SQLite 做有界调度。暂停不启动新阶段，已发出请求结算；恢复复用已完成阶段。源文件不可变资产 ID、修订号、运行 ID 和生成器版本用于结果关联与缓存失效，不新增摘要扫描、全书一致性巡检或证据采集框架。

## 7. 交付边界

本轮 Goal 是编码交付与静态审查，不执行准确率测量、留出集盲测、人工标注、性能跑分、UI验收或文件哈希核对。取消此前85%等需实测才能成立的完成门槛。

产品自动化行为必须按本规格实现；实际效果未经运行验证时，交付说明直接写明“未测试、未运行验证”，不能宣称达到实测准确率、耗时或通过率。
