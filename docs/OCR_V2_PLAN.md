# 第二轮 OCR 重构：问题分析与产品、后端设计

日期：2026-10-05。状态：新计划，尚未实施。范围：整个项目、所有后续资料；不针对截图中的两页或任何固定书籍特化。

执行入口：[Goal 指令](OCR_V2_GOAL.md)。配套：[编码与代理分工](OCR_V2_IMPLEMENTATION.md)、[进度](OCR_V2_PROGRESS.md)。

本轮取代 `WORKFLOW_REDESIGN_*` 中的执行方案，保留其历史交付记录。上一轮“静态接受”不能证明实际识别有效；本轮重新审查关键边界，不在旧任务面板上继续堆补丁。

## 1. 目标与不可更改的要求

用户正常使用路径固定为：**选择文件 → 选页 → 识别 → 结果**。选页完成后进入识别页，点击一次“开始识别”，后台自动完成全部处理；用户不需要理解或干预内部阶段。

- 识别全程无人介入：不要求逐页校对、确认疑点、填写坐标、修改公式、手工校准字体或批准每轮修复。
- 前端简洁但不黑箱：让用户知道处理范围、当前在做什么、已有多少结果、是否正在自动恢复、结果是否可用。
- 内容识别、布局恢复和输出生成各有独立结果。布局或 PDF 生成失败不得抹掉已经取得的文字和结构。
- 自动识别仍须努力取得可编辑内容并还原原书。保留原图只是明确标记的有限处置，不能把原图复制包装成 OCR 成功。
- 不改写、补写、润色原文；无法辨认的内容保留来源和不确定状态。数学表达不按常识“纠正”。
- 实验性上下文复用已取消；每次识别、复核、修复及重试均使用独立上下文，只包含当前页及本次职责所需资料，不引入复用开关、复用页数、跨页响应续接或请求历史累积。来源几何和有依据的书级样式统计可继续使用，不属于对话历史。
- 不按页码、文件名、书名、书籍 ID、样本内容或截图特判。通用判断只能依据本页实际内容、来源几何、响应状态和明确规则。
- 延续 Windows 本地单用户、FastAPI、SQLite、React/TypeScript 及现有模型接入。无需微服务、消息中间件或通用工作流框架。
- 所有编码由 `gpt-6.1-sol / xhigh` 子代理完成；主代理只定要求、协调、静态审查和决定接受/退回。
- 所有代理禁止测试和运行验证、禁止 SHA256 等无意义检查；编码子代理禁止 computer use。产品自身自动复核是要实现的功能，不是代理获准试跑。

“一键式”指选页之后一次启动即可自动结束并给出真实结果，不承诺任何资料或服务条件下百分之百准确。外部密钥失效可以提示修改接入设置，但不应转化为人工识别任务。

## 2. 当前问题分析：证据与判断边界

本次依据用户截图及当前源代码阅读，没有执行应用、模型、数据库查询、编译或测试。

### 2.1 截图能直接证明什么

- 导航把“自动任务、上传资料、页面编排、高级编辑、高级排版”放在同一级，无法表达用户必须先选文件、再选页、最后识别的顺序。
- 两页均失败，却出现满格绿色进度条和“已完成 2/2”；“本轮页面已形成终态”是内部状态描述，不能解释实际成果。
- 用户首先看到运行 UUID、模型、页序修订、物理请求数和 tokens，真正的工作阶段、失败位置及可用成果反而不突出。
- 错误是“源页 1/2 尚未取得可生成的原书布局”；这描述了生成层缺少布局，不能直接证明模型完全没有识别出文字。
- 截图记录 2/6 次请求和较大输出 token 用量，只能说明记录到的请求及用量。不能据此断言发生截断、模型不支持图片、没有执行复核，或准确率为零。

### 2.2 代码已经能定位的设计问题

| 问题 | 当前代码证据 | 影响与本轮处理 |

| 核心路径过早依赖排版 | `_process_page()` 先构建 `SourceFidelityLayout`，再布局、编译、复核；缺布局会进入输出失败链 | 内容复核先独立完成；版面恢复/渲染处理自己的问题，不能把排版问题当文字识别失败 |
| 缺布局错误落在生成入口 | `latex_export._fidelity_document()` 在 `page.layout_source is None` 时抛出截图同文错误 | 明确各层所需契约；不让“缺精确布局”的页面走需要精确布局的生成器；保存初始错误及后续输出错误 |
| 原图保留仍绕经重排文档构造 | `compile_service._preserve_source_page_in_directory()` 在写原图 PDF 之前调用 `build_latex_documents()` 和资源复制 | 原图保留直接基于源页几何和资产生成 PDF；不再依赖精确布局、LaTeX 文档构造或字体求解 |
| 解析异常丢失可操作信息 | `_workflow_request()` 用“模型返回的页面结构无效”等泛化文本覆盖具体字段原因 | 保留阶段、错误分类、简短字段路径及处置；主页面显示用户可理解的说明，技术详情保留诊断 |
| 状态统计容易误导 | `WorkflowDashboard.tsx` 用 `counts.completed / total` 绘制统一绿色条，并写“已完成” | 完成处理数与识别结果分开；失败仍可形成终态，但不能使用成功文案/全绿外观 |
| 几何分析被重复执行 | `_prepare()` 取得来源分析；`solve_layout()` 再次调用 `analyze_source()` | 同一来源版本只准备一次，显式传递必要分析，减少重复工作及结果分歧 |

### 2.3 尚不能确认的事实

截图没有第一次模型响应、解析错误链和当时采用修订，不能认定本次两页具体在何处分叉。以上定位的是现有代码中的缺陷与脆弱边界，不是对实际运行调用栈的复现。新实现必须保留这些诊断信息，避免下一次只剩最终“无布局”错误。

## 3. 前端流程：三个操作步骤和一个结果状态

### 3.1 选择文件

- 新项目直接显示上传区域，主按钮“选择文件”，支持多个 PDF/图片及追加资料。
- 本地导入只处理文件、页数、来源元信息与按需缩略图，不调用模型。
- 成功后自动进入选页。部分文件导入失败时保留已成功资料，并明确指出未导入文件；不要让用户误认为全部已导入。
- 不以任务总览作为新项目首页；历史项目按实际状态打开选页、正在运行的识别页或已有结果。

### 3.2 选页

- 缩略图网格为主，按来源文件分组，展示文件内页码；选中页默认保留原顺序。
- 支持全选、取消、范围选择、单页选中/移除、预览放大、调整已选页顺序。大文件按需加载缩略图，不一次渲染全部大图。
- 固定底栏显示“已选择 N / M 页”和唯一主按钮“下一步：识别 N 页”；零页时按钮不可用并说明原因。
- 单份选择状态作为权威，不能同时存在编排页码范围、任务页码范围和另一套选中数组。后端冻结的是有序 `page_id`，显示页码不作为身份。
- 选择草稿与书籍的全部来源页分开，取消勾选不删除源页或识别历史。
- 进入识别页只保存选择，不发送模型请求；返回选页应恢复选择与顺序。

### 3.3 识别：待开始

- 页面只展示资料摘要、已选页数、模型配置摘要和“开始识别”主按钮，支持返回选页。
- 默认目标是忠实原书，优先源尺寸；输出纸型、并发、额度和已有人工稿策略进入折叠设置或全局设置，不再逐次要求填写。
- 沿用已保存的模型配置，不擅自替换模型、供应商或接入协议。配置缺失时显示“设置模型”，只要求必要配置，不要求测试连接。
- 一次点击冻结来源、选择顺序、设置与保护策略并启动。快速重复点击或响应丢失使用同一请求身份，不能创建重复任务。

### 3.4 识别：运行中

首屏只需：阶段说明、处理页数、结果计数、暂停/继续。示例文案为“正在识别文字 · 已处理 8/24 页”“正在自动处理 2 页中的识别疑点”“正在生成结果”。多页并发时显示主要活动和小型分阶段计数，不假装整本书同步停在同一阶段。

- 可展开页面列表，看某页处于排队、识别、自动复核、恢复版面、生成或自动恢复。
- 进度表示已结束处理页数，明确称“已处理”；导出仍进行时显示“页面处理结束，正在生成下载文件”，不得先宣布全部完成。
- 不虚构百分比、准确率或剩余秒数；模型请求等待时显示“模型处理中”及已等待时间。网络轮询断开显示“连接中断，后台任务可能仍在运行”，不改成任务失败。
- 自动恢复要说明“正在重新取得结构化结果”或“正在修复局部识别”，不显示需要人决定的技术步骤。
- 页面重载后由持久任务状态恢复；离开识别页不会暂停后台任务。暂停停止新步骤，已发送请求结算后稳定保存。
- 运行中不能悄悄改变当前任务选页、原文修订和模型设置；后续修改留给下次任务。
- UUID、token、请求预算、原始字段路径、修订号置于“处理详情”，不能占据主视觉。

### 3.5 结果

- 自动进入结果状态，同页呈现预览、结果摘要与下载；无需再去“高级排版”点击编译。
- 分开回答三件事：文字是否识别可用、版面还原程度、文件是否生成。只有原图的页明确写“未可靠文字化，已保留原页”。
- 展示“可编辑识别结果 N 页、含保留区域 M 页、仅原页 K 页、未形成结果 F 页”；这些类别互斥，合计等于本轮所选页数。已保护旧稿另作说明，不能算本轮新识别成果。
- 全部失败时突出“本次未取得可用识别结果”，红色/中性处理条；原页 PDF 若可下载，名称必须是“下载原页保留 PDF”。没有文字结果不能显示“识别成功”。
- 混合结果逐页标记，不把整本 PDF 可打开等同识别成功；源页不可读则明确列出缺失页，不静默省略。
- 下载默认提供同一快照的 PDF、内容 JSON、LaTeX/资源包；某格式失败不应隐藏其他已生成格式及已识别内容。
- 已知可恢复的失败提供“继续处理未完成项”，复用已有内容；外部配置错误显示原因及设置入口；需要新的外部请求时必须在已有任务额度或新的用户重试授权内。
- 主导航只保留“文件 → 选页 → 识别”；结果是识别的完成状态。编辑、源码、布局校准放进“更多/高级工具”，继续兼容旧稿，不承担推进识别的职责。

## 4. 后端：内容先保存，版面按内容派生

固定流程为：

```text
文件导入与选页（不调用模型）
  → 冻结任务 → 准备源页 → 粗版面与阅读顺序分析
  → 整页理解 + 按需局部高清识别 → 保存响应 → 分块解析/保存内容
  → 从源页出发检查覆盖 + 独立核对内容 → 按错误原因有界恢复局部
  → 精确版面恢复 → 生成候选 → 本地版面判断/有界调整
  → 保存逐页结果 → 独立生成各格式 → 汇总
```

局部步骤失败走明确分支，不能统一回到整页重新识别。取消原来的“必须先有完整原书布局并编译成功，才有有效内容”的依赖。

### 4.1 源页准备

只针对所选页准备模型输入；保留不可变原文件、页身份、旋转/裁切映射、像素尺寸及可取得的物理尺寸。预处理不得删除边注、页眉页脚或把复杂公式当噪点抹掉。原图和处理图分开。

原生 PDF 文本和本地墨迹分析作为来源证据，不能将已有错误 OCR 层自动当真值。统一的分析结果供识别裁切、覆盖判断和布局使用，不在每个阶段重复准备。

**粗版面在识别之前，精确排版在内容保存之后。** 前置分析只确定可见区域、分栏、跨栏标题、阅读顺序以及公式/表格的大致边界，不要求字体、精确基线或完整 `PageLayout`。无法确定粗结构时保留整页输入和未知关系，不阻断内容识别，也不把错猜的结构当强约束。

按来源选择输入：原生 PDF 利用可取得的文字、位置与字体作为辅助证据；扫描页以图像为主；混合页面逐区域选用证据。文字层可能有错字、错序或不可见历史 OCR，必须与可见源图对应，不能仅因存在文字层就跳过视觉覆盖复核。优先使用现有 PyMuPDF/Pillow 能力，不为了前置分析新装多个模型或服务。

### 4.1.1 整页理解与局部高清输入

- 清晰普通页保持整页识别路径，不固定拆块或增加一次布局模型调用。
- 本地分析发现小字、密集排版、分栏、复杂公式或表格，或已有响应出现截断/漏区时，可以提前或恢复时采用局部高清图；不必等整页请求失败才处理明显的小字区域。
- 每个局部请求仍独立构造输入，提供本页概览、目标区域和必要周边，不携带上次对话历史。局部图从原始分辨率源资产取得，不能把低清图放大后当作新增视觉信息。
- 按内容边界裁切，公式组、编号、表格表头及必要关联区域应一起保留；禁止机械九宫格或把分子分母分开。多图输入规模受当前服务能力、输入大小及统一 policy 约束，不为每个字符单独请求。
- 裁切坐标有可逆映射；各结果回到同一源页坐标和阅读顺序。重叠区域只有在源位置和内容对应同一处时才去重，不能仅凭文本相同删除原书真实重复内容。
- 粗区域只是观察，不作为“已经全部识别”的证明；后续覆盖复核必须能发现粗分析阶段漏掉的区域。

### 4.2 轻量内容契约

新路径建立 `PageContent`，不要求模型生成 `SourceFidelityLayout`。最小信息为按阅读顺序排列的内容块、块类型、可见文字/公式、粗略源框及具体不确定内容。详细契约见编码指南。

- 程序分配持久块/行 ID、来源和修订；模型输出顺序数组与当前请求需要的局部引用，不要求其维护整页复杂引用图。
- 普通文字使用文字及少量有语义的样式片段；数学使用有界 LaTeX 数学片段；图形引用实际源区域；禁止模型生成完整可执行文档或资源路径。
- 保留原视觉行、段落、分栏和公式编号关系。轻量化不等于把整页压成无结构长字符串。
- 精确基线、物理字体大小和输出画布不是内容必填项。缺少这些仍能保存、展示和导出已经取得的文字。
- 封面、目录、空白、正文、表格采用同一内容框架；页面类型可改变呈现策略，不能禁止转录其他可见文字。
- 正文和页边内容只保存一次，其他视图从内容派生，禁止 `body_latex`、`header_segments` 与 layout 中反复存同一内容作为多个权威。

**按内容类型分配识别职责，但沿用已配置模型和协议。** 普通文字关注字词、标点、视觉行和段落；公式关注上下标、分式、矩阵、公式组与编号；表格关注单元格及行列/合并关系；图形保留实际源区域并单独识别图注；页眉页脚保留为独立角色，不混进正文。各类型只返回自身需要的结构，不要求每块填写所有类型字段，不引入多模型投票平台。

每个内容块记录来源位置、内容修订、识别/复核状态及未解决原因，作为局部恢复的最小单位。页级结果从块结果汇总。不能因为一个块失败就删除其他已取得内容；块状态直接保存在既有内容修订/阶段数据中，不另建通用子任务系统。

### 4.3 响应持久化与分类恢复

收到响应后，在严格解析之前保存有界的响应正文、provider request ID、响应完成状态及用量，关联已预约请求。不要保存密钥、完整请求图像或私密请求头；不将正文复制到前端错误弹窗。

- 有完整 JSON、仅程序派生字段缺失：本地正规化，不能补造文字或坐标。
- 某块内容有效、可选布局信息非法：保存内容并明确布局未知，不丢弃整页。
- JSON 截断、必需内容缺失、正文格式不能恢复：保留原响应，仅在剩余额度允许时发更小职责的恢复请求；禁止正则强补截断文本或伪造闭合后当完整结果。
- 恢复请求只能针对真实源页或可定位区域。缩小 schema、减少重复字段或有依据地裁切，不能用同一失败的大提示词无限重试。
- HTTP 400/鉴权/协议错误：集中停止无效模型请求，页面保存已有内容和明确原因；不偷偷切模型、协议或降低为另一种未授权服务。
- 未知消费请求：不自动重复发送。已持久化正文可重新解析；仅有发送记录、没有正文时保持明确未完成/源页保留结果。

完整响应中若仅个别块非法，应保留可独立解析的有效块，并以源区域或原响应条目关联未完成项；整段 JSON 截断且无法可靠划定条目时，不猜补字符串、不提取零散片段冒充完整内容。两种情况都保留原响应与准确的失败范围。

恢复必须针对原因改变处理条件，按下表执行；这些是产品运行分支，不是要求开发代理执行验证。

| 原因 | 自动处理 | 保留边界 |
| --- | --- | --- |
| 小字/局部细节不足 | 从原始源资产取得高清区域，带本页概览及必要周边重新读取 | 不更改其他已可靠块，不宣称放大能恢复源图不存在的细节 |
| 阅读顺序错误 | 根据源栏关系调整块顺序 | 不重新识别已经可用的文字；关系仍不明则标记未知 |
| 响应截断 | 减少重复输出字段或按完整内容区域拆分请求 | 不重复同一失败的大请求，不拼造缺失正文 |
| JSON/字段结构错误 | 本地正规化程序字段；必要时精简契约重新取得目标结果 | 已有可解析内容保留；不得用任意宽松解析掩盖丢失 |
| 公式或单元格内容疑点 | 局部重新读取后比较，仅修改有源证据的目标 | 原编号、表头和上下文关系一起保留，不按数学常识改原文 |
| 字体、几何或编译错误 | 转交布局/输出阶段 | 不触发文字 OCR 重跑 |
| 鉴权/协议/配置错误 | 停止新的无效模型调用，保留已产生内容 | 不自动切服务，不使用同参数无限重试 |

暂时网络/服务错误可按统一 policy 有界重试；内容或格式失败的恢复不能只是原样再次发送。明显可读而仅结构失败的块，应在剩余额度内优先尝试恢复，不能直接贴原图掩盖程序错误。仅当不可辨、有限恢复无改善、预算不足或输出无法可靠生成时保留必要源区域/原页，记录具体原因。

### 4.4 独立内容复核与局部恢复

内容复核使用完整源页和当前 `PageContent`，独立于识别对话；不等待 PDF。关注漏块、漏行、阅读顺序、错字、标点、公式及编号、表格对应关系，不把字体误差作为文字错误。

复核分清两个职责，可在同一次独立复核请求中完成，不强制每页多加两个请求：

1. **覆盖判断从源页出发。** 遍历实际有内容区域，再查对应结果；检查边注、脚注、跨栏标题、编号和块间空隙，不能只遍历候选已有块。粗分析遗漏的区域允许新建问题，不能因无候选 ID 而忽略。
2. **内容判断针对对应区域。** 比较字形、标点、公式与表格关系；需要局部恢复时，先让模型根据目标原图独立重读，不把待确认旧文字作为标准答案，再由程序将新候选与旧修订比较并复核。

局部重读仍是当前页独立请求，程序可以使用已保存旧值做修订比较，不能恢复会话续接。墨迹只提供可能存在内容的信号，不能自动推导文字或通过状态；两次模型输出一致也不能独自作为正确依据。

独立上下文仍可能使用同一模型，不能称为独立真值或准确率证明。本地来源覆盖判断与模型指出的问题都要保留依据；无充分依据的内容必须保持不确定。

修复是对已定位块的有限替换/补入，绑定旧内容修订，保留不相关正确内容。整块遗漏可凭源框补入；不能因候选里没有目标 ID 而永远无法修复。局部重读需带必要周边，不能裁断跨行公式或表格。

每轮改动保留原候选，内容复核没有改善或新增问题则不采用新候选。无法可靠判断不等待人工，以最佳内容加必要源区域结束，并说明未可靠文字化的范围。

### 4.5 版面恢复

`PageLayout` 引用内容 ID，是 `PageContent` 的派生布局。用源几何、本地分析和粗定位求原行/区域位置、栏关系、样式；不靠用户补坐标，不靠模型精确猜所有基线。

- 沿用源尺寸及长宽比，统一坐标转换；未知 DPI 只作有说明的估计，不能宣称测得真实字号。
- 字体匹配不足影响版面结论，不使已有正确文字作废。维持原换行与公式组，不通过删内容、挤压字形或强缩整页来掩盖溢出。
- 样式归纳只利用本次已可靠取得的来源证据，不依赖人工校准页，不按处理完成先后随机改写旧页。
- 编译及字体错误交给布局/输出修复，不能触发整页 OCR 重跑。
- 局部不具备足够几何证据时保留对应区域原图，已识别内容仍存在 JSON；整页不能可靠重排时才使用原页保留 PDF，不把普通文字页统一转换为图片。

### 4.6 三种明确输出路径

| 路径 | 输入 | 结果与限制 |
| --- | --- | --- |
| 忠实重排 | 已保存内容 + 可用派生布局 | XeLaTeX 生成重排页，按实际内容及版面状态标记 |
| 局部源内容保留 | 可用重排部分 + 源区域资产 | 只覆盖有定位的问题区域，不能双重显示原文字；相关区域明确未可靠文字化 |
| 必要原页保留 | 可读源页及其几何 | 直接由 PyMuPDF/图片生成 PDF，不要求 layout、字体或 LaTeX 文档；保留已取得内容 JSON，整页保留不计 OCR 成功 |

LaTeX 包可以包含源图页的简单派生引用，但此包的生成失败不得阻止原页 PDF。JSON 从内容快照生成，不能等待 PDF 或 LaTeX 成功。各格式分别记录状态，最后统一挂入同一快照的产物目录。

## 5. 执行可靠性与预算

沿用现有 SQLite 任务、修订、请求预约和 CAS；重构字段及函数边界，不建立第二套通用任务平台。

### 5.1 最小状态

- 执行状态：queued / running / pausing / paused / interrupted / finished。`finished` 只表示自动处理结束。
- 阶段：prepare / recognize / review / recover / layout / render / export。
- 结果分别保存：内容状态、布局状态、来源保留方式、各格式生成状态。用户可见总体结论由这些值推导，不靠一次“编译成功”决定。
- 页面初始失败、自动恢复错误、输出错误分开保存，初始错误不可被最后一个错误覆盖。
- 使用现有阶段记录加简短错误列表即可。不要为进度引入事件总线、事件溯源或独立消息库。

### 5.2 整轮硬预算与按需分配

取消“每页固定六次、基础/恢复槽位硬分割”的算法结构。正常清晰页仍通常为一次内容识别加一次独立复核；复杂页可在共享预算内使用有依据的局部请求，不能为了耗尽额度执行无效工作。

初始 policy 默认整轮最多 `6 × N` 个物理模型请求，N 为本轮冻结的所选页数；单页安全上限 12 次，且始终受整轮剩余额度约束。因此单页任务默认整轮仍最多 6 次，12 不是额外授权。暂时错误重试每页共享最多 2 次；局部恢复每页最多 2 轮，同一块每轮最多一个新候选，无改善不重复同一方案。数值集中在一个 policy，启动时冻结，可在高级设置调整，不写进提示词或多个模块。以上是初始资源策略，不是准确率或性能结论。

- 先为未取得基础结果的页面保留可用额度，优先推进这些页；在额度足够时保留其识别及首次复核所需请求。首轮复杂输入额外裁切和后续恢复都只能使用扣除该保留量后的共享余额，不能让某个困难页饿死其余页面。
- 低于基础处理所需额度时，按冻结页序推进可执行项，明确哪些页/阶段因额度未完成，不谎称全部充分复核。
- 其余预算按可定位遗漏/错误及可改善的输入条件分配；同优先级按冻结页序，不依据模型自报置信度或完成先后随意抢占。
- 每次物理请求（包括局部识别、复核、结构恢复和暂时重试）原子预约并计入页级和整轮上限，未知消费同样计数。单次请求带多幅本页图不能据此绕过输入规模限制。
- 内容修复前预约其所需局部请求和修后复核的完整额度，不再让一次结构失败直接挤掉全部复核机会。预算仍不足时保留最佳候选/源区域，不能采用未复核改动并称通过。
- 只取消固定步骤配额，不取消硬上限；不自动增加整轮额度、不无限拆块、不启动跨页会话、不建立复杂的价值评分器。暂停恢复沿用已消费和已预约记录。
- 额度不足、源图不可辨、结构错误和服务故障分别记录，不能统一归为“模型识别失败”。
- 每页候选编译最多 3 次：初次生成加最多两次本地布局调整；不额外做全书反复试排。原页 PDF 直接生成不消费模型额度，不借该分支无限重试 I/O。

默认模型并发 2、渲染并发 1，可在高级设置调整。第一次正常识别兼顾暴露接入错误，但不新增付费探测；识别响应可解析后释放后续工作，不等第一页完成全部布局和导出。该默认值是控制资源与错误扩散的设计选择，不是性能实测结论。

### 5.3 保存、恢复与重复操作

每阶段完成后保存可复用产物及其输入修订。对同一输入的恢复只继续缺失部分：已有内容不重识别，只有 PDF 失败只继续输出，已经发送且结果未知的调用不自动补发。

失败重新处理不是从零“开始新任务”。正常可恢复工作沿用原运行及原预算；已完成运行需要补做、预算耗尽或配置改变时，用户的“重试未完成项”创建关联原运行的补做任务，仅冻结必要页并授予新预算。自动识别过程不等待这个按钮，仍会先形成明确终态；该按钮是用户事后可选操作。

保存人工稿与采用候选保留现有事务/修订保护。默认保护旧人工稿，运行中新保存的稿件不能被旧候选覆盖。任务自身识别内容仍保留，不能因当前稿未采用而删除它。

## 6. 本轮必须完成什么

完整交付包括新主流程、轻量内容契约、独立布局与输出、可定位错误、有界自动恢复、同快照导出、旧数据兼容和代理静态审查。

不能只做：重画任务卡片、把失败颜色改掉、追加更长提示词、提高重试次数、换模型、让用户校准、把所有页贴成图片，或专门让截图的两页通过。

本轮交付按编码与必要静态审查判断，具体 A1—A16 见编码指南。所有执行代理不测试、不运行验证；最终如实施完成须写明“未测试、未运行验证”，不得承诺实际准确率或一次成功率。

识别优化的设计参考：[MinerU2.5](https://arxiv.org/abs/2509.22186) 的全局与局部解析分离、[olmOCR](https://allenai.org/blog/olmocr) 的 PDF 文本/元信息辅助视觉识别。这里只借鉴设计方向，不要求引入其模型、训练或评测流程，也不能将外部效果宣称为本项目效果。
