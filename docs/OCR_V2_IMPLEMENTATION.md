## 1. 执行约束

1. 所有编码、接口接线、迁移、样式、兼容适配、依赖文件修改与返工，均交给 `gpt-6.1-sol`、`xhigh` 子代理。主代理不能代写基础代码。
2. 主代理负责明确要求、冻结契约、文件归属、依赖协调、阅读实际代码和差异；每轮明确接受或退回，退回需给出具体位置、原因和所需修改。
3. 所有代理包括主代理禁止测试和运行验证：不跑测试、构建、类型检查、lint、试编译、服务、应用、实现脚本、接口探测、模型试跑、迁移试跑、性能评测或浏览器验收；不计算 SHA256/文件指纹，不运行无意义检查或反复 `diff --check`。
4. 不新增测试、样本特判、人工标注、评估集、验证脚本或取证框架。现有测试和历史报告保留，但不运行、不扩充，也不能据其宣称新版有效。
5. 子代理禁止 computer use、浏览器或桌面操作，不派下级代理。思考清楚后直接编码，只做实现所需阅读和静态自查。
6. 禁止过度设计与防御性编程。不做猜测性兜底、多层通用抽象、重复转换、重复校验。明确的请求边界、预算、来源与修订保护、状态事务和错误处置属于必要功能，必须集中实现。
7. 不启动新服务，不引入任务中间件、插件化引擎、向量库或通用补丁 DSL；不以另起一个项目逃避旧数据和实际入口的迁移。
8. 产品在真实使用中自动复核、预算判断、编译和错误恢复仍须实现；代理不得借这些功能执行开发试跑。不因禁测而请求用户重新许可测试。

## 2. 最小数据契约与权威关系

复用现有来源、运行、请求与修订表。D1 在首次交付中冻结以下字段意义及 Python/TypeScript 类型，其他代理按它实现。不为了整齐创建七套仓库层或服务层。

| 对象 | 最小内容 | 权威与边界 |
| --- | --- | --- |
| SelectionDraft | book_id、selection_revision、有序 page_ids | 持久化用户选页草稿；不删除源页；只在开始任务时冻结 |
| SourcePage | page_id、source_version、源文件/页、尺寸、图像资产、坐标变换 | 沿用现有来源身份；不要求模型返回数据库 ID 或文件路径 |
| RecognitionResponse | attempt_id、page_id、响应正文资产引用、完成/截断状态、简短解析错误、用量 | 收到后先保存再解析；正文有界、仅本地保存；不含密钥/请求头，不向普通 UI 返回正文 |
| PageContent | content_revision_id、source_version、ordered blocks、issues、来源响应引用 | 新路径唯一内容权威；不依赖排版或 PDF 是否存在 |
| PageLayout | layout_revision_id、content_revision_id、source_version、画布/区域/原行定位、样式依据 | 已保存内容的派生物；不能偷偷修改文字；可暂时缺失 |
| PageOutcome | 内容结论、布局结论、source_disposition、当前内容/布局修订、错误摘要 | 识别质量与产物可用性分离；不能用单个布尔 success 混合表达 |
| OutputSnapshot | selection_revision、page_ids、逐页内容/布局/来源引用、设置版本、各格式状态/资产 | 单一输出快照；JSON、PDF、LaTeX 包状态分别保存 |

### 2.1 内容块

- 块类型使用有限枚举：text、equation、table、figure；header/footer/title/footnote/caption 是角色，避免每种页面单独一套响应类。
- 普通文字块保留原视觉行数组、段落与阅读顺序；单行内容可由文字、行内数学及必要粗体/斜体/字族片段组成，不要求精确物理字号。
- 独立公式保留可见公式行、编号及必要对齐关系；LaTeX 只承载数学片段，不包含完整文档和任意命令执行。
- 表格保留可识别单元格、行列及合并关系；无法可靠文字化的范围标为源区域，不能编造表格数据。
- figure 表达可见图形的源框及独立图注；原图裁切及资源命名由程序执行，模型不提供磁盘路径。
- 粗定位可为空；缺定位影响后续局部还原能力，不使已取得文字无效。未知内容显式标记，不能以空数组代表“识别成功的空白”。
- 模型传输结构只含当前类型所需字段；程序负责持久 ID。程序自有字段通过一次正规化产生，不能要求模型回传所有内部元信息。
- 类型检查保持对内容必需字段严格，布局可选字段单独处理；不通过任意 `dict` 或吞掉全部校验来“提高成功率”。不对截断正文猜测补全。

粗版面与局部输入沿用 `SourceAnalysis` 增加必要区域、阅读顺序、来源依据及裁切映射，不另立布局平台。内容块关联来源区域/映射、当前内容修订、识别/复核状态与未解决原因；个别块失败不回滚其他有效块。区域 ID 不等于“已识别”，覆盖判断允许发现原区域清单以外的内容。

模型请求根据 text/equation/table/figure 职责选择必要字段和简短提示；仍沿用一个已配置的模型/协议适配器，不为每种块新建客户端或服务。页眉页脚是角色，不额外创建重复内容权威。块级状态放入现有修订及阶段数据，不创建可递归派发的子任务框架。

### 2.2 修复与状态

内容修复仅接受目标内容修订、块 ID 或证据框、旧值与新内容，以及来源理由。整块遗漏通过证据框插入；不接受任意文件路径、代码或通用 JSON patch。

内容结论为 `usable / uncertain / unavailable / unverified`；`usable` 表示按本轮自动规则可用，不表示百分之百准确。布局结论为 `faithful / approximate / unavailable / unverified`。来源处置为 `transcribed / regions_preserved / page_preserved`，另有来源不可读错误。格式生成状态为 `pending / generating / available / failed`。

任务执行状态与这些结论分开。旧 auto_passed 等状态在旧接口保留，新默认 UI 使用适配后的新契约，不能让两个字段同时指挥新运行。旧稿缺自动复核依据时为 unverified。

## 3. 函数边界与调用方向

下列是职责边界，不要求为了每个函数新增文件。

| 责任 | 输入 → 输出 | 不得承担 |
| --- | --- | --- |
| prepare_source | SourcePage → prepared image + 粗区域/阅读顺序/原生文字证据/裁切映射的 SourceAnalysis | 精确排版前置、内容通过判定 |
| recognize_content | 本页概览/按需原始高清区域 + 按内容类型精简请求 → provider response | 精确排版、最终采用、静默换协议 |
| persist_and_parse | 响应 → 响应记录 + 有效内容块及明确未完成范围 | 个别块非法就丢整页、猜补截断内容 |
| review_content | 完整源页 + PageContent → 从源页出发的覆盖问题及对应块内容问题 | 仅检查候选已有块、依赖 PDF、要求人工批准 |
| recover_content | 分类原因/源区域 → 独立局部重读 → 程序比较旧修订及有界候选修改 | 把旧错误作为标准答案、整页无条件重写、无限调用 |
| derive_layout | PageContent + SourceAnalysis → PageLayout | 改字、改公式、重复分析同一来源 |
| render_layout | 内容与可用布局 → 页级 PDF/诊断 | 重新 OCR、覆盖内容修订 |
| preserve_source | 原页/区域及几何 → 明确保留产物 | 依赖精确布局、字体或 LaTeX 编译 |
| export_snapshot | 冻结选择及结果引用 → 各格式状态 | 任一格式失败就丢弃其他格式 |

流水线协调以上函数并持久化阶段；存储负责事务和预约；协议适配器负责请求/响应差异；渲染不反向导入 pipeline。移除旧提示词拼接，新旧协议契约使用显式版本入口。

所有模型调用通过同一预算预约入口，恢复和重试不能绕过。响应正文落盘成功后，解析或后续步骤失败不应重新发送；正文落盘失败则保留“收到但未保存”的明确状态，不谎称可自动恢复。

所有识别、复核、修复及重试请求均独立构造上下文。OpenAI 使用 `store:false`，不续接响应；Gemini 只构造当前请求的 `contents`，不累积历史图像、模型响应或思考签名。不得恢复已移除的实验性复用设置或分组会话。持久化响应用于本地解析和诊断，不用作跨页请求历史；来源几何与有依据的书级样式统计可继续复用。

### 3.1 优化过程的共同接口要求

- D3 提供一次来源分析及裁切映射；D2 使用它组织当前页输入，不另做与 D3 竞争的裁切和坐标转换。完整页概览和高清裁切只属于本次请求，不属于历史复用。
- D1 提供块状态及有效内容保存接口，D2 返回有效块/明确失败范围，D4 根据原因继续相应块。完整 JSON 的个别块失败与整段 JSON 截断分开处置，不能靠猜补截断字符串冒充部分恢复。
- D4 负责从源页出发的覆盖判断、原因路由和局部候选比较；D2 负责对应请求，不能在适配器内部偷偷发二次请求。只凭墨迹存在或两次文字一致不能判内容通过。
- D3 合并区域结果时使用源位置和内容对应关系去重；相同文本出现在不同源位置要保留。公式组/编号、表头/单元格的关联不能被裁切破坏。
- D1/D4 共用一个启动时冻结的 policy：整轮默认 6N、单页安全上限 12、每页暂时重试最多 2、每页局部恢复最多 2 轮；细则以产品方案 §5.2 为准。取消旧每页固定六次和基础/恢复硬槽位划分，先保护尚未取得基础结果页面的预算，再原子预约复杂处理及修复/复核所需额度。
- 小字、错序、截断、结构、公式/表格、渲染和服务配置分别走产品方案 §4.3 的处理分支，保存原因；清晰但格式错误的内容有预算时优先恢复，不直接整页贴图。

## 4. API 与前端状态接线

优先扩展现有路由，下面列出新默认流程需要的语义；D1/D7 可复用路径，但不得同时留下两个新权威入口。

| 行为 | 请求/响应要求 |
| --- | --- |
| 导入资料 | 沿用上传 API；返回已导入来源、页数和来源页身份，前端成功后跳转选页 |
| 保存选择 | `PUT /api/books/{id}/selection`：有序 page_ids + expected_selection_revision；返回实际 selection_revision |
| 读取选择/缩略图 | 返回当前草稿；缩略图按来源页身份按需读取，不调用识别 |
| 启动 | 现有 `POST /runs` 增加 selection_revision，冻结有序 page_ids、policy、设置；client_request_id 保持幂等；不再依赖前端另外解释一遍页码字符串 |
| 运行详情 | 当前执行状态、活动阶段数、已处理/总数、互斥结果数、最近必要错误、更新时间、输出状态；普通响应不附全页内容和原始模型正文 |
| 页面结果 | 分页结果摘要，按需获取 PageContent、源图与输出预览；禁止每次轮询重传整本书 |
| 暂停/继续 | 沿用 pause/resume，后端确认后显示暂停；活跃请求结算不当成全新任务 |
| 补做 | 明确目标仅为未完成阶段；原运行可继续则复用，否则建立关联原运行的新任务并冻结新预算，排除已成功且无变化的阶段 |
| 输出 | 同一 OutputSnapshot 的各格式下载入口及状态；可用格式立即可下载，失败格式返回具体原因 |

默认继续使用轻量轮询，不为了展示阶段引入 WebSocket 服务或消息基础设施。轮询只拉摘要；终态后停止高频轮询。选中状态、任务状态及结果状态分别由一个来源驱动，避免 `App` 和多个面板相互覆盖。

选页范围必须与当前来源版本匹配；来源变化时只要求回到选页更新选择，不是人工识别审批。运行期间新选择只影响下一次任务。

## 7. 迁移和兼容要求

- 不删除源文件、旧人工稿、已有修订、历史结果或未提交工作；规划期间和开发代理执行期间均不运行迁移。
- 编码采用增量迁移及现有事务/备份机制，保留版本入口；现有 layout 可派生旧内容视图，但缺依据时必须为未复核，不把历史页变成新 OCR 成功。
- 新运行写入明确 workflow_version。旧活跃任务仍按旧处理器恢复，或明确保持旧版中断状态供后续补做；不得把旧 stage_data 直接解释为新 PageContent。
- 新输出使用新输入版本引用，已有缓存不能冒充新内容/布局结果；复用已有 ID/版本机制，不增加内容哈希或对整个数据目录做指纹扫描。
- 已有自定义 LaTeX/人工稿继续保护，可在高级工具打开；不能为了迁移强制它们重新 OCR，也不在每次读取时改写数据。
- 新任务默认入口切换后，移除其对旧重型响应与旧布局前置条件的依赖；旧接口仅作明确兼容，不维持两套竞争的新默认状态。

## 8. A1—A16 静态交付条件

每项状态只用 pending / implemented / static_accepted。静态接受不等于运行通过。主代理在进度中记录实际代码位置和接受/退回原因；不扩建证据平台。

| 条件 | 必须能从代码确认的结果 |
| --- | --- |
| A1 顺序明确 | 上传成功自动进入选页；选页下一步进入识别；识别开始按钮才发送任务请求；范围不在多处重复输入 |
| A2 一键无人识别 | 启动后所有普通阶段和内容疑点自动推进，无等待人工校对/批准/坐标填写状态 |
| A3 内容独立 | 无精确布局仍能保存 PageContent、显示内容并导出 JSON；布局错误不清除内容，不自动整页重识别 |
| A4 契约一致 | 新提示词、schema、解析器、程序校验互相一致；所有页面类型都能表示完整可见内容；无重复内容权威 |
| A5 响应可恢复 | 已收到正文先保存再严格解析；错误保留阶段/类别/字段；已保存响应可本地重新解析，无盲目重复付费 |
| A6 恢复有界 | 统一预算、每页/整轮上限、共享暂时错误重试、修复及复核预约、配置错误停止、未知消费不重发 |
| A7 输出隔离 | 原页 PDF 不依赖布局生成器或 XeLaTeX；JSON、PDF、LaTeX 包分别落盘和记录状态；已生成格式不会因别的格式失败失效 |
| A8 状态真实 | 已处理不等于成功；全部失败无全绿成功界面；仅原图不算可编辑识别；失败原因不被最终导出错误覆盖 |
| A9 简洁可知 | 默认主屏只有步骤、阶段、页数、结果与必要操作；技术信息/高级工具折叠；刷新或轮询断线不丢后台状态 |
| A10 一致与保护 | 选择、来源、内容、布局和输出快照版本关联明确；旧稿保护/CAS/幂等仍有效；旧运行不被新契约错误解释 |
| A11 通用且可维护 | 无指定页/书/样本特判；无所有普通页贴图伪装成功；不重复准备来源、不新增框架或通用兜底层 |
| A12 完整接线与交付 | 入口实际调用新实现，无空实现/永久 TODO/只增类未接线；全部模块经主代理实际阅读接受，文档注明未测试未运行 |
| A13 粗分析与高清输入 | 识别前确定必要粗区域/阅读顺序，精确排版后置；清晰页不强制拆块，复杂页按需原始高清裁切并保留本页概览/必要周边；映射和重叠合并不损失公式、表格或真实重复内容 |
| A14 分类型与块级恢复 | 类型契约仅含必要字段；有效块独立保存，个别块失败不清空整页；格式错误优先合理恢复；布局失败不重跑内容；原图处置只覆盖确有需要的区域并说明原因 |
| A15 覆盖与证据 | 覆盖从完整源页出发，能够发现候选/粗区域清单外的遗漏；PDF 原生文本是辅助证据；局部重读不把旧答案当真值，墨迹或两次一致不能单独判通过；无跨请求会话复用 |
| A16 预算分配与原因路由 | 取消每页固定调用步骤，统一整轮/单页/轮数硬上限；基础页额度受保护，复杂区域和修复/复核原子预约；截断、小字、结构、错序、渲染及配置原因分别处置，不重复相同失败策略 |

审查优先关注跨模块契约、异常分支和已有内容是否被保留；不能只查文件存在、函数名字或子代理总结后就判接受。主代理如拒绝，应给出“某函数把 layout 缺失升级为全页内容失败，应改为保存内容并标布局未知”等具体要求。
