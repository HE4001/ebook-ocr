# LaTeX 正文与 PDF 排版

当前有三条显式渲染路径：原书还原 `source_fidelity` 使用结构化原行、区域和公式组；现有模板 `legacy_template` 使用既有 LaTeX 片段及项目设置；自定义源码 `custom_latex` 使用人工源码，完整文档保留导言区、宏包、宏、纸型和版面。新书默认还原，旧书增量迁移后保持模板。缺少必要位置的还原页需校准，不能静默套模板。

还原页的 `Page.text` 是布局生成的兼容源码；只查看或原样保存继续由布局控制。实际修改自由源码并保存后切为自定义源码，旧布局保留，但不覆盖该源码。下文“完整文档”指自定义完整文档，布局生成的完整源码仍按还原策略处理。下载为 LaTeX、PDF 和 JSON，实测与限制以 [修复验收报告](RENDERING_REPAIR_VERIFICATION.md) 为准，历史安装记录不是本轮通过记录。

## 使用流程

1. 确认上传、勾选与页序后，识别所需页面。
2. 在正文编辑区校对 LaTeX，或在封面封底书目栏校对纯文本字段。
3. 点击“更新本页 PDF”预览当前页面草稿。该操作使用已保存整书排版，不保存页面修改；确认内容后仍需点击保存校对。
4. 在整书预览保存纸型与排版设置，按需开启“打印装订版”。
5. 点击“生成/更新 PDF”，检查按已保存内容生成的整书 PDF，再下载 LaTeX、PDF 或 JSON。

PDF 只在用户点击更新时编译。草稿、已保存内容、纸型、排版、页序或装订变化后旧预览失效。整书生成与 LaTeX 下载使用已保存内容，页面草稿只参与本页预览；排版草稿需先保存或恢复。还原使用布局与整页映射设置，模板使用项目设置，完整文档使用自身设置。失败信息显示在预览区，不把旧 PDF 当成最新结果。

## 编译环境

PDF 预览与下载需要 XeLaTeX、`ctexbook`、Fandol 字体，以及模板所需宏包。模板使用 `geometry`、`amsmath`、`amssymb`、`mathrsfs`、`longtable`、`array`、`fancyhdr`、`ulem` 和 `hyperref`。`mathrsfs` 提供 `\mathscr`，TeX Live 需具备 `jknapltx` 宏包和 `rsfs` 字体包。可使用包含这些组件的 TeX Live 或 MiKTeX 环境；Windows 一键启动负责准备编译依赖，直接运行后端只查找编译器，不下载发行版或宏包。

一键入口仍是双击 `ocr.bat` 后按回车，或执行 `ocr.bat Start` / `ocr.bat Restart`，无需额外安装菜单。`scripts/start.ps1` 在真实启动服务前调用 `scripts/latex-dependencies.ps1` 的 `Initialize-LatexDependencies`。已有服务正常运行时 `Start` 直接返回，不修改运行中服务的依赖；`Restart` 停止服务后重新准备。

编译器按以下顺序选择：

1. 非空的 `EBOOK_OCR_XELATEX`。启动器在当前进程未设置该变量时读取用户级值；已有当前进程值优先。该变量只接收可执行文件名或路径，不接收附加参数或 shell 命令。一键启动遇到显式配置无效时显示警告并继续自动查找；准备成功后以找到的有效路径替换启动进程中的配置。直接启动后端仍会拒绝无效的显式配置。
2. 未配置或配置无效时，在原有进程 PATH 中查找 `xelatex`。
3. Windows 依次查找 `%APPDATA%\TinyTeX\bin\windows`、`%PROGRAMDATA%\TinyTeX\bin\windows`、`%APPDATA%\TinyTeX\bin\win32`、`%PROGRAMDATA%\TinyTeX\bin\win32` 中的 `xelatex.exe`，未提供相应环境变量时跳过该根目录。

一键启动未找到编译器时，先查配置路径及默认目录中的 `tlmgr.bat`，重装 XeTeX、LaTeX 基础程序、PDF 驱动和路径查询工具，并执行 XeTeX 安装后配置。无法修复时，从官方 GitHub 最新发布获取 Windows TinyTeX-1 包，按官方资产文件名缓存到 `.cache/dependency-downloads/` 并校验发布哈希，使用隐藏进程解压到唯一缓存目录后复制安装，保留下载与解压缓存。安装目标优先 `%APPDATA%\TinyTeX`，必要时使用 `%PROGRAMDATA%\TinyTeX`；目标完整路径必须为 ASCII 且无空格。已有但缺失编译器的目标在新包解压成功后移至同级 `TinyTeX.backup-<唯一编号>`，保留原文件，再安装新副本。没有合适路径、网络失败、哈希不符或解压失败时停止启动并显示错误。

选定编译器后，启动器检查 XeTeX 和 `xdvipdfmx` 程序，并用同目录的 `kpsewhich.exe` 查询模板宏包、Fandol 字体与 XeLaTeX 格式文件；缺少查询工具时自动补装。宏包、字体或程序缺少时使用所选 TeX Live 的 `tlmgr` 针对性安装或重装；管理器明确要求先更新自身时才执行 `tlmgr update --self`。格式文件 `xelatex.fmt` 缺失时补齐 `fmtutil-sys` 并通过 `--byfmt xelatex` 重建。

最后每次准备都会编译脚本内固定的 `latex-dependency-probe.tex`，覆盖宋体、黑体、楷体、仿宋、数学公式、表格、页眉和链接，确认能输出非空 PDF。发现间接缺失的 LaTeX 文件时，通过 `tlmgr search --global --file` 查询所属包并安装，最多补全 20 轮；同一文件补装后仍缺失或出现其他编译错误时停止并保留诊断日志。测试页和 PDF 保存在 `.cache/dependency-downloads/latex-check-*`，不读取或编译用户书籍。完整环境不会访问网络。其他发行版若未提供 `tlmgr` 且组件缺失，需通过其管理器补齐；完整环境可直接使用。工具调用有超时限制，依赖检查或试编译失败时不会启动后端。本流程补齐项目所需组件及其传递依赖，不安装 TeX Live 的所有无关宏包。

选定编译器目录会加入启动进程 PATH，`EBOOK_OCR_XELATEX` 设为所选绝对路径，后端继承它们；不修改系统 PATH 或用户级配置。配置有误时，修正或清除相应进程及用户级变量后重新启动后端，使用启动器时可用 `ocr.bat Restart`。

通过 `uvicorn` 等手动入口启动后端后，编译 API 仍按显式配置、PATH、Windows 常规 TinyTeX 目录查找编译器，其他平台只使用显式配置与 PATH。后端只在编译子进程 PATH 中加入选定编译器的绝对父目录，供同目录 `xdvipdfmx` 等工具使用；不安装任何 TeX 依赖。缺少编译器不阻止手动后端进行 OCR、校对、LaTeX 或 JSON 导出，PDF 操作会显示依赖错误。

历史默认路径与子进程 PATH 修复及一键依赖准备阶段的静态记录，不作为当前渲染验收结论；当前实际编译、测试与隔离 UI 证据见[修复验收报告](RENDERING_REPAIR_VERIFICATION.md)。

后端为正文片段和书目生成 `ctexbook` + Fandol 模板，完整文档直接使用自身源码。源文件采用 UTF-8，可在具备对应文档类、宏包、字体和资源的环境中离线编译。编译调用不经过 shell，使用 `-no-shell-escape`，Windows 进程隐藏；每次编译进程上限为 120 秒。应用不再限制 LaTeX 命令和环境词表；实际语法、缺包、字体及资源错误由 XeLaTeX 报告，不自动修复源码。编译接口不会按任意源码自动安装额外宏包，也没有新增资源上传功能；合法 LaTeX 仍可能需要当前环境没有的依赖，或依赖其他 TeX 引擎。

## 正文片段与校对

以下片段语法用于现有模板或自定义源码；原书还原通过布局校准编辑原行和公式组，不把生成的完整文档误作自定义文档。自由源码编辑区可填写片段或以 `\documentclass` 开头的完整文档；实际修改并保存后由自定义源码控制。片段的字体、纸张和模板由应用管理，完整自定义文档由自身源码管理。编辑区提供对齐、强调、分段及公式按钮，选择相应范围后可插入对应语法。

| 内容 | 写法 |
| --- | --- |
| 原页文字行 | 左对齐原行使用 `\noindent\makebox[\linewidth][l]{原行}`，居中或右对齐分别改为 `[c]` 或 `[r]`；原视觉行之间用 `\\`，真正原段落边界才用 `\par` 或空行，不合并印刷折行 |
| 原文标题 | 按标题所在原行保留文字、编号、对齐及可辨样式，不为标题新增或移动行 |
| 对齐 | 普通文字行使用上述行盒子的 `l`、`c`、`r`；人工校对已有的 `center`、`flushleft`、`flushright` 环境继续保留 |
| 局部字族 | `{\songti 文字}`、`{\heiti 文字}`、`{\kaishu 文字}`；只在可辨的原字族范围内使用 |
| 不缩进 | 段落前使用 `\noindent` |
| 强调 | `\textbf{文字}`、`\textit{文字}`、`\underline{文字}`，只保留原页实际强调 |
| 文字与公式同时加粗 | `{\bfseries\boldmath 文字与完整公式区域}`，从文字模式选择包含完整公式定界符或环境的范围，两条声明必须位于数学模式外，范围在原文强调结束处闭合 |
| 公式内部与上下标加粗 | 在数学模式内选择符号或局部表达式，使用 `\boldsymbol{...}`；不包含公式定界符，粗正体字母才用 `\mathbf{A}`，不将整式改为 `\mathbf` |
| 行内公式 | `\(x^2 + y^2\)` |
| 独立公式 | `\[...\]` 或 `equation*` 环境独立放在原有位置；保留原有公式行及可见编号，编号标签规则见下文 |
| 公式与同句文字 | 保留题干、行内或独立公式、续文和标签所在原行及先后顺序，不因同属一句而合并、移动或新增行 |
| 引用与列表 | 保留原行中的引文和印刷编号，不根据题号新增列表或嵌套；人工校对已有的列表环境继续保留 |
| 表格 | 简表用 `tabular`，长表用 `longtable`；列用 `l`、`c`、`r`，单元格以 `&` 分隔、行末 `\\` |
| 代码 | 行内 `\texttt{转义后的代码}`，原样多行使用 `verbatim` |
| 脚注 | 正文标号用 `\textsuperscript{原标号}`，注释文字按原标号留在该源页正文末尾 |

印刷脚注不使用自动编号的 `\footnote`，不猜测归属或重新挂接。图注、表注保留可见文字和标号，不生成原书没有的标题、编号、图片或目录。节号可写为 `\S`；数学模式支持 `\leqslant`、`\geqslant` 与 `\mathscr{R}` 等花体字母，按原页可见字形选择。数学表达式使用 LaTeX 数学模式；公式中不可读的局部写 `\text{[无法辨认]}`。正文不可读的局部写 `[无法辨认]`，后加手写批注不转录。

普通文字中的特殊字符需要转义：`#`、`$`、`%`、`&`、`_`、`{`、`}` 分别写成 `\#`、`\$`、`\%`、`\&`、`\_`、`\{`、`\}`；字面反斜杠用 `\textbackslash{}`，波浪号用 `\textasciitilde{}`，脱字符用 `\textasciicircum{}`。数学模式与 `verbatim` 遵守各自语法。不要把 Markdown 标题、表格或美元公式定界符当作新正文语法。

例如，原页确有以下标题、同一段的两行正文、独立公式和脚注时，可校对为以下内容。示例中的标题和脚注各自属于真实独立段落，正文两原行之间只使用 `\\`：

```latex
\noindent\makebox[\linewidth][c]{一、原文标题}\par
\noindent\makebox[\linewidth][l]{这是正文第一原行，包含行内公式 \(E=mc^2\)。}\\
\noindent\makebox[\linewidth][l]{这是同段第二原行，保留原脚注标号\textsuperscript{1}。}
\[
  \frac{a+b}{c}
\]
\par
\noindent\makebox[\linewidth][l]{\textsuperscript{1} 原页脚注文字。}
```

识别约定见 [backend/prompts.py](../backend/prompts.py)。模板已经加载常用公式与表格宏包；完整文档可自行加载宏包、定义命令和设置排版。宽表、复杂合并单元格、图形和跨页内容仍需对照原页校对；识别不虚构原书没有的图片或资源。

## LaTeX 语法与完整文档

源码遵循 XeLaTeX 以及所用文档类、宏包的语法，应用没有命令或环境白名单。自定义命令、导言区、宏包和完整文档均可保存；编辑区不会把 Markdown 转成 LaTeX。书目和页眉页脚仍是纯文本，不填 LaTeX。支持完整语法不改变识别要求：按原行、原顺序和可辨样式转录，不为适配纸型移动、拆合原行。

正文片段会放入项目的 `ctexbook` 模板，继承项目字体、字号、纸型、结构化页眉页脚和装订设置。需要加载额外宏包或自行决定文档类时，使用完整文档：

```latex
\documentclass{ctexbook}
\usepackage{amsmath,amssymb}
\newcommand{\R}{\mathbb{R}}
\begin{document}
\noindent\makebox[\linewidth][l]{原页的一行文字，含行内公式 \(x\in\R\)。}
\end{document}
```

完整文档按源码开头的显式 `\documentclass` 识别，可在它之前保留空白、`%` 注释，以及 `\RequirePackage`、`\PassOptionsToPackage` 或 `\PassOptionsToClass`。这是片段与完整文档的格式探测，不是语法白名单；宏定义通常放在文档类之后。普通文字或 `verbatim` 中出现 `\documentclass` 不会使片段变成完整文档。

完整文档不再套项目模板，自己的文档类、宏包、宏、纸型、字体、页眉页脚和版式保持原样，项目排版与装订选项不作用于它。其结构化页眉页脚仍保存在 JSON 中，但不会再次渲染到完整文档上。源码中依赖的宏包、字体或外部文件必须在实际编译环境中可用；当前接口只保存源码，没有自动安装任意依赖或上传额外资源的步骤。

常用写法仍按实际 LaTeX 语法使用：样式组和环境需闭合；行内数学用 `\(...\)`，独立数学用 `\[...\]` 或合适的数学环境；表格用 `&` 分列、`\\` 分行。`\tag` / `\tag*` 放在支持标签的顶层显示数学中，不能放进行内数学或 `aligned`、`matrix` 等内部环境；`\tag{1}` 添加编号括号，`\tag*{(1)}` 原样保留。`\verb` 不能放进 `\makebox`、`\textbf` 等命令参数，原行盒里的代码使用 `\texttt{转义后的文字}`。识别仍保留原书编号而不新增自动编号，原标题按所在原行表达；这些是转录要求，不是源码命令白名单。

## 加粗、斜体与字体变化

页面代理在首次识别中逐行辨认字族、字重和倾斜，保留整段、局部词句、条件及数学符号的可见样式；正文、空白页、封面和封底正常识别均只发起一次请求。判断字重时与附近同字号、同字族的字形比较，强调范围精确到可见字符，跨原有折行继续保留，到下一段重新辨认。标题、定义或例题名称的语义，字号和扫描深浅都不能直接作为加粗依据；页眉页脚的 `bold`、`italic` 也按实际可辨字形记录。

纯文字用 `\textbf{原文}`、`\textit{原文}`；既粗且斜用 `\textbf{\textit{原文}}`，避免无界的 `\bfseries`、`\itshape`。`\textbf` 只改变文字字重，不能自动使其中的数学符号变粗。原页整段文字与公式同时加黑时，识别和人工校对使用标准有界组 `{\bfseries\boldmath 原文与完整公式}`；`\bfseries` 和 `\boldmath` 都必须在数学模式外，花括号在实际强调范围结束处闭合，不沿用到后续正文。编辑器的“文字与公式加粗”仅用于从文字模式选择、包含完整公式定界符或环境的范围；例如选中 `原文 \(x+y\)` 后使用，不能只选已经处于公式中的 `x+y` 或下标内容。按钮只插入分组，不判断当前模式，不额外插入段落命令。

已在公式内部或上下标中时，选择需加粗的数学内容，使用“公式内加粗”插入 `\boldsymbol{...}`，不要选中 `\(...\)`、`\[...\]` 或数学环境的边界。粗正体字母使用 `\mathbf{A}`，不把整个表达式改成 `\mathbf`。字重修改只包住原页确有强调的范围，不改变原行、上下标范围或括号位置。例如错误源码 `E_{\bfseries\boldmath 2)}` 既把文字模式命令放入下标，也把右括号收入下标组，需要对照原图分别校正；本次按钮及提示更新不会自动修复旧数据或已有人工源码。

原文局部楷体或黑体字族使用 `{\kaishu 原文}`、`{\heiti 原文}` 保留；黑体字族不等于粗体字重，原页两者确实同时存在时可写为 `{\heiti\textbf{原文}}`，不能一律给黑体追加粗体。普通黑色文字也不是加粗依据。楷体本身不是斜体，真正的字符倾斜才使用 `\textit`。数学变量的通常斜体由数学模式产生；公式内部可辨粗正体字母用 `\mathbf{A}`，粗斜变量或希腊符号用 `\boldsymbol{x}`、`\boldsymbol{\alpha}`，不在数学模式内部使用文字与公式加粗分组。当前 `mathrsfs` 的花体和 AMS 双线字体没有真实粗体，`\boldmath` 或 `\boldsymbol` 不会让 `\mathscr`、`\mathbb` 自动变粗；原页确有局部加黑时可用 `\pmb{\mathscr{A}}`、`\pmb{\mathbb{R}}` 叠印近似。`\pmb` 仅用于局部符号，不包装整条复杂公式，显示效果仍需人工校对；部分大型数学符号也没有对应粗体字形。

旧页不会自动补写字族、粗体或斜体。原页有可辨样式而正文没有对应命令，属于识别遗漏，需要重新识别或对照原页人工编辑；模板页已有中文强调命令或页眉页脚的 `bold`/`italic` 为 `true`，但 PDF 未显示对应字形时，更新 PDF 可使用现有字体映射。旧正文若用 `\textbf` 包住文字与公式，仍需按原图修改为适当的有界分组或数学粗体命令。人工校对后保存，再更新 PDF。

模板已有宋体、黑体真实粗体映射，楷体没有粗体变体时采用适度合成粗体。模板中的中文斜体保留所选字体并作倾斜，粗斜体同时使用对应粗体和倾斜，不用楷体替代真正的倾斜。完整文档不继承这些映射，需在自身导言区声明所需中文字族及真实粗体或合成粗体、倾斜配置；不要依赖文档类默认用楷体代替真实倾斜，只按原页可辨字形配置。字体映射只改善已有样式的渲染，不推测原文未记录的格式。

完整源码支持阶段曾仅作静态编码与审查。当前主代理已实际编译兼容样本并核对输出；其证据和未覆盖范围见[修复验收报告](RENDERING_REPAIR_VERIFICATION.md)，不能据此证明真实上游识别精度。

## 原页行顺序与公式位置

新版响应 v2 在一次请求中返回原行及独立 `layout` 观察；程序补充来源指纹、物理尺寸、旋转与裁切变换、修订号。坐标为规范原图左上原点的 0—1 归一值，未知位置保持 `null`。每行保留内容、阅读顺序、区域、基线和样式，页眉页脚也是相应原行，避免再次叠加。

还原公式行填写数学体，不带外层 `\[...\]`、`equation` 或 `aligned` 环境。单个顶层 `&` 表示公式组共同锚点；矩阵内部的 `&` 保留其自身含义。公式组保存有序原行 ID、锚点及原编号；编号归属一条原行，`anchor_x` 是编号右缘。正文行的行内公式继续用 `\(...\)`。局部粗体和原印刷下划线保留，后加笔迹、手画下划线不写入正文。

生成器按绝对基线放置自然宽高的文字和数学，按完整源页画布统一缩放，既不裁剪，也不逐行缩小或删除内容凑页。每源页独立编译后按编排合并，并记录实际输出范围。`compiled.ebook-metrics.csv` 的 measurement-v2 记录自然宽度、高度、深度和数学锚点前段宽度；后者通过整式与后段的实际宽度差计算，包含接缝数学间距。

旧模板和自由源码继续支持上述片段语法，包括旧固定行盒；它们不因此获得原图几何。模板可以自然续页，诊断显示实际范围，覆盖不完整不得通过。旧页可显式校准补原行与位置，或由用户主动识别；程序不自动调用模型或重写旧稿。

## 整书排版设置

纸型保存在 `Book.paper_size`，其他设置在 `Book.layout`，本页、整书与源码导出一致使用当前策略设置。还原原行由布局控制，画布选择原页尺寸或项目纸型统一映射；模板使用项目字体与间距，完整文档使用自身设置。选择纸型即保存，排版表单点击“保存排版”后生效，不调用模型或改变内容、用量、页序。

| 字段 | 默认值 | 允许值 / 单位 |
| --- | --- | --- |
| `source_fidelity_paper` | `project` | `project` 整页等比放入项目纸型；`source` 原页画布尺寸 |
| `font_family` | `songti`（宋体） | `songti`、`heiti`（黑体）、`kaiti`（楷体） |
| `font_size_pt` | `null`，随纸型 | 6–48 pt；界面留空为 `null` |
| `line_height` | 1.6 | 1–3，基础基线距离为字号 × 此倍率 |
| `paragraph_indent` | 2 | 0–8 个汉字宽度 |
| `paragraph_spacing_pt` | 0 | 0–48 pt |
| `margin_mm` | `null`，随纸型 | 2–50 mm；界面留空为 `null` |

界面中的 pt 对应 LaTeX 的 bp（1/72 英寸）。模板以字号乘以行距倍率设置正文基础基线距离，不再叠乘 `ctex` 默认行距；标题、公式等特殊内容仍有各自排版间距。首行缩进按当前中文字符宽度计算。显式字号和边距在切换纸型后保留，只有留空的设置跟随纸型默认值。

| 纸型 | `paper_size` | 宽 × 高（mm） | 默认字号（pt） | 默认边距（mm） |
| --- | --- | --- | --- | --- |
| A4 | `a4` | 210 × 297 | 12 | 18 |
| A5 | `a5` | 148 × 210 | 11 | 14 |
| A6 | `a6` | 105 × 148 | 10.5 | 10 |
| B5（ISO） | `b5` | 176 × 250 | 11.5 | 16 |
| B6（ISO） | `b6` | 125 × 176 | 11 | 12 |
| 6 × 9 英寸 | `trade_6x9` | 152.4 × 228.6 | 11 | 14 |

封面封底书目按 `cover_fields` 数组的原顺序输出，字段内的原有断行逐行保留，不按类别重排或合并行；继续使用现有的书目字号角色、居中模板和封底靠底位置。内容页的页眉页脚保留整页左、中、右锚点、绝对行号和字形。缺失行保持空白，原书页码保持原文，不添加输出页码。还原每源页生成一张画布；模板长内容和完整自定义文档可自然续页，模板异常续页会诊断。纸型改变不要求拆分原行。

## 左右页与装订版

普通内容页只根据当前原图的非空页脚判断 `page_side`。有原书页码时，以整组页码相对整页中轴的位置为优先依据；没有实质页码时，才看其他页脚是否一致在同一侧。居中、冲突、无非空页脚或证据不明确时为 `unknown`。不能从页码奇偶、文件名、源页号、编排顺序、页眉或相邻页推断，封面封底始终为 `unknown`。完整识别规则见 [左右页与打印版](PRINT_LAYOUT.md)。

项目纸型下的还原正文页按已知页侧移动整页留白，原页尺寸下不另加装订边距。模板/自定义片段须有非空页脚且页侧已知才应用；未知页侧及封面封底对称，完整文档由自身源码控制。左页右侧、右页左侧是内侧，取基础边距1.2倍，外侧0.8倍，两侧总宽度不变。

LaTeX `geometry` 按源页侧别固定移边，长文本续页沿用该源页的边距，不按输出物理页码奇偶切换，不插入凑左右面的空白页，不强制源页落到某个物理左页或右页。装订选项是本次输出选择，不写入 `Book.layout` 或 JSON，也不改变正文、页侧或用量。打印生成的 PDF 时使用其自身纸张尺寸。

## 导出、缓存与接口

JSON 保持 `{book,files,pages}` 结构，`book` 携带纸型、排版及 `content_format: latex`，`pages[].text` 可为 LaTeX 正文片段或完整文档，来源和结构化书目、页眉页脚保留。LaTeX 导出单份源码为 `.tex`，多份源码为 ZIP；PDF 下载只在当前整书成功生成后可用。

| 方法与路径 | 用途 |
| --- | --- |
| `PUT /api/books/{id}/layout` | 提交可选 `paper_size`、`layout`、`render_strategy`，至少一项；返回 `Book` |
| `GET /api/books/{id}/export` | 下载结构化 JSON |
| `GET /api/books/{id}/export.tex?print_version=false` | 下载已保存源码；单份为 `.tex`，多份为含各 `.tex` 的 ZIP，不调用编译器 |
| `POST /api/books/{id}/compile?print_version=false` | 编译已保存整书，返回PDF链接、兼容warnings及结构化诊断、页映射、质量状态和版本 |
| `POST /api/books/{id}/pages/{number}/compile?print_version=false` | 以 `PageUpdate` 请求体预览本页草稿，返回同样结构，不保存页面 |
| `GET /api/books/{id}/compiled/{sha256}.pdf` | 内联读取成功生成的 PDF |

`backend/latex_export.py` 按编排顺序为每个源页生成独立源码：还原页由结构生成，片段和封面封底使用单源页模板，完整自定义文档保持原源码。例“片段、完整文档、片段、片段”生成四份 `.tex`；完整文档仍可输出多张。PDF 逐源页用 XeLaTeX 编译，再由 PyMuPDF 按同一顺序合并。单份源码下载 `.tex`，多份下载含 `0001.tex` 等文件及 `README.txt` 编排映射的 ZIP。端点名保留 `export.tex`；ZIP 响应使用 `Content-Type: application/zip` 及 `.zip` 的 Content-Disposition，前端按类型以 Blob 下载，并使用安全处理后的书名加真实扩展。

每源页编译缓存存于 `latex-units`，整书合并缓存存于 `latex-cache`；缓存同时持久保存 PDF 指纹、诊断、质量、实际纸型和页映射。键包含有效源码及布局、修订、当前来源指纹及变换、输出纸型、字体、装订、生成器/测量/诊断版本和编译器/字体身份。重排更新合并结果，未变化单页可复用；来源变化不把旧布局标为当前通过。已有 PDF 文件本身不能证明当前修订通过。

编译返回 `pdf_url`（失败时为 `null`）、兼容 `warnings`、结构化 `diagnostics`、`page_map`、`quality_status` 及版本。编译失败为 `compile_failed`；否则存在错误或警告为 `needs_review`，无上述问题但检测覆盖未完成或布局未验证为 `unverified`，其余为 `passed`。`passed` 只表示当前诊断覆盖通过，不证明 OCR 内容或视觉还原完整。自然盒和实际 PDF 字形范围检查补足日志的盲点：没有 Overfull 仍可能越界。待检查的诊断草稿可查看下载，但不能称为已通过；编译失败不以旧 PDF 冒充新结果。

`PUT /api/books/{id}/pages/{number}/layout` 保存校准并生成源码；`POST .../compile-layout-pdf` 只预览校准草稿。两者使用 `LayoutCalibrationUpdate` 及必填预期内容/布局修订，冲突返回 409。画布与字体参数省略沿用当前值，显式 `null` 恢复未知；画布宽高必须成对提交或成对清空，字族及字号共同确认后才可记录人工依据。自由源码保存的预期修订可省略以兼容旧 `{text}` 请求，前端提交双修订。`GET /api/books/{id}/compiled/{digest}/pages/{output_page}.png` 按需生成输出页图，用于同页对照；完整 PDF 入口仍保留。结构化诊断含来源、编排位置、输出范围、行/块、坐标、依据、建议及检测覆盖。

## 旧数据迁移与实现状态

旧版 Markdown 只作为启动迁移输入。`backend/storage.py` 在写入旧数据库前通过 SQLite backup 保存同一数据目录下的 `app-before-latex.db`；随后在事务内一次性转换正文，设置 `Book.content_format: latex`，原文留在内部 `pages.legacy_markdown` 供恢复，不对 API 或 JSON 公开。迁移不调用模型，不重新识别，保留人工校对、处理状态、用量、尝试次数及页序。备份已存在时不会覆盖；新建的 LaTeX 数据库不需要旧正文转换。
