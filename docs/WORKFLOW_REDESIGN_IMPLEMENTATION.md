## 1. 全部代理的执行边界

主代理与所有子代理均不得执行测试或运行验证，包括单元/集成/端到端测试、构建、类型检查、lint、试编译、启动应用/服务、执行实现脚本、接口探测、模型试跑、数据库迁移试跑、性能评测和浏览器验收。

不新增测试、基准或验收工具，不维护盲测集，不做人工标注、SHA256/文件指纹、全文件校验、反复 diff --check、截图取证或专门为证明结果建立的证据目录。禁止借“快速检查”“导入确认”“能力预检”等名称绕过禁测。

允许读取所需代码、搜索引用、编辑分配文件和阅读实际差异。静态审查应有具体目的：找接口冲突、遗漏需求、数据覆盖风险、无界循环和多余抽象；不反复执行不影响实现判断的检查。

所有编码子代理不得 computer use，不使用浏览器或桌面，不派发下级代理。主代理本轮也不进行 UI 验收。

## 2. 职责与简洁性

- 编码统一由 gpt-6.1-sol / xhigh 子代理完成，包括业务、迁移、接口接线、样式和必要冲突修复。
- 主代理只定义要求、接口和文件所有权，审查实际代码，决定接受或退回，维护计划和交付说明；不参与基础编码。
- 退回时必须指明文件/函数、触发条件、缺陷、具体修改要求和再次接受条件，交对应子代理修订。
- 不过度设计、不进行防御性编程；仅实现明确要求的输入边界、修订保护、事务与调用上限，不重复逐层校验、不吞异常、不增加假设性兼容分支。
- 采用直接函数和已有工具，不增加通用 DAG、插件/agent 框架、事件溯源、微服务或双份内容权威。
- 产品实际工作所需的自动内容复核、编译和输入约束属于实现功能，不得删掉；代理只编码，不运行这些功能。

## 4. 内容与状态契约

### 4.1 单一内容权威

演进现有 SourceFidelityLayout，沿用 regions、lines、equation_groups 和源变换，补充源区域图像资产及自动处置说明。LaTeX 是该结构的生成物，不新增同义的三套持久化中间格式。

完整自由 LaTeX 保留旧 custom_latex 权威；旧人工稿默认受到保护。启动任务时已获明确替换授权的范围可以自动采用新结果并归档旧稿，不能在后台猜测覆盖权限。

### 4.2 最低数据要求

| 对象 | 字段与用途 |
| --- | --- |
| SourceIdentity | book_id、永久 page_id、source_file_id、source_page、source_version、图像尺寸和坐标变换 |
| Document | schema_version、区域、原行、公式组、样式、画布、源区域资源与依据 |
| Revision | revision_id、parent_revision_id、source_version、content/layout revision、origin、run_id、内容和生成器版本 |
| Run | run_id、冻结页序及其 revision、设置/策略快照、状态、请求上限与计数 |
| PageTask | run_id、page_id、阶段、执行状态、基准修订、候选修订、次数及错误 |
| Assessment | revision_id、内容/布局/覆盖结论、规则版本和必要问题信息 |
| Issue | 类别、严重性、区域、简短原因、自动处置结果；不是人工待办 |
| Attempt | run/page/stage、attempt_id、状态、已知 usage 和供应商 request_id |

不增加 source_hash、manifest_hash、request_hash 或文件摘要字段。版本由程序维护；源文件替换产生新源版本，页序变化递增编排修订。现有功能确实依赖的内部缓存机制可保留，不以本次任务名义扩展或专门运行哈希验证。

大图片/PDF仍放本地文件。只增加必要表/字段，优先复用现有归档及用量记录。

### 4.3 执行与质量

stage 固定为 prepare、recognize、layout、render、verify、repair、finalize；执行状态为 queued、running、succeeded、failed、interrupted。运行级保留暂停/恢复状态。

页面结果为 auto_passed、completed_with_issues、failed。content/layout/coverage分别记录 passed、uncertain、unverified、failed，不能将执行结束映射成质量通过。

没有 awaiting_human、manual_review_required 或 human_confirmed 等新流程状态。旧编辑记录作为内容来源保留，不作为自动流水线依赖。

所有页面形成终态后，任务结束并汇总成功、带问题及失败数量。单页内容不确定不暂停全书。配置或原文件错误可以结束任务为失败，不能假装自动完成。

### 4.4 修订、并发与缓存

- 后台候选绑定基准修订，提交时使用已有的比较并交换语义；用户在运行中修改页面后，旧候选不得覆盖。
- 自动采用与移动当前指针在同一事务完成。候选失败保留旧结果。
- 内容变化失效相关内容和布局结论；纸型变化只失效布局输出；页序变化只重组整书与相关邻页检查。
- 缓存使用源资产 ID/版本、页面修订、输出设置版本和生成器版本，不扫描源文件生成新指纹。
- 请求前原子预留调用名额，内部重试走同一计数入口；已发送结果未知仍计一次。不得并发超限。
- 任务快照不包含密钥。只存产品恢复和错误解释所需记录，不做全请求取证平台。

## 5. 模型与接口

### 5.1 模型职责

保留 Responses/Gemini 两个显式适配器，提供 recognize_page、review_page、propose_repair。共用内部类型，协议参数分别序列化，不按模型名猜能力，不自动换供应商。

识别输出观察；审查输出区域覆盖、差异与提案；修复只操作指定区域，包含旧值与基准修订。提案允许替换行、插入有来源依据的遗漏区域、更新几何/公式组以及删除有证据的重复块；不接受任意代码/任意路径修改。

首次正常页面请求就是实际工作，不额外发“测试连接”“Schema能力预检”或原创测试图片请求。产品实际使用中遇图片/Schema不支持时集中报告并停止无效请求，其余已有结果保留。

### 5.2 新接口落点

| 接口 | 内容 |
| --- | --- |
| POST /api/books/{book_id}/runs | 页面范围、expected_arrangement_revision、策略、request_limit、client_request_id；冻结本轮范围 |
| GET /api/books/{book_id}/runs/{run_id} | 阶段、终态计数、额度、已知用量及错误摘要 |
| POST /api/books/{book_id}/runs/{run_id}/pause | 停止新阶段调度 |
| POST /api/books/{book_id}/runs/{run_id}/resume | 复用已完成阶段，保持原任务设置 |
| GET /api/books/{book_id}/results | 分页读取页面结果和自动处置说明 |
| GET /api/books/{book_id}/issues | 只读问题摘要及原图/输出定位，不返回人工待办 |
| POST /api/books/{book_id}/export-manifests | 固定页序和所选修订，返回 PDF/源码资源包/JSON 的同一份输出范围 |

不为新流程开发人工 decision、逐项 approve 或校对队列接口。既有自由编辑和保存接口维持兼容即可。

没有要求用户介入的隐式恢复：不可确定结果的请求按既定产品策略标记并保留源内容，不在重启时无限重发。用户主动暂停/恢复或发起新任务属于任务控制，不是逐页识别介入。
