## 1. 修复目标与边界

本轮主要目标是：在保留可编辑文字和数学公式的前提下，使输出页面在内容完整性、原始断行、版心位置、公式对齐、字体层级和分页上接近原书，并让无法可靠还原的部分可以被发现、定位和人工修正。

“内容正确”“编译成功”“版式还原”是三个独立结果。编译器成功退出，只能证明生成了 PDF，不能证明内容完整或页面美观。

### 1.1 完成后的用户可见结果

1. 长行、公式和页脚不再无提示地伸出纸张或被裁切。
2. 原书的一行、一个段落和一组推导公式有明确区别，不因模板默认行为被合并或拆散。
3. 采用原书还原输出时，一个源页对应一张输出页；无法满足时明确标记问题，不把异常续页当作还原成功。
4. 原书的版心、正文密度、缩进、公式锚点和留白关系得到保留，而不是统一套用一组猜测的尺寸。
5. 原图和输出能够在应用内同页对照，问题可定位到稳定的源页及相关区域。
6. 旧项目和人工编辑的 LaTeX 继续可用，不因升级丢失内容、编辑权或历史结果。

### 1.2 范围分级

| 范围 | 本轮要求 |
| --- | --- |
| 普通正文、标题、习题、行内公式、连续推导公式 | 核心修复，必须完成 |
| 页眉、页脚、原页码、分页映射 | 核心修复，必须完成 |
| 原图对照、质量诊断、草稿与保存状态 | 核心修复，必须完成 |
| 简单表格、脚注、双栏页 | 必须覆盖基础布局；无法可靠重建的复杂情况明确提示 |
| 封面、封底、复杂图表和装饰图形 | 明确现有信息损失与后续方案；不能宣称本轮已完整复刻 |
| 纯阅读重排、电子书阅读器、EPUB、物理双面拼版 | 不作为本轮新增交付 |

本计划保留现有模板重排及完整 LaTeX 文档能力。新增原书还原策略不应变成对所有用户源码的强制改写。

## 3. 总体修复策略

### 3.1 明确三种渲染来源

| 策略 | 排版依据 | 适用数据 | 约束 |
| --- | --- | --- | --- |
| 原书还原 `source_fidelity` | 校验过的原页几何信息、行、公式组和样式 | 新结构化结果或人工校准后的旧页 | 保留原行、相对位置和一源页一输出页 |
| 现有模板 `legacy_template` | 现有 `Book.layout` 与 LaTeX 片段 | 尚未补齐版式的旧页 | 保持兼容；提供裁切和分页诊断，不标为已还原 |
| 自定义源码 `custom_latex` | 用户维护的片段或完整文档 | 人工自由编辑页面 | 保留源码；诊断覆盖不完整时明确显示“未验证” |

这些是拟新增的内部策略名，不是已经存在的 API。界面使用“原书还原”“现有模板”“自定义源码”等用户能理解的名称。

旧项目升级后默认保持现有策略；不能仅升级程序就更换字体、重编正文或自动重新识别。新建项目默认使用原书还原策略，但单页缺少必要信息时应显示待校准状态，不能静默套模板冒充还原。

### 3.2 从内容识别到几何排版

目标数据流：

```text
原始 PDF / 图片
  → 建立源页坐标与旋转、裁切映射
  → 单次页面识别：文字、原行、公式组、可辨样式与区域关系
  → 本地结构校验、几何校准与必要人工修正
  → 按页生成 LaTeX，测量实际内容尺寸
  → 编译及页面映射
  → 编译诊断 + 尺寸诊断 + PDF / 图像检查
  → 原图对照预览、保存与导出
```

继续使用正常情况下每页一次模型识别请求；不把自动二次识别、自动换模型或自动扣费重试作为排版修复前提。本地测量、编译和人工校准不需要调用模型。

### 3.3 原则性要求

- 不通过删字、隐藏内容、移到纸外或强制裁切来满足一页限制。
- 不将一个段落整体塞进不可拆的行盒。
- 不为凑纸型而擅自改写原文、合并原行或拆分公式。
- 不逐行使用不同水平缩放比例压字；不以异常字距制造“看似齐边”。
- 版面信息不足时记录未知与依据，不把模型猜测值当作测量值。
- 对已有人工源码不做正则全局“修复”；复杂 LaTeX 无法通过简单字符串替换安全还原结构。
- 字体、字重、倾斜、字号、位置分别处理，不能将“例题”“定义”等语义直接映射为加粗。

## 4. 数据契约与内容权威来源

这一节描述拟新增的契约。必须先实现版本化兼容，再切换提示词和生成器，避免模型返回新字段后被当前 `extra="forbid"` 校验拒绝。

### 4.1 页面布局记录

建议新增可空的 `layout_source_json` 和 `layout_schema_version`，保留现有 `text`、书目、页眉页脚和原始识别结果。最终字段命名在阶段 B 固定，但必须包含以下语义：

| 数据 | 必须表达的内容 |
| --- | --- |
| 来源身份 | `book_id`、永久 `Page.number`、`source_id`、`source_page`、来源图像指纹 |
| 页面几何 | 图像像素宽高；源 PDF 可用的页面框、旋转及物理尺寸；可见书页区域 |
| 坐标变换 | 原图到校正图的裁切、旋转或纠偏变换；输出到源图的可逆定位关系 |
| 页面区域 | 正文版心、页眉、页脚、栏、图表和脚注区域；阅读顺序单独记录 |
| 原行 | 稳定 `line_id`、段落或块 ID、阅读顺序、文本或公式内容、包围框及可用基线 |
| 公式组 | 稳定 `group_id`、原行顺序、公式行、编号归属、可确认的对齐锚点 |
| 样式 | 字族类别、字重、倾斜、相对字号与范围；未知属性可空 |
| 参数依据 | 来自文件元数据、本地测量、模型估计还是人工校准；需要复核的原因 |
| 修订关系 | 内容修订号、布局修订号、生成器版本，以及布局是否与当前正文一致 |

不能要求模型重复生成 `source_id`、物理 PDF 尺寸、图像指纹等程序已经掌握的事实；这些数据由导入和存储层补入。模型负责观察内容与关系，本地代码负责校验和转换。

### 4.2 坐标规则

1. 识别布局使用归一化坐标 `[x0, y0, x1, y1]`，原点为提供给识别的规范图像左上角，x 向右、y 向下，值域为 0—1。
2. 明确规范图像采用何种旋转和裁切；保存到原始源页的映射，不能前后端分别猜测。
3. 有尺寸的区域必须满足 `x0 < x1`、`y0 < y1`，拒绝非有限数和越界值。未知区域用空值，不用全页框假装精确识别。
4. PDF 的 pt、模板现用的 bp、图像像素与归一化坐标分别命名。实现中应统一内部单位并集中换算；不能把 TeX pt 与 bp 混用而不记录。
5. PNG/JPEG 缺少可信 DPI 时，仅可确定长宽比和相对位置；物理尺寸由项目配置或人工指定，不凭像素数声称原书是多少毫米。
6. 扫描偏斜、装订阴影和手写批注不能直接当作版心边界。原始文件不覆盖，纠偏图仅作为派生缓存。

### 4.3 内容与源码避免双重权威

- 原书还原页：结构化行及公式内容是生成依据，`text` 可保留为兼容展示的生成源码，并记录生成所依据的修订号。
- 用户自由编辑生成源码并保存后：显式切为自定义源码，或标记布局与源码已脱离；不继续根据旧布局覆盖这份人工源码。
- 如提供结构化内容编辑，保存后重新生成对应源码，并同步修订号。不得独立修改两份内容而不检查一致性。
- 完整文档维持自身导言区、宏包、字体、纸型和页眉页脚；不对其再次叠加项目模板。
- 原始模型响应、人工修订和当前有效结果应有可恢复的版本边界。无需引入通用版本管理系统，但必须能够恢复升级或修复前的有效正文。
- 来源文件、正文、布局或裁切变更后，旧诊断和 PDF 缓存必须失效；旧结果可以保留供回看，但不能标为当前结果。

### 4.4 响应 Schema 与协议兼容

当前模型响应只有六个顶层字段，新布局契约应定义独立版本。客户端按本次请求选定的版本校验，不依赖模型自行猜版本，不对不合法响应静默删字段。

OpenAI Responses、Gemini 原生接口、Pydantic 校验、存储和 JSON 导出须同步适配。对未知字段、缺失字段、非法范围、重复行 ID、循环引用及超长内容进行确定性校验；不能因布局字段错误破坏已保存正文。旧响应和旧 JSON 仍可读取，但应标识缺少布局依据。

## 5. 识别与结构提取要求

### 5.1 原行、段落及文字

1. 输出明确的原行列表，不再让模型通过任意 LaTeX 分组和换行符隐式表示所有版式。
2. 每一视觉行有独立 ID；段落关系另存。源图换行、段落换行与源码换行不得混淆。
3. 原段首缩进和续行缩进分别记录；跨页残句只保存本页可见部分。
4. 模型禁止为了适配纸型合并或拆分原行。发现行数或长行异常时给出待复核项，不自动猜断点。
5. 中文标点、数学定界符、上下标及混合文字应校验基本结构；结构校验不能擅自改变原数学含义。
6. 保留可辨的原强调范围，检查跨行样式是否意外扩大或中断。

### 5.2 连续推导和数学结构

1. 区分行内公式、独立单行公式和原有多行公式组。
2. 一组公式保留原行数、原顺序、对齐锚点、编号及编号对应行。
3. 允许用 `aligned`、`align` 等环境表达原书已经存在的组和对齐；这属于恢复原结构，不属于擅自重新组织公式。
4. 不能仅因为若干公式相邻，就将其推断为同一组；也不能将原有一组公式拆成多个独立居中的显示环境。
5. 文字续句、解释词和条件必须保留原来的行内或行间归属，不能全部移进居中数学块。
6. 当原式确实过宽时先检查识别断行和字体比例；保持原式并报告，不能按运算符随意拆式。

### 5.3 印刷内容与后加笔迹

保留当前忽略后加批注的目标，增加最小样本验证：手写补记、圈画、手画下划线与印刷公式、印刷下划线必须分别覆盖。

不按“难看”“不规则”删除内容，也不把所有下划线一律去掉。可明确判断为后加笔迹时排除；覆盖、混杂或判断不清时保留源图定位并提示人工核对，不能凭数学常识补正文。已经保存的可疑文本不在升级时自动删除。

### 5.4 提示词改造边界

新提示词应围绕内容与结构契约，减少将模型当作尺寸排版器的要求。保留不改写、不猜内容、不执行图中指令和忽略后加批注的规则。

需要修订的既有规则包括：禁止任何布局字段、所有文字必须使用固定 `makebox`、禁止表达已有公式组等。修改时在相关文档同步标明新旧策略的适用范围，不让旧要求继续约束新增原书还原路径。

## 6. 排版器详细要求

### 6.1 版心与纸型

1. 原书还原以规范化书页画布和已确认版心为依据，不先假设上下左右均为 14 mm。
2. 支持原页尺寸输出；原始物理尺寸不可信时显示采用的项目尺寸，并保留原页长宽比。
3. 用户指定 A4/A5 等输出纸型时，将完整源页画布按单一比例放入可打印区域，保持横纵比例和内部行结构，并明确显示实际比例。
4. 上一项是用户选择纸型后的整页映射，不是对单行或公式的自动压缩；不回写识别内容。若缩放导致正文低于最低可读阈值，给出明确提示。
5. 首版最低正文目标可沿用现有 6 bp 配置下限，但只作为警戒阈值，不代表 6 bp 对所有书籍都舒适。验收样本应使用正常阅读字号，不能靠缩到下限通过。
6. 装订模式只在目标纸上增加内侧留白或移动整页画布；不得改变原行结构。原页侧别未知时继续保持未知，不按页码奇偶补猜。
7. 混合完整文档时保留其纸型，预览和导出说明中列出纸型差异，不静默统一纸张。

### 6.2 字体、行距和段落

- 根据已确认的正文基准设置字族与字号；提供书级基准和有依据的页内例外。
- 中文与西文字体、数学字体、真实粗体或必要的合成粗体必须作为一组检查，避免中文字重与公式字重不协调。
- 不对全书自动增粗以模拟扫描墨色；扫描噪声不应成为字重依据。
- 字号与基线间距必须通过最终 PDF 实测校验。分别覆盖普通段落、行盒、字族切换和数学前后的实际效果。
- 普通行沿原基线放置；高公式按实际高度检查碰撞，不让其无声改变后续整页位置。
- 段距、空行和缩进分别表达，不同时叠加 `\\`、空段、环境间距造成额外空白。
- 原书两端对齐的普通行可以在明确宽度及有限字距内实现；末行及有意短行不强制撑满。超出合理字距时报告并回查字体、断行和版心。

### 6.3 公式组、表格与图文关系

- 原有公式组整体保留对齐结构，组内间距与组外间距分别控制；不重复叠加多个显示环境的上下间距。
- 数学符号、字母、括号、上下标及编号需要检查基线、裁切和相互遮挡。
- 简单表格保留列关系、原行、合并单元格和边界；不能因列数正确就认定版式正确。
- 脚注与图注保持所属区域和标号；避免落入另一栏、页脚或下一源页。
- 对不能可靠重建的复杂图形，本轮至少标出未还原区域。后续可以使用原图裁片，但必须作为显式资源，保存来源和坐标，并让导出文件包含所需资源。
- 不使用生成图像替代书中真实图表，也不凭图形外观编造曲线或数据。

### 6.4 页眉页脚和页码

1. 三种页码分别保存和展示：源文件页序、原书印刷页码、输出 PDF 页序。
2. 原书页码按原文显示，不根据输出页序重新编号。
3. 还原策略中页眉页脚按源区域放置，仅保留左/中/右标签不足时应使用区域坐标。
4. 页眉页脚与正文应参与碰撞检查；完整文档不重复叠加结构化页眉页脚。
5. 自定义源码或旧模板确实输出多张时，映射必须保留一对多关系；界面显示实际输出范围，不能错指到后续源页。

### 6.5 分页和测量

新增还原路径应以单个源页为编译及诊断单元，再按编排合并。可缓存单页结果，避免一次修改重编整书；整书合并不能改变源页顺序。

在生成代码中加入可测量的行/块宏：按实际字体和数学内容测量自然宽度、总高度及放置区域，与目标区域比较，记录块 ID 和页 ID。测量诊断写入旁路结果，不进入最终可见正文。

禁止用固定高度盒子或裁剪命令遮住溢出内容来制造一页结果。分页异常时允许生成可查看的诊断草稿，但质量状态不能为通过；用户仍可保留或下载草稿，不新增与任务无关的权限确认流程。

旧模板及任意完整文档可能无法插入完整测量信息，应实施可行的外部检查并标为相应覆盖级别，不能声称已经安全解析所有 TeX 宏。

## 7. 诊断与质量状态

### 7.1 三层诊断

| 层级 | 检查内容 | 局限及处理 |
| --- | --- | --- |
| 编译诊断 | 语法、缺包、缺字、字体替换、Overfull/Underfull、页眉高度 | 无警告不等于内容没有越界 |
| 生成器测量 | 行与块自然宽高、落点、版心边界、预计页数、相邻块碰撞 | 原书还原路径必须具备；任意用户宏不能保证覆盖 |
| 输出检查 | 实际页数、页面映射、PDF 文字/图形范围、渲染后裁切及可见性 | 已被裁掉的字可能无法从 PDF 文本重新找到；不能只检查提取后的文字边界 |

对固定宽 `makebox` 的关键要求：增加一个内容越界但日志无 `Overfull` 的夹具，必须由测量层或独立检测发现。对于暂时无法准确测量的旧源码，至少标记检查覆盖不足，不能返回无问题即通过。

### 7.2 结构化诊断

建议在现有 `pdf_url`、`warnings` 之外新增结构化 `diagnostics`、`page_map`、`quality_status` 和内容修订标识。旧 `warnings` 在过渡期保留。

每条诊断至少包含：

- 稳定错误码和严重程度。
- 永久页面 ID、源文件页号、编排位置及已知的输出页范围。
- 可选行/块 ID、源区域、输出区域、超出量及单位。
- 中文说明、检测依据和可执行的修正建议。
- 所针对的内容/布局修订号，以及是否覆盖完整。

首批错误码至少覆盖：`CONTENT_OUTSIDE_PAGE`、`CONTENT_OUTSIDE_FRAME`、`UNEXPECTED_PAGE_COUNT`、`BLOCK_OVERLAP`、`MISSING_GLYPH`、`FONT_SUBSTITUTION`、`LAYOUT_SOURCE_MISMATCH`、`LAYOUT_UNVERIFIED`、`SOURCE_CONTENT_REVIEW`。

区分数学内部正常符号叠放和不同内容块碰撞；不能简单把任何包围框交叉都当成错误。

### 7.3 状态含义

| 状态 | 含义 |
| --- | --- |
| `passed` | 本修订必要检查已执行，没有发现阻断还原的问题；不代表 OCR 自动达到百分之百正确 |
| `needs_review` | 已生成 PDF，但存在裁切、分页、内容或明显位置问题 |
| `unverified` | 可预览，但缺少布局依据、检测覆盖或必要工具，尚不能判断 |
| `compile_failed` | 编译未生成可用的当前结果；不能显示旧结果为最新 |

`passed` 不得用于存在已知缺字、纸外内容或原书还原分页异常的结果。未执行检查与检查无问题必须区分。前端删除“超宽超高也无须重排”等将生成成功等同于可用的笼统提示，改为具体问题和实际影响。

## 8. 前端交互要求

### 8.1 同页对照

1. 校对区提供“原图 / 输出”并排对照；源码编辑可切换显示或展开，避免固定三列把页面压得过窄。
2. 两侧按同一源页定位，提供适合整页、适合宽度和放大查看。同步位置应基于页内归一化坐标，不以两侧滚动条百分比直接代替。
3. 窄窗口采用原图/输出切换并保留查看位置；不强制并排。
4. 点击诊断跳到对应源页和区域。缺少区域时至少定位到源页；输出多张时展示实际范围。
5. 可提供透明叠加查看已配准的原图和输出，但要能关闭；不把扫描噪声差异当作文字错误。

浏览器原生 PDF `iframe` 难以提供稳定的页内同步控制。建议校对视图使用受控分页渲染层，例如后端按需生成预览图并附页面尺寸和诊断坐标；原 PDF 继续用于完整预览和下载。若选用前端 PDF 渲染库，实施时再核对其依赖和维护情况，不在计划阶段承诺尚未评估的库。

### 8.2 设置及编辑状态

- 原书还原设置优先显示输出纸型、缩放比例及需要校准的参数；不能让项目全局行距无提示地覆盖已确认的原页基线。
- 已有模板继续显示当前字体、字号、行距与边距的适用范围。
- 自定义源码显示“版式由源码控制”；不展示实际无效的设置为已应用。
- 原图对照、缩放和定位不保存草稿、不调用模型、不覆盖识别结果。
- 单页预览明确使用当前内容草稿还是已保存版本；整书预览只使用已保存内容和布局。
- 任何内容或布局变化后，诊断与 PDF 一起失效；异步旧响应不得覆盖更新后的页面或另一本书。
- “重新识别”沿用现有用户操作入口。批量操作需显示页范围和人工修改情况，不因发现问题自动覆盖校对结果。

## 9. 缓存、迁移及回退

### 9.1 缓存标识

缓存键应包含有效源码或结构化内容、布局修订、源图指纹、裁切/纠偏映射、生成器及诊断版本、字体配置、输出纸型和装订策略。编译器或字体实际版本改变时必须使受影响的缓存失效或重新验证。

不能只缓存 PDF 而丢失其页映射和质量状态。源文件替换或页面重新编排时，应区分单页内容缓存和整书合并缓存；前者可复用，后者必须更新。

### 9.2 数据迁移

1. 在独立数据副本验证增量迁移和重复初始化，不能直接拿唯一用户库试迁移。
2. 仅添加版本化字段或关联记录；缺失布局以空值表示，禁止自动编造源坐标。
3. 旧内容、页侧、页眉页脚、书目、人工编辑、状态、用量及尝试次数保持不变。
4. 旧页补布局应通过人工校准或用户触发的识别产生，不在后台自动调用模型。
5. 存储正文和其布局版本时使用同一事务。任务失败、暂停或服务中断不得留下半套新数据。
6. 保留人工保存优先于排队识别的现有并发规则；新布局也必须使用相同修订检查，避免旧任务覆盖新校对。
7. JSON 导出带布局版本与来源修订信息；自由源码及旧页可继续导出。新增资源时，LaTeX 包必须携带相对资源和必要编排映射，不能引用本机绝对路径。

### 9.3 回退

按新增渲染策略回退到旧模板或自定义源码，保留新版布局记录供后续修正。数据库回滚只使用升级前备份，不能在已有新编辑后直接覆盖整库；实施说明必须记录备份时点、恢复步骤及其会丢弃的后续修改。

本轮不修改密钥管理、上游接口地址或模型选择行为。

## 10. 分阶段实施计划

按依赖顺序实施，不以“提示词已修改”或“PDF 能生成”提前宣布修复完成。下表的工作项是后续实施任务，本次文档编写不执行这些变更。

### 阶段 A：复现基线与紧急诊断（P0）

**任务**

- A1：固定上述 11 页的内容修订、现有输出及页映射；保存本地诊断报告，不提交书籍。
- A2：制作长行盒越界、公式过宽、源页意外续页三个最小合成夹具。
- A3：建立实际 PDF 页数、源页范围及质量状态；优先让当前裁切和分页问题可见。
- A4：定位实际行距与配置值不一致的最小复现，记录结论和测试，不先盲改字号。
- A5：调整预览问题提示，使“生成成功”和“排版待检查”分开。

**涉及模块**：`backend/latex_diagnostics.py`、`backend/latex_export.py`、`backend/main.py`、`frontend/src/PdfPreview.tsx`、`frontend/src/types.ts`。

**交付**：可重复运行的夹具、诊断结果、当前问题定位清单。

**通过条件**：R01—R03 均能稳定复现并产生可定位问题；未支持的检测明确未验证。阶段 A 通过仅代表发现机制改善，不代表裁切和分页已修复。

### 阶段 B：版本化布局契约与存储（依赖 A）

**任务**

- B1：确定页面区域、原行、公式组、样式和修订关系的最小 Schema。
- B2：明确原图、规范图和输出页之间的坐标及单位转换。
- B3：实现新旧响应和 JSON 的版本化解析，同步两类模型协议。
- B4：增加布局存储、源码脱离标记、迁移和缓存版本。
- B5：通过人工标注的小样本贯通保存、读取、编排与导出，不依赖实时模型才能验证接口。

**涉及模块**：`backend/models.py`、`backend/storage.py`、`backend/importers.py`、`backend/responses_client.py`、`backend/gemini_client.py`、`frontend/src/types.ts`。

**交付**：Schema、迁移说明、样例 JSON、坐标换算与修订规则。

**通过条件**：旧库可读写；未知布局不被伪造；内容与布局一致性可追踪；非法新响应不破坏旧结果。

### 阶段 C：原书还原排版器（依赖 B）

本阶段使用阶段 B 的人工校准参考数据验证排版器，修正后的样本存于独立测试位置，不覆盖用户原始识别结果。阶段 D 再验证模型能否直接产生同等结构，避免将识别精度与排版器正确性混为一项。

**任务**

- C1：使用已校准原页画布、版心、字号及基线生成页面。
- C2：实现原行和公式组的测量、定位、编号及碰撞检查。
- C3：消除 R01 的长行合并与裁切，恢复 R04 的公式组对齐。
- C4：实现单源页输出及稳定页映射；修复 R02 的异常续页，保留无法满足条件时的诊断。
- C5：统一字体/字号/基线实际效果，核验页眉页脚落点。
- C6：验证目标纸型和装订留白下的整页映射；完整文档继续采用自身源码。

**涉及模块**：`backend/latex_export.py`、`backend/latex_diagnostics.py`、`backend/main.py`；可增加职责明确的布局模块，避免把所有几何逻辑塞进导出函数。

**交付**：新生成器、单页诊断及合并映射、修复前后对照结果。

**通过条件**：本地 11 页核心样本按还原策略输出 11 张；全部可见内容完整；原书第 13 页不再意外续页；公式行数与对齐经人工对照确认。仅增加诊断不能算阶段 C 完成。

### 阶段 D：识别契约与校准闭环（依赖 B、C）

**任务**

- D1：按新结构更新提示词，移除固定行盒和公式组表达的冲突要求。
- D2：实现布局范围、行 ID、内容长度和结构一致性校验。
- D3：对原行合并、手写混入、强调范围错误建立针对性样本。
- D4：提供缺失几何信息的人工校准和局部修正，不要求整页重新录入。
- D5：用固定响应夹具验证两个协议；真实模型抽样作为另一次明确的识别操作，不自动覆盖用户样本。

**涉及模块**：`backend/prompts.py`、`backend/models.py`、`backend/pipeline.py`、模型客户端、`frontend/src/PageEditor.tsx`。

**交付**：新识别契约、校准流程、样本对照及未解决问题记录。

**通过条件**：新结果可直接进入还原排版器；低把握区域可定位；后加批注案例通过人工核对；没有新增每页强制多次模型调用。

### 阶段 E：原图对照与问题处理（依赖 A、B、C）

**任务**

- E1：实现应用内原图/输出同页对照及窄窗口切换。
- E2：实现诊断到页和区域的跳转、放大及页内位置保持。
- E3：显示策略、修订状态、实际纸型和质量结果。
- E4：验证草稿、保存、编排及异步响应失效规则。
- E5：保持完整 PDF 查看与下载入口。

**涉及模块**：`frontend/src/App.tsx`、`frontend/src/PdfPreview.tsx`、`frontend/src/PageEditor.tsx`、`frontend/src/LayoutSettingsForm.tsx`、`frontend/src/api.ts`、`frontend/src/styles.css`、后端按需预览接口。

**交付**：可实际操作的对照校对流程与必要状态回归测试。

**通过条件**：用户无需另开窗口即可发现并定位裁切、公式错位及分页问题；切页不串页，旧响应不覆盖新草稿。

### 阶段 F：整体验收、文档与发布（依赖 C、D、E）

**任务**

- F1：执行第 11 节的核心回归及视觉验收。
- F2：验证混合模板/还原/完整文档的编排和导出。
- F3：验证旧库迁移、人工校对保护、失败恢复及缓存失效。
- F4：更新使用说明、架构、LaTeX 说明、打印规则和验收记录。
- F5：记录工具与字体版本、实际通过项目、未覆盖项目和回退步骤。

**通过条件**：P0 全部修复，正文及数学核心 P1 完成；不以 P2 功能缺失阻止核心修复交付，但必须明确列出其限制，不宣称所有原书页面都已完整复刻。

## 11. 验收标准与测试矩阵

### 11.1 硬性标准

| ID | 标准 | 验证方式 |
| --- | --- | --- |
| AC01 | 核心样本无文字、符号、上下标、编号和页脚被裁切 | 源图逐行对照 + 生成器尺寸检查 + PDF 渲染检查 |
| AC02 | 原书还原的 11 个样本源页输出 11 张，顺序准确 | 实际 PDF 页数和稳定源页映射 |
| AC03 | 原行和公式组的行数、顺序、断点正确 | 人工标注基线与结构化结果对比 |
| AC04 | 连续推导对齐，无额外重复公式间距 | 公式锚点测量和视觉对照 |
| AC05 | 没有把后加手写补记、圈画转为正文 | 指定批注样本逐项核对 |
| AC06 | 越界但没有 Overfull 的夹具仍被发现 | 固定宽行盒专项测试 |
| AC07 | 未检测、检测失败和检测通过可区分 | API 及界面状态验证 |
| AC08 | 内容/布局修改使旧 PDF 和诊断失效 | 单页、整书、切页和异步响应回归 |
| AC09 | 人工源码、旧库与完整文档继续工作 | 迁移、编辑、混合导出测试 |
| AC10 | 原图和输出对照能定位同一源页 | 实际界面操作验证 |

### 11.2 版面精度的初始验收目标

以下是拟采用的工程目标，尚不是当前系统已达到的指标。阶段 A/B 在校正后的样本上核准标注方法后冻结；如需调整，记录依据，不能为了让失败样本通过而事后放宽。

- 版心四边相对人工标注的偏差：不超过规范源页相应宽/高的 1%。
- 普通文字行基线误差：中位数不超过正文 0.25 em，95% 不超过 0.5 em；人工标注不清晰的行单独列出。
- 同一公式组对应对齐锚点相对参考位置的误差：不超过正文 0.5 em。
- 普通正文行距的中位数相对已确认参考值偏差：不超过 5%；含大公式、上下标或特殊留白的行单独评估。
- 可读正文、公式和页码超出最终纸张可见范围：零容忍，不用上述位置容差允许裁字。
- 不允许无依据的内容块重叠；数学结构内部正常叠放不计入碰撞。

em 采用已确认的正文基准字号，所有比较先逆向消除目标纸型的统一缩放。扫描像素差、纸张底色、抗锯齿和噪点不作为逐像素一致性要求。不能用一个全页图像相似度分数代替内容完整性验收。

### 11.4 检查规模与结果记录

先运行与变更有关的后端测试、前端状态测试和构建，再进行必要的实际编译与视觉检查。现有部分测试包含历史 Markdown/HTML 假设，应更新相关断言或明确其历史身份，不能简单删除失败测试换取绿色结果。
