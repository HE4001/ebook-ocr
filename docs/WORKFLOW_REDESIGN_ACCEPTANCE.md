## 1. 完成的含义

本轮交付是：实现规定功能，主代理阅读实际代码并接受，完成相关文档。**所有代理均不测试、不运行验证**，不得为满足交付条件增加隐藏的试跑步骤。

“静态审查接受”仅说明从代码判断实现符合要求，不代表真实模型准确率、实际界面、迁移或 PDF 输出已经运行验证。最终必须明确写“未测试、未运行验证”。

产品使用时的自动审查和有限修复仍是必需代码功能；它们与开发代理的测试行为分开。

## 2. 静态完成条件 C1—C10

| ID | 必须实现的行为 | 主代理静态审查重点 |
| --- | --- | --- |
| C1 无人工识别介入 | 一次启动后自动推进所有页，无逐页校对/坐标填写/人工批准关卡 | 全部正常、修复、失败分支都不等待人工决定 |
| C2 自动处理闭环 | 准备、识别、布局、生成、内容审查、局部修复、终态和导出接通 | 入口、调用与数据提交完整，无未接线占位函数 |
| C3 有界资源 | 模型修复/复审、暂时错误重试、候选编译及运行总调用均有明确上限 | 每个循环出口、请求前原子计数及内部重试一致 |
| C4 状态真实 | 自动通过、带问题完成、失败区分；合法JSON/能编译不等于内容正确 | 内容、布局、覆盖与执行状态不混用 |
| C5 自动保留不确定内容 | 未能修复时保留最佳候选/源区域，必要源页保留；标明未可靠转录 | 不猜字、不漏页、不将图像保留冒充文字化成功 |
| C6 数据保护 | 源文件/旧人工稿/历史修订保留，后台旧候选不覆盖新编辑 | 事务、基准修订、采用指针与启动时范围授权 |
| C7 自动工作台 | 默认展示任务、进度、结果和问题说明，不要求人解决疑点 | 前端没有必须逐页确认才能推进/导出的状态 |
| C8 输出一致 | PDF、源码资源包、JSON来自同一页序和修订范围 | 资源引用、结果状态、页映射、兼容源码路径一致 |
| C9 实现简洁 | 复用现有技术栈，没有多余框架和验证体系 | 不新增哈希/指纹、测试集、评估脚本或重复内容权威 |
| C10 按规定交付 | 模块由指定子代理编码，主代理实际审查并处理退回意见，文档准确 | 模型/文件归属/审查结论与未运行声明齐全 |

每项完成状态使用 pending、implemented、static_accepted，不使用 verified。每项记录相关文件/函数和简短审查结论即可，不建立专门取证体系。

## 3. 取消的旧安排

以下内容不再是本轮工作或完成门槛：

- 20/40页开发集与留出集、11页重新运行、人工参考标注、盲测、重复运行。
- CER、公式准确率、召回/精确率、85%自动完成率及人工动作下降70%的实测目标。
- pytest、pnpm test/build、类型检查、lint、启动器测试、迁移试跑和故障注入。
- 真实模型质量试跑、独立能力探测、接口冒烟、实际PDF/PNG或浏览器验收。
- SHA256、源图/数据库哈希、编译器与字体指纹、全书一致性扫描。
- 截图、性能日志、调用取证、验收脚本、基准目录和测试通过报告。

不得把这些任务转交另一代理或换名称执行。已有测试和历史报告无需删除，但不运行、不扩充，不拿历史通过结果代替本轮事实。

## 4. 静态退回条件

以下代码不能接受：

1. 内容不确定时停止并等待人工校对，或把几何未知交给人填表。
2. 删除全部告警或只看模型自报 confidence 就标通过。
3. 无界重试、修复循环，或错误/复核调用不计入额度。
4. 无依据覆盖旧人工稿、旧候选覆盖运行中的新编辑。
5. 不确定文字直接编造，失败页悄悄省略，或源图保留显示为成功转录。
6. 普通页面省略识别而直接整页贴图，或产品关键路径只有空实现。
7. 新增不必要框架、重复校验、吞异常以及与交付无关的验证任务。

主代理给出具体文件/函数、问题、修改要求，交回所属子代理。修改后只阅读相关改动，不运行代码。
