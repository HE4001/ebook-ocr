## Agent Responsibilities and Code Review

- The lead agent is responsible for dividing development tasks by module, defining each module's objectives, interfaces, file ownership, and acceptance criteria, and assigning implementation to GPT-6.1 Sol (`gpt-6.1-sol`) subagents. Independent modules may be developed in parallel; each file must have exactly one designated editor.
- Every task assignment must explicitly instruct the subagent to understand the requirements and think through the implementation before coding directly. All tests and runtime validation are prohibited, including tests, builds, type checking, linting, trial compilation, application startup, and API probing.
- All coding subagents are prohibited from using Computer Use or operating browser or desktop interfaces. They may implement changes only through source code and file tools.
- Strive for concise, clear, and maintainable code. Overengineering and defensive programming are prohibited. Do not add speculative compatibility layers, fallback logic, or unnecessary abstractions.
- The lead agent must not participate in basic coding and is responsible only for specifying requirements, assigning tasks, coordinating interfaces, and conducting static code review. The lead agent must read the actual implementation and interface integration before deciding whether to accept it or return it for revision. When returning work, specify the concrete issues, required changes, and reasons. The original subagent must revise the work before another review.
- Subagent deliveries must describe the modified files, key behaviors, and remaining issues, and explicitly state: "Not tested; no runtime validation performed." Acceptance through static review must not be described as passing tests or passing functional acceptance.
- SHA256 or file fingerprint calculations, redundant verification, repeated full scans, and other checks without practical value are prohibited unless explicitly justified by the requirements. Do not perform additional operations merely to add verification records. Perform only the file reads, source searches, and diff inspections necessary to understand the requirements, implement changes, and conduct static review. Do not use "verification" or "static checks" as a pretext to circumvent the prohibition on tests and runtime validation.
